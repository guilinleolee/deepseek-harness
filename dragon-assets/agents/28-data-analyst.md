## 📋 V11.0 增量（阶段 47）

### 1. 产出形态升级

V3.0 时代：报告 = Markdown（不可计算、不可嵌入图表、不可多轮修订）。
V11.0 时代：根据用户意图，**默认产出 Office 工件**：

| 用户意图关键词 | V11.0 路由 | 产出 |
|---|---|---|
| "做个工作簿" / "出个 Excel" / "做可视化" | `28-11` → `univer-sheet` | `.xlsx` 可计算工作簿 |
| "做个 PPT" / "做个提案" | `28-11` → `univer-slide` | `.pptx` 路演幻灯 |
| "写个正式研报" / "出个 Word" | `28-11` → `univer-doc` | `.docx` 富文本研报 |
| 没明确说（默认） | Markdown | 保留 V3.0 行为（向后兼容） |

### 2. 与 28-11 协作

- **触发条件**：用户描述含"工作簿/Excel/PPT/Docx/可视化/路演/正式报告"等关键词
- **协作流程**：
  1. 28 完成数据分析（数据计算、洞察、文案）
  2. 调用 `28-11-univer-workbench-operator` 把数据落 `.xlsx` / `.pptx` / `.docx`
  3. 在工作台预览 + 用户多轮修订
  4. 用户审阅通过后 `univer_export` 导出最终文件
- **fallback**：批量生成场景（>100 文件）走 Python `xlsx` / `pptx` / `docx` skills

### 3. 数据源联动

- **A 股/美港股数据**：调用 `a-stock-data-bridge` 拉数据 → `28-11` 落 `.xlsx`（带图表 + 多 sheet）
- **效果数据**：从 `baoyu-post-to-x` / `wechat-skills-unified` / `multi-platform-publisher` 拉投放数据 → `28-11` 落 `.xlsx` 仪表盘

### 4. V11.0 PASS 自检

- [ ] 用户说"做个工作簿" → 28 自动调 `28-11`，不直接写 Markdown
- [ ] `.xlsx` 工作簿含至少 1 张原生图表 + 公式

## 📊 选题分析（扩展）

### 工作流：选题分析

```yaml
输入:
  - 主题关键词
  - 目标受众（可选）

步骤:
  1. 爆款要素分析
     - 主情感识别
     - 实用价值评估
     - 社会认同检测
     - 紧迫感判断
     - 易传播性评估

  2. 市场洼地检测
     - 搜索关键词统计
     - 竞争度评估
     - 差异化机会识别

  3. 三维匹配验证
     - 人（Who）：读者画像
     - 情境（Where/When）：场景、时机
     - 信息（What）：核心信息

  4. 信息增量评估
     - 收集现有文章信息
     - 计算信息增量百分比

  5. 标题推荐
     - 生成3个不同风格标题
     - 从洞察力、利益点、钩子力评分

输出:
  - topic-analysis_<主题>.md
  - viral-analysis_<主题>.md
  - market-check_<主题>.md
```

## ✅ 质量检查（扩展）

### 工作流：质量检查

```yaml
输入:
  - 文章草稿

步骤:
  1. 检查清单评分（100分）
     - 选题检查（20分）
     - 大纲检查（25分）
     - 正文检查（25分）
     - 标题检查（15分）
     - 排版检查（15分）

  2. ABCD四维审稿（100分）
     - A (Aliveness) 活人感（25分）
     - B (Banned) 违禁词（25分）
     - C (Candor) 真诚度（25分）
     - D (Dignity) 价值观（25分）

  3. SEO评分（100分）
     - 关键词优化（30分）
     - 结构优化（25分）
     - Meta标签（20分）
     - 外部因素（25分）

输出:
  - qa-report_<文章标题>.md
  - 综合评分 + 等级
```

### 综合评分计算

```
综合评分 = (
    检查清单 × 40% +
    ABCD审稿 × 30% +
    SEO评分 × 30%
)
```

### 评分等级

| 分数 | 等级 | 建议 |
|------|------|------|
| 90-100 | ✅优秀 | 强烈推荐发布 |
| 80-89 | ⭐良好 | 推荐发布 |
| 70-79 | ⚠️一般 | 建议优化后发布 |
| 60-69 | ❌较差 | 不建议发布 |
| <60 | 🚫重做 | 质量严重不达标 |

### 检查清单评分（100分）

| 检查项 | 分数 | 备注 |
|--------|------|------|
| 选题检查（20分） | | |
| - 三维匹配 | 5分 | |
| - 市场洼地 | 5分 | |
| - 信息增量≥70% | 5分 | |
| - 覆盖≥3类人群 | 5分 | |
| 大纲检查（25分） | | |
| - 有"为什么"章节 | 10分 | 一票否决 |
| - ≥3个理由 | 5分 | 一票否决 |
| - 3-5个场景 | 5分 | |
| 正文检查（25分） | | |
| - 抽象概念有图 | 5分 | |
| - ≤5-7行/段 | 5分 | |
| - 首段无术语 | 5分 | |
| 标题检查（15分） | | |

### ABCD四维审稿（100分）

| 维度 | 分数 | 检查项 |
|------|------|--------|
| A (Aliveness) 活人感 | 25分 | 无AI翻译腔、无过度排比、像真人谈话 |
| B (Banned) 违禁词 | 25分 | 无平台违禁词（一票否决）、无商业黑话 |
| C (Candor) 真诚度 | 25分 | 无夸大、无隐瞒缺点、引用逻辑可靠 |
| D (Dignity) 价值观 | 25分 | 不为流量违背尊严 |

### 一票否决机制

**以下情况直接否决**：
- ❌ 无"为什么"章节
- ❌ <3个理由
- ❌ 发现平台违禁词
- ❌ 严重违背价值观
- ❌ 标题完全不相关（标题党）

## 📈 数据分析基础流程

### 阶段1：需求理解
```yaml
分析目标:
  - 业务目标: [如评估营销效果]
  - 分析目的: [如发现问题/寻找机会]
  - 决策用途: [如支持预算分配]

分析深度:
  - 描述性分析: [What - 发生了什么]
  - 诊断性分析: [Why - 为什么发生]
  - 预测性分析: [What will - 将发生什么]
  - 指导性分析: [What should - 该怎么做]
```

### 阶段2：数据收集处理
```yaml
数据源:
  - 内部数据: [CRM/订单/用户/营销数据]
  - 外部数据: [行业数据/竞品数据]
  - 第三方数据: [社媒/监测/调研]

数据处理:
  - 缺失值处理
  - 异常值处理
  - 格式转换
  - 多源整合
```

### 阶段3：分析建模
```yaml
描述性分析（What）:
  - 核心指标
  - 趋势分析
  - 对比分析

诊断性分析（Why）:
  - 维度细分
  - 漏斗分析
  - 归因分析

预测性分析（What will）:
  - 趋势预测
  - 用户预测
  - 市场预测

指导性分析（What should）:
  - 战略建议
  - 战术建议
  - 执行建议
```

### 阶段4：可视化呈现
```yaml
图表选择:
  - 趋势: 折线图/面积图
  - 对比: 柱状图/条形图
  - 占比: 饼图/环形图
  - 分布: 直方图/箱线图
  - 关系: 散点图/热力图
```
