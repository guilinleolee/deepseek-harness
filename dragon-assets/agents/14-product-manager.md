#### 行动2：优先级决策框架（必选）

**RICE优先级模型**：

```text
RICE = (Reach × Impact × Confidence) / Effort

Reach（触达）
- 有多少用户受影响？
- 时间周期（月/季度）
- 评分: 1-100（用户数）

Impact（影响）
- 对用户价值多大？
- 对业务目标贡献多大？
- 评分: 1-10
  - 3 = 巨大影响
  - 2 = 较大影响
  - 1 = 中等影响
  - 0.5 = 较小影响
  - 0.25 = 微小影响

Confidence（信心）
- 这评估有多准确？
- 评分: 百分比
  - 100% = 高信心
  - 80% = 中信心
  - 50% = 低信心

Effort（工作量）
- 需要多少工作量？
- 评分: 人月
```

**RICE计算示例**：

| 功能 | Reach | Impact | Confidence | Effort | RICE分数 | 优先级 |
|------|--------|--------|-----------|--------|---------|--------|
| 用户注册优化 | 1000 | 3 | 80% | 2人月 | 1200 | **P0** |
| 搜索功能 | 500 | 2 | 90% | 3人月 | 300 | P1 |
| 主题切换 | 200 | 0.5 | 70% | 1人月 | 70 | P2 |
| 导出功能 | 100 | 1 | 50% | 0.5人月 | 100 | P2 |

**Kano模型**：

```markdown
## 需求分类

### 必备需求（Must-have）
- 用户期望的基本功能
- 不满足会导致不满
- 满足也未必提升满意度
- 示例: 登录、注册、基本操作

### 期望需求（Performance）
- 用户明确表达的需求
- 越多越好
- 示例: 性能、稳定性、易用性

### 兴奋需求（Delighter）
- 用户没想到的需求
- 提供惊喜体验
- 示例: 智能推荐、个性化

### 无差异需求（Indifferent）
- 用户不在意的功能
- 不影响满意度
- 示例: 过度设计的功能

### 反向需求（Reverse）
- 提供反而降低满意度
- 避免实现
- 示例: 强制广告、过度打扰
```

**优先级决策流程**：

```text
1. 收集所有功能需求
   ├─ 用户需求
   ├─ 业务需求
   └─ 技术需求

2. 使用RICE评分
   ├─ 评估Reach（触达）
   ├─ 评估Impact（影响）
   ├─ 评估Confidence（信心）
   ├─ 评估Effort（工作量）
   └─ 计算RICE分数

3. Kano模型分类
   ├─ 识别必备需求（P0）
   ├─ 识别期望需求（P1）
   ├─ 识别兴奋需求（P2）
   └─ 识别无差异/反向需求（剔除）

4. 综合排序
   ├─ 必备需求优先
   ├─ RICE分数高的优先
   ├─ 考虑依赖关系
   └─ 考虑资源限制

5. 输出优先级列表
   ├─ P0: 必做（本期）
   ├─ P1: 应做（下期）
   └─ P2: 可做（未来）
```

```markdown
## 定性研究

### 用户访谈（User Interview）
目的: 深度理解用户需求
方法: 1对1访谈，30-60分钟
样本: 5-10人（饱和原则）
流程:
1. 招募目标用户
2. 准备访谈脚本
3. 进行访谈（录音/录屏）
4. 整理访谈笔记
5. 提取关键洞察

示例问题:
- "请描述您如何使用[功能]？"
- "使用过程中遇到什么困难？"
- "最希望改进的地方是什么？"

### 焦点小组（Focus Group）
目的: 收集群体意见和讨论
方法: 6-8人小组讨论，90分钟
样本: 2-3组
适用场景:
- 新产品概念测试
- 功能偏好讨论
- 品牌认知研究

### 可用性测试（Usability Testing）
目的: 发现可用性问题
方法: 用户完成任务，观察行为
样本: 5人/轮
指标:
- 任务完成率
- 任务完成时间
- 错误率
- 满意度评分

### 日志研究（Diary Study）
目的: 了解长期使用行为
方法: 用户记录日常使用
周期: 1-4周
数据:
- 使用频率
- 使用场景
- 情绪变化
- 痛点记录
```

```markdown
## 定量研究

### 问卷调查（Survey）
目的: 收集大规模用户反馈
方法: 在线问卷
样本: 100+人（统计显著性）
工具:
- Google Forms

设计原则:
- 问题清晰无歧义
- 避免引导性问题

目的: 对比方案效果
方法: 随机分组，对比指标
样本: 统计显著性（n > 1000）
指标:
- 转化率
- 点击率
- 留存率
- 收入

流程:
1. 提出假设
2. 设计实验
3. 分流测试
4. 收集数据
5. 统计分析
6. 得出结论

### 数据分析（Data Analysis）
目的: 从数据中发现洞察
数据来源:
- 用户行为数据
- 业务数据
- 性能数据

方法:
- 漏斗分析（Funnel Analysis）
- 留存分析（Cohort Analysis）
- 分群分析（Segmentation）
- 归因分析（Attribution）
```

#### 行动4：产品指标体系（必选）

**北极星指标（North Star Metric）**：

```text
北极星指标: 最能反映产品核心价值的单一指标

选择标准:
1. 与用户价值直接相关
2. 与业务目标一致
3. 可操作可优化
4. 前置指标（非后置）

示例:
- Spotify: 每月收听时长
- Airbnb: 预订过夜数
- Slack: 每周活跃用户发送消息数
- Facebook: 月活跃用户数（DAU/MAU比）
```

**AARRR海盗指标**：

```text
Acquisition（获取）
├─ 指标: 新用户数、获客成本（CAC）
├─ 目标: 提高用户获取效率
└─ 优化: 营销渠道、SEO、ASO

Activation（激活）
├─ 指标: 首次使用率、核心功能使用率
├─ 目标: 让用户体验到价值（Aha Moment）
└─ 优化: 新手引导、产品流程

Retention（留存）
├─ 指标: 次日留存、7日留存、30日留存
├─ 目标: 提高用户粘性
└─ 优化: 产品价值、用户体验、通知

Revenue（变现）
├─ 指标: ARPU、LTV、转化率、付费率
├─ 目标: 提高商业价值
└─ 优化: 定价策略、付费功能、增值服务

Referral（推荐）
├─ 指标: 病毒系数（K Factor）、NPS
├─ 目标: 驱动口碑传播
└─ 优化: 分享功能、推荐激励
```

#### 战术2：数据驱动决策

**决策流程**：

```text
1. 提出假设
   ├─ 基于观察或数据
   ├─ 明确假设内容
   └─ 定义成功指标

2. 设计实验
   ├─ 确定实验方案
   ├─ 设计对照组和实验组
   └─ 计算样本量

3. 收集数据
   ├─ 运行实验
   ├─ 监控数据质量
   └─ 确保统计显著性

4. 分析结果
   ├─ 统计检验（t-test/卡方检验）
   ├─ 计算置信区间
   └─ 评估业务影响

5. 做出决策
   ├─ 拒绝或接受假设
   ├─ 制定行动计划
   └─ 持续监控
```

**常见产品决策误区**：

```markdown
## 误区1: 依赖假想数据

正确: 聚焦核心价值，做减法

## 误区3: 忽略留存
问题: 只关注获客，不关注留存
正确: 留存比获客更重要

## 误区4: 数据虚荣
问题: 追求好看但无意义的指标
正确: 关注北极星指标和业务目标

## 误区5: 用户意见=用户需求
问题: 用户说要什么就做什么
正确: 理解用户真实需求，而非表面要求

## 误区6: 缺乏优先级
问题: 所有功能都是P0
正确: 使用RICE/Kano模型优先级排序
```
