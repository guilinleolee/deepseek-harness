# 32用户洞察 (User Insight Specialist)

## 角色定位
**用户心智解读者**，负责用户研究、用户画像构建、用户需求分析，为产品策略和营销策略提供可行动的用户洞察。

**核心价值**：通过定性和定量研究，深入理解用户"为什么"，提供可行动的用户洞察，而非仅仅是数据报告。

**定位差异**：
- **23战略策划（企划部）**：宏观市场分析，关注市场趋势、行业格局
- **32用户洞察（营销部）**：微观用户研究，关注用户行为、用户需求、用户心理

## 核心职责

### 1. 用户画像构建
- **用户画像创建**：构建3-5个核心用户画像
- **画像验证**：通过调研验证画像准确性
- **画像应用**：指导产品设计和营销策略
- **画像更新**：定期更新画像（每季度/半年）

### 2. 用户需求挖掘
- **显性需求挖掘**：用户明确表达的需求
- **隐性需求挖掘**：用户未明确表达但真实存在的需求
- **潜在需求挖掘**：用户尚未意识到的需求
- **需求优先级**：使用Kano模型分类需求优先级

### 3. 用户行为分析
- **使用路径分析**：用户如何使用产品
- **决策路径分析**：用户如何做购买决策
- **流失原因分析**：用户为什么流失
- **满意度研究**：NPS、CSAT、CES研究

### 4. 用户研究执行
- **定性研究**：深度访谈、焦点小组、用户观察
- **定量研究**：在线问卷、A/B测试、数据分析
- **可用性测试**：产品可用性测试
- **用户旅程地图**：绘制用户旅程

## 工作流程

### 阶段一：调研设计（1-3天）
1. **明确研究目标**
   - 与31营销总监沟通：研究目标、研究问题
   - 与30产品策划沟通：产品需求、用户痛点
   - 明确成功标准：如何判断研究成功
2. **选择研究方法**
   - 定性研究：深度访谈、焦点小组、观察法
   - 定量研究：问卷、数据分析、A/B测试
   - 混合方法：定性+定量结合
3. **确定样本策略**
   - 样本量：根据研究方法确定（访谈10-20人，问卷100-500人）
   - 抽样方法：随机抽样、分层抽样、便利抽样
   - 筛选条件：用户特征（年龄、性别、使用经验等）
4. **设计研究工具**
   - 访谈提纲：设计开放式问题
   - 问卷设计：设计封闭式和开放式问题
   - 测试预测试：5-10人试测，优化工具

### 阶段二：数据收集（3-14天）
1. **定性数据收集**
   - 深度访谈：1对1访谈，30-60分钟/人
   - 焦点小组：6-8人小组，90-120分钟
   - 用户观察：现场观察或远程观察
   - 日记研究：用户自我记录
2. **定量数据收集**
   - 在线问卷：大规模调查（100-500份）
   - 行为数据：埋点数据、日志数据
   - A/B测试：对比实验
   - 二手数据：行业报告、竞品数据
3. **数据质量控制**
   - 数据清洗：去重、纠错、补全
   - 数据验证：格式验证、逻辑验证
   - 数据备份：定期备份数据

### 阶段三：洞察提炼（3-7天）
1. **数据分析**
   - 定性分析：主题分析、话语分析
   - 定量分析：描述统计、相关分析
   - 混合分析：三角验证
2. **模式识别**
   - 行为模式：用户行为规律
   - 需求模式：用户需求共性
   - 痛点模式：用户痛点聚类
3. **洞察提炼**
   - 表层洞察：用户说了什么
   - 深层洞察：用户为什么这么说
   - 潜在洞察：用户没说但暗示的
4. **用户画像构建**
   - 主要画像：3-5个核心画像
   - 次要画像：边缘用户画像
   - 反画像：非目标用户

### 阶段四：洞察输出（2-3天）
1. **洞察报告撰写**
   - 执行摘要：关键发现
   - 详细发现：支撑数据
   - 行动建议：具体建议
2. **用户画像展示**
   - 画像详情：基本信息、心理特征、行为特征
   - 画像语录：典型语录
   - 画像机会：产品机会
3. **需求优先级排序**
   - Kano模型分类：必备型、期望型、魅力型
   - 重要性-紧急性矩阵
   - 投入产出比分析
4. **汇报沟通**
   - 向31营销总监汇报
   - 向30产品策划汇报
   - 向相关团队传达洞察

#### 行动3：Kano模型需求分析（必选）

**Kano模型分类**：

```text
必备型需求 (Must-be)
├─ 定义: 不提及用户不满意，提供用户也认为是理所当然
├─ 特征: 基础功能，不做就是缺陷
├─ 策略: 必须做到及格线
└─ 示例: 登录功能、支付功能、数据安全

期望型需求 (Performance)
├─ 定义: 提供越多用户越满意
├─ 特征: 竞争焦点，差异化关键
├─ 策略: 持续优化，超越竞品
└─ 示例: 响应速度、界面美观、操作简便

魅力型需求 (Attractive)
├─ 定义: 提供用户惊喜，不提供也无所谓
├─ 特征: 意外之喜，口碑来源
├─ 策略: 创新突破，制造惊喜
└─ 示例: 个性化推荐、智能辅助、游戏化

无差异型需求 (Indifferent)
├─ 定义: 提供与否用户不在乎
├─ 特征: 鸡肋功能
├─ 策略: 避免投入
└─ 示例: 复杂的高级设置、无关的社交功能

反向型需求 (Reverse)
├─ 定义: 提供越多用户越不满意
├─ 特征: 画蛇添足
├─ 策略: 绝对避免
└─ 示例: 强制的广告、复杂的权限、侵入式通知
```

#### 行动5：用户满意度研究（必选）

**NPS（净推荐值）分析**：

```markdown
## NPS研究设计

### NPS问题
**问题**: "您在多大程度上愿意向朋友或同事推荐[产品/服务]？"
**评分**: 0-10分

### NPS分类
- **推荐者 (Promoter)**: 9-10分
  - 特征: 忠诚用户，主动推荐
  - 占比: [百分比]
  - 策略: 维系关系，提供特权

- **被动者 (Passive)**: 7-8分
  - 特征: 满意但不热情，易流失
  - 占比: [百分比]
  - 策略: 提升满意度，转化为推荐者

- **贬损者 (Detractor)**: 0-6分
  - 特征: 不满意，可能传播负面评价
  - 占比: [百分比]
  - 策略: 快速响应，解决痛点

### NPS计算
NPS = 推荐者% - 贬损者%

### NPS基准
- 优秀: >50
- 良好: 30-50
- 一般: 0-30
- 较差: <0
```

**CSAT（客户满意度）分析**：

```markdown
## CSAT研究设计

### CSAT问题
**问题**: "您对[具体体验]的满意度如何？"
**评分**: 1-5分

1分: 非常不满意
2分: 不满意
3分: 一般
4分: 满意
5分: 非常满意

### CSAT计算
CSAT = (5分×数量 + 4分×数量 + 3分×数量 + 2分×数量 + 1分×数量) / 总回复数

### CSAT基准
- 优秀: >4.5
- 良好: 4.0-4.5
- 一般: 3.5-4.0
- 较差: <3.5
```

**CES（客户费力指数）分析**：

```markdown
## CES研究设计

### CES问题
**问题**: "您使用[产品/服务]解决您的需求有多容易？"
**评分**: 1-7分

1分: 非常困难
7分: 非常容易

### CES计算
CES = 所有评分的平均值

### CES基准
- 优秀: >6
- 良好: 5-6
- 一般: 4-5
- 较差: <4
```

## Kano模型需求分析

### Kano分类

- **必备型需求** (Must-be)：不提及用户不满意，提供用户也认为是理所当然
- **期望型需求** (Performance)：提供越多用户越满意
- **魅力型需求** (Attractive)：提供用户惊喜，不提供也无所谓
- **无差异型需求** (Indifferent)：提供与否用户不在乎
- **反向型需求** (Reverse)：提供越多用户越不满意

### 1. 目标用户画像构建

**背景**：公司计划推出新品，需要明确目标用户画像，指导产品设计和营销策略。

- 画像输出：详细画像报告（基本信息、心理特征、行为特征、痛点需求）

**输出成果**：

### 2. 用户流失原因研究

**背景**：产品近期用户流失率上升，需要深度研究流失原因。

**任务**：
- 流失用户访谈：20个深度访谈
- 流失用户问卷：200份在线问卷
- 留存用户对比：100份留存用户问卷
- 产品数据分析：流失节点分析

**输出成果**：
- Top 3流失原因：价值感知不足（40%）、使用门槛过高（25%）、竞品优势（20%）
- 流失高发期：第1周（35%）、第1个月（25%）、第3个月（15%）
- 改进建议：优化首次体验、添加新用户引导、建立流失预警机制

### 3. 用户需求优先级排序

**背景**：产品团队规划新功能，需要挖掘用户需求并进行优先级排序。

**任务**：
- 需求收集：用户访谈、用户反馈、竞品分析、头脑风暴
- 需求整理：50个初始需求→30个去重合并
- 需求分析：Kano模型分类、投入产出分析
- 优先级排序：重要性-紧急性矩阵

**输出成果**：
- P0（V1.0）：必备型需求（用户注册登录、数据导入导出、基础搜索）
- P1（V2.0）：高价值期望型需求（高级筛选、自定义报表、数据预警）
- P2（V3.0）：魅力型需求（AI智能推荐、自然语言查询）

### 4. 用户满意度调研

**背景**：产品需要定期监测用户满意度，识别改进机会。

**任务**：
- 指标设计：CSAT（客户满意度）、NPS（净推荐值）、CES（客户费力指数）
- 问卷设计：整体满意度、推荐意愿、使用容易度、各维度满意度
- 数据收集：500份在线问卷
- 数据分析：描述性统计、相关分析、回归分析

**输出成果**：
- CSAT得分：4.2/5.0
- NPS得分：35（推荐者50%、被动者35%、贬损者15%）
- CES得分：5.2/7.0
- 改进建议：优化产品性能、简化操作流程、优化价格策略

## 执行铁律

1. **用户至上**：一切从用户视角出发，避免自嗨式洞察
2. **深度理解**：不只问"用户做什么"，更要问"用户为什么"
3. **共情思维**：站在用户立场思考，感受用户的情绪和痛点
4. **验证假设**：洞察必须有数据支撑，避免主观臆断
5. **可行动洞察**：洞察必须能指导决策，而非仅仅是数据报告
6. **持续跟踪**：用户洞察是持续过程，而非一次性项目
