# Blueprint — 蓝图规划器

> 来源: [affaan-m/everything-claude-code/skills/blueprint](https://github.com/affaan-m/everything-claude-code)

## 功能概述

将一句话目标转换为分步构建计划，支持多会话、多Agent工程项目的执行。每个步骤包含独立的上下文简报，确保新Agent可以冷启动执行。

## 何时使用

- 将大型特性拆分为多个PR，明确依赖顺序
- 规划跨越多个会话的重构或迁移
- 协调跨子Agent的并行工作流
- 任何需要在会话间保持上下文一致的任务

**不适用于**：单个PR可完成的任务、<3次工具调用、"just do it"场景。

## 工作流程（5阶段）

```
┌─────────────────────────────────────────────────────────────┐
│ Phase 1: Research (研究)                                  │
│ - 预检查 (git, gh auth, remote, default branch)          │
│ - 读取项目结构、现有计划、记忆文件                        │
├─────────────────────────────────────────────────────────────┤
│ Phase 2: Design (设计)                                    │
│ - 拆分为1-PR规模的步骤 (通常3-12步)                     │
│ - 分配依赖边、并行/串行顺序                              │
│ - 每步分配模型层级、 rollback策略                        │
├─────────────────────────────────────────────────────────────┤
│ Phase 3: Draft (草稿)                                     │
│ - 写入自包含Markdown计划文件                              │
│ - 每个步骤包含: 上下文简报、任务列表、验证命令、退出标准  │
├─────────────────────────────────────────────────────────────┤
│ Phase 4: Review (评审)                                     │
│ - 委托最强模型子Agent进行对抗性评审                       │
│ - 检查清单 + 反模式目录                                   │
│ - 修复所有关键问题后再定稿                               │
├─────────────────────────────────────────────────────────────┤
│ Phase 5: Register (注册)                                  │
│ - 保存计划、更新记忆索引                                 │
│ - 呈现步骤数和并行摘要                                   │
└─────────────────────────────────────────────────────────────┘
```

## 核心特性

| 特性 | 说明 |
|------|------|
| **冷启动执行** | 每步包含自包含上下文简报，无需读取前置步骤 |
| **对抗性评审门控** | 每计划由最强模型评审，检查清单+反模式检测 |
| **分支/PR/CI工作流** | 每步内置构建，git/gh缺失时优雅降级 |
| **并行步骤检测** | 依赖图识别无共享文件/输出的步骤 |
| **计划变更协议** | 步骤可拆分、插入、跳过、重排序，带正式协议和审计跟踪 |
| **零运行时风险** | 纯Markdown技能，无hooks/脚本/可执行代码 |

## 使用示例

**基础使用**
```
/blueprint myapp "迁移数据库到PostgreSQL"
```

生成 `plans/myapp-migrate-database-to-postgresql.md`，包含步骤：
- Step 1: 添加PostgreSQL驱动和连接配置
- Step 2: 为每个表创建迁移脚本
- Step 3: 更新仓储层使用新驱动
- Step 4: 添加PostgreSQL集成测试
- Step 5: 移除旧数据库代码和配置

**多Agent项目**
```
/blueprint chatbot "将LLM提供者提取为插件系统"
```

生成计划，并行步骤示例：
- "实现Anthropic插件" 和 "实现OpenAI插件" 在接口步骤完成后并行运行
- 模型层级分配：接口设计步骤使用最强模型，实现步骤使用默认模型
- 每步后验证不变式（如"所有现有测试通过"、"核心无提供者导入"）

## 计划文件格式

```markdown
# 计划: [项目名称] - [目标]

## 步骤概览
| Step | 名称 | 依赖 | 并行组 | 模型层级 |
|------|------|------|--------|---------|
| 1 | 步骤名 | - | A | strongest |
| 2 | 步骤名 | 1 | B | default |
| 3 | 步骤名 | 1 | B | default |

## Step 1: [名称]
### 上下文简报
[新Agent可以冷启动执行所需的全部上下文]

### 任务列表
- [ ] 任务1
- [ ] 任务2

### 验证命令
```bash
验证命令
```

### 退出标准
- [ ] 标准1
- [ ] 标准2

### Rollback策略
[如何回滚此步骤]
```

## 反模式目录

| 反模式 | 检测条件 | 修复建议 |
|--------|---------|---------|
| **上下文泄露** | 步骤依赖前置步骤的细节 | 重写为自包含 |
| **过早优化** | 步骤包含未经验证的性能改进 | 推迟到测量后 |
| **大爆炸重构** | 单一步骤>500行变更 | 拆分为子步骤 |
| **缺少不变式** | 无验证命令或退出标准 | 添加明确的验证 |
| **循环依赖** | A→B→C→A | 重构依赖图 |

## 最佳实践

1. **从1句话开始**：越模糊的目标，Blueprint帮你澄清
2. **验证不变式**：每步后验证关键约束不被破坏
3. **最小变更原则**：每PR只做一件事
4. **并行检测**：识别可并行步骤加速执行
5. **冷启动优先**：每步上下文自包含
