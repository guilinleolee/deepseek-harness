# rhythm-orchestration - 节奏编排引擎

> **版本**: V1.0
> **来源**: 老金元组织方法论 × 天龙引擎V8.96
> **核心**: 节奏编排5决策 + 跳过/插队/暂停协议

---

## 核心概念

### 什么是节奏编排？

**节奏编排** ≠ 工作流顺序
**节奏编排** = 让系统学会：谁先上，谁后上，谁跳过，谁插队，谁暂停。

核心思想：
- 不是所有能力都该同时出现
- 不是所有步骤都必须完整走完
- 成熟系统一定是有取舍的

### 5大节奏决策

```
┌─────────────────────────────────────────────────────────────┐
│ 节奏编排5决策                                               │
├─────────────────────────────────────────────────────────────┤
│ 1. 谁先上    → 优先级排序                                  │
│ 2. 谁后上    → 串行依赖管理                                │
│ 3. 谁跳过    → 条件触发跳过                                │
│ 4. 谁插队    → 风险优先级上升                              │
│ 5. 谁暂停    → 资源争用/流控                               │
└─────────────────────────────────────────────────────────────┘
```

---

## 节奏编排流程

### 7步法

```
Step 1: 元识别
├── 输入: 任务分解后的元列表
└── 输出: 参与编排的元集合

Step 2: 依赖分析
├── 分析元间依赖关系
├── 构建依赖DAG（有向无环图）
└── 输出: 依赖拓扑序列

Step 3: 优先级判定
├── 紧迫度（时间敏感度）
├── 重要性（业务价值）
├── 阻塞度（是否阻塞其他元）
└── 输出: 优先级矩阵

Step 4: 节奏设计
├── 确定执行顺序
├── 确定并行/串行
├── 设定同步点
└── 输出: 节奏图

Step 5: 跳过条件设计
├── 识别可跳过节点
├── 定义跳过条件
├── 设计跳过后的路径
└── 输出: 跳过矩阵

Step 6: 插队规则设计
├── 识别高风险场景
├── 定义插队条件
├── 设计插队后的恢复
└── 输出: 插队协议

Step 7: 暂停规则设计
├── 识别资源争用场景
├── 定义暂停条件
├── 设计恢复流程
└── 输出: 暂停协议
```

## 跳过协议（Skip Protocol）

### 核心原则

> "不是每个流程节点都必须严格走一遍。有些时候，步骤存在，但当前任务里不值得单独占一个节奏位。"

### 跳过条件类型

```yaml
skip_conditions:
  - type: "triviality_skip"
    trigger: "任务规模<阈值"
    examples:
      - "单文件修改跳过评审"
      - "单行代码修改跳过测试"
      - "文档更新跳过安全扫描"

  - type: "redundancy_skip"
    trigger: "结果已存在"
    examples:
      - "缓存命中跳过重复计算"
      - "已验证跳过重复校验"
      - "历史记录存在跳过重新分析"

  - type: "context_skip"
    trigger: "上下文已满足"
    examples:
      - "前置结果已知跳过等待"
      - "用户已确认跳过确认步骤"
      - "环境已就绪跳过准备步骤"

  - type: "risk_skip"
    trigger: "风险评估<阈值"
    examples:
      - "低风险变更跳过完整评审"
      - "热修复跳过预发布检查"
      - "实验性功能跳过合规检查"
```

### 跳过决策矩阵

```
┌─────────────────────────────────────────────────────────────┐
│ 跳过决策检查表                                              │
├─────────────────────────────────────────────────────────────┤
│ 元: ________________                                        │
│                                                             │
│ 跳过条件检查:                                              │
│ □ 任务规模 < 设定阈值（Y/N）: ____                        │
│ □ 结果已存在于缓存（Y/N）: ____                           │
│ □ 上下文已满足前置条件（Y/N）: ____                       │
│ □ 风险评估 < 低风险阈值（Y/N）: ____                       │
│                                                             │
│ 跳过风险检查:                                              │
│ □ 跳过不会导致数据不一致（Y/N）: ____                      │
│ □ 跳过不会绕过安全检查（Y/N）: ____                        │
│ □ 跳过有清晰的回退路径（Y/N）: ____                        │
│                                                             │
│ 决策: □跳过  □不跳过  □需人工确认                          │
│ 理由: ___________________________________________________   │
└─────────────────────────────────────────────────────────────┘
```

## 插队协议（Preempt Protocol）

### 核心原则

> "现实不是永远按顺序发生的。总会有高风险、异常、突发、全局影响。这时候如果系统还死守原顺序，那它不是稳，是僵。"

### 插队条件类型

```yaml
preempt_conditions:
  - type: "security_preempt"
    trigger: "安全相关事件"
    priority: "P0_CRITICAL"
    action: "立即中断当前，切换到安全处理"
    examples:
      - "发现恶意代码"
      - "检测到注入攻击"
      - "权限验证失败"

  - type: "data_integrity_preempt"
    trigger: "数据完整性风险"
    priority: "P0_CRITICAL"
    action: "立即中断，锁定数据"
    examples:
      - "检测到数据不一致"
      - "发现事务未提交"
      - "回滚操作需要执行"

  - type: "performance_preempt"
    trigger: "性能严重劣化"
    priority: "P1_HIGH"
    action: "暂停非关键任务，专注性能优化"
    examples:
      - "响应时间 > SLA阈值 3倍"
      - "内存使用 > 90%"
      - "队列积压 > 1000条"

  - type: "user_interaction_preempt"
    trigger: "用户紧急请求"
    priority: "P2_MEDIUM"
    action: "优先响应用户，关键任务降级"
    examples:
      - "用户主动中断"
      - "紧急查询请求"
      - "高优先级问题反馈"
```

```
┌─────────────────────────────────────────────────────────────┐
│ 插队决策检查表                                              │
├─────────────────────────────────────────────────────────────┤

│ 候选插队事件: ________________                             │
│                                                             │
│ 紧迫度检查:                                                │
│ □ 是否威胁系统安全（Y/N）: ____                            │
│ □ 是否威胁数据完整性（Y/N）: ____                          │
│ □ 是否威胁业务连续性（Y/N）: ____                          │
│ □ 用户是否等待（Y/N）: ____                                │
│                                                             │
│ 影响评估:                                                  │
│ 当前任务完成度: ____%                                       │

│ 插队后恢复时间: ____分钟                                    │

│ 理由: ___________________________________________________   │
```

## 暂停协议（Pause Protocol）

### 核心原则

> "当资源争用或系统过载时，成熟系统必须能智能暂停，而非盲目继续导致雪崩。"

### 暂停条件类型

```yaml
pause_conditions:
  - type: "resource_contention"
    trigger: "共享资源争用"
    action: "暂停低优先级任务，释放资源"
    examples:
      - "数据库连接池耗尽"
      - "API配额剩余 < 10%"
      - "并发请求数 > 阈值"

  - type: "backpressure"
    trigger: "下游处理能力不足"
    action: "暂停生产，阻止积压"
    examples:
      - "队列长度 > 1000"
      - "处理速度 < 生产速度 50%"
      - "下游超时频繁"

  - type: "circuit_breaker"
    trigger: "熔断器触发"
    action: "全局暂停相关调用"
    examples:
      - "错误率 > 50%"
      - "连续超时 > 5次"
      - "服务不可用"
```

## 节奏图表示例

### 简单节奏图

```
任务: 内容创作
────────────────────────────────────────────────────────────

元: [理解] → [资料] → [方案] → [执行] → [检查]
                    ↓
              [跳过? 条件:资料已存在]

节奏:
- 理解: 先上
- 资料: 理解后
- 方案: 资料后（或跳过资料）
- 执行: 方案后
- 检查: 执行后

特殊:
- 插队: 安全问题 → 安全检查立即执行
- 暂停: API限流 → 等待恢复
```

### 复杂节奏图

```
任务: 系统开发
────────────────────────────────────────────────────────────

Phase 1: 准备阶段（可并行）
├── [环境检查] ─┐
├── [依赖分析] ─┼→ [依赖汇总]
├── [风险扫描] ─┘

Phase 2: 核心执行（按序）
[方案设计] → [评审] → [执行] → [测试] → [部署]

Phase 3: 收尾阶段（可跳过）
└── [文档更新] ← 条件: 正式发布

节奏规则:
- Phase 1三任务并行，但依赖分析必须先完成
- 评审可跳过条件: 小改动 + 低风险
- 文档更新可跳过条件: 热修复
- 插队: 安全问题 → 安全评审立即执行
- 暂停: 测试失败率 > 30% → 暂停执行
```

## 命令速查

```bash
# 节奏设计
/rhythm-design <任务>                # 生成节奏图
/rhythm-design --step-by-step      # 逐步设计

# 跳过设计
/skip-define <步骤>                 # 定义跳过条件
/skip-eval <任务>                   # 评估可跳过节点
/skip-matrix                        # 生成跳过决策矩阵

# 插队设计
/preempt-define <场景>              # 定义插队条件
/preempt-eval <事件>                # 评估插队优先级
/preempt-matrix                     # 生成插队决策矩阵

# 暂停设计
/pause-define <场景>               # 定义暂停条件
/pause-eval <状态>                 # 评估暂停必要性
/pause-matrix                      # 生成暂停决策矩阵

# 节奏验证
/rhythm-validate <节奏图>          # 验证节奏图完整性
/rhythm-simulate <节奏图> <场景>   # 模拟执行

# 节奏优化
/rhythm-optimize <节奏图>          # 优化节奏
/rhythm-check-deadlock             # 检查死锁风险
```

## 与其他技能协同

| 技能 | 协同方式 |
|------|---------|
| **meta-design** | 元拆分后 → 节奏编排 |
| **card-dealing** | 节奏设计后 → 发牌时机 |
| **silence-protocol** | 跳过决策 → 留白机会识别 |
| **escalation-matrix** | 插队/暂停 → 升级触发 |

## 适用场景

| 场景 | 节奏编排价值 |
|------|------------|
| 复杂任务执行 | 确定执行顺序和并行度 |
| 多Agent协作 | 协调多个Agent的执行节奏 |
| 紧急响应 | 快速插队处理危机 |
| 资源优化 | 智能暂停避免过载 |
| 快速迭代 | 跳过不必要步骤加速 |
