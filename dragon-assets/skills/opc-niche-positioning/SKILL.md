# OPC-Niche-Positioning 三环定位

## 定位陈述

**职能**: 利基市场定位 | **协议**: OPC | **边界**: 不进入内容/话术/运营层

## 核心价值

通过"三环合一"框架发现最优利基：**新杠杆/元杠杆** + **边界变动** + **创始人独有资源**。三环重叠处胜算最高。

## 三环分析框架

### 环1：新杠杆与元杠杆

**新杠杆**（无需许可）：
- 代码杠杆：一次构建，无限服务。服务第100万用户和第101用户的成本趋近于零
- 媒体杠杆：一次诉说，无限回响。文章/视频/播客，多一人看不增加成本

**元杠杆**（AI作为创造杠杆的杠杆）：
- 第三波自动化：替代创造性脑力（写作/设计/分析/策划）
- 质变临界点：完整业务闭环100%自动化 → 自主主体 → 创始人从驾驶员变调度员

**分析问句**：这个赛道里能用代码/媒体/AI自动化替代人力一对一服务吗？

### 环2：边界变动

| 边界类型 | 影响 | 重点问句 |
|---------|------|---------|
| **技术边界变动** | 最大，当前最活跃 | AI让什么变得可能？过去十人团队的事现在一人能做了吗？ |
| **信息传播路径变动** | 流量迁移窗口期 | 用户现在活跃在哪个平台？商业化是否还没饱和？ |
| **政策/监管边界变动** | 行业消失/新行业诞生 | 政策在推动哪个细分方向？ |

**核心判断**：原有商业路径的受益者，为什么没有/不会/不愿意追这个方向？（价值网络冲突=以小博大的空间）

### 环3：独有资源与优势

直接从 `opc-doc/outputs/01-resource-audit/` 读取，不重新收集。把资源盘点作为"叠加层"——先有环1和环2的分析结论，再叠加上来看哪里匹配。

## 机会评分六维模型

找到候选利基后，用六个维度筛选：

| 维度 | 评估内容 | 分值 |
|------|---------|------|
| 痛点强度 | 目标用户有多痛？是忍一忍就过去的不便，还是反复影响核心需求？ | 1-5 |
| 杠杆密度 | 代码/媒体/AI自动化能叠加几种？ | 1-5 |
| 窗口红利 | 现在进入是否刚好赶上边界移动早期？ | 1-5 |
| 资源匹配度 | 创始人资源/经验/关系能直接转化为优势吗？ | 1-5 |
| 交付标准化 | 能形成可复用交付流程，而不是每次从头定制？ | 1-5 |
| 现金流潜力 | 多快能产生实际收入（不依赖大量前期资本）？ | 1-5 |

**总分**：XX/30，高分优先推进

## 执行协议

### SCP协议（苏格拉底对话）

- 默认**一次只问一个问题**
- 如果几个问题都很轻且紧密相关，可合并成2-3个
- 给出**3个候选利基方案**，并附加"4. 我有自己的方案"
- **用户确认后再写入正式结果**
- 不直接给推荐结论，只做方案分析

### 执行步骤

```
1. 解释本步目标
   └→ 先解释三环含义，新杠杆vs元杠杆区别，什么叫边界变动

2. 先分析环2（边界变动）
   └→ 行业最近发生了哪些明显变化？
   └→ 有没有之前做不到、现在可以做到的事？
   └→ 某类客户以前只能找大公司，现在可以找个体了？
   └→ 原有路径上的大公司为什么没追这个方向？

3. 再分析环1（新杠杆/元杠杆）
   └→ 代码/工具：能否用软件/自动化代替人力重复劳动？
   └→ 媒体：能否把知识/经验做成可反复使用的内容资产？
   └→ 元杠杆：这个行业有没有完整业务流程可交给AI自主运转？

4. 读取环3（资源叠加）
   └→ 从 opc-doc/outputs/01-resource-audit/ 获取资源盘点结论
   └→ 把环1+环2的发现叠上来，找三环重叠区

5. 每轮回答后给简短反馈，标注激活了哪个环

6. 生成3个候选利基（每个格式）：
   候选利基X：[简短名称]
   目标用户：谁，处于什么处境
   核心痛点：什么问题，有多痛
   激活的环：✅/❌ 环1 | ✅/❌ 环2 | ✅/❌ 环3
   时间窗口：为什么现在是合适的时机
   大公司为什么不追：价值网络冲突/体量太小/速度太慢
   机会评分（六维）：痛点X | 杠杆X | 窗口X | 资源X | 标准化X | 现金流X
   总分：XX/30
   风险点：

7. 默认增加"4. 我有自己的方案"

8. 让用户选择、组合、修改，或直接提出自己的版本

9. 用户确认后，生成定位陈述并落盘
```

## 本阶段边界

### ✅ 本步做什么

- 分析新杠杆/元杠杆可用方向（环1）
- 识别行业边界变动，尤其是大公司追不上的方向（环2）
- 叠加创始人独有资源，找三环重叠区（环3）
- 用机会评分模型对候选利基做六维评估
- 确认目标利基，形成定位陈述

### ❌ 本步不做什么

- 不做内容策略或内容形态规划（→MVP设计阶段）
- 不做文案撰写、话术设计、帖子骨架（→资产沉淀阶段）
- 不做平台运营方案或渠道选择（→转化闭环阶段）
- 不做产品定价（→商业模式设计阶段）
- 不做获客路径或具体转化步骤（→转化闭环阶段）

**越界检测**：如果出现"发什么内容""怎么写文案""用哪种格式""怎么发小红书"，立即说：
> "这个方向很有价值，不过它属于后续阶段。我们先把利基定位确认好，后面的执行才有准确的靶心。"

## 落盘文件

用户确认目标利基和定位陈述后，**立即**写入：

```
opc-doc/outputs/02-niche-positioning/
├── three-ring-analysis.md       # 三环分析结论
├── candidates.md               # 3个候选利基及机会评分六维
├── target-segment.json          # 确认的目标细分
└── positioning-statement.md      # 定位陈述

opc-doc/state/
├── current-stage.json           # {"stage": "02-niche-positioning", "status": "completed"}
└── decisions.json              # 追加确认的利基选择
```

**落盘完成后告知用户**：
> "✅ 利基定位结论已保存。下次对话可以从价值主张继续。"

**只有落盘完成后，才可以提示进入 `opc-value-proposition`**。

## 异常处理

| 情况 | 处理 |
|------|------|
| 市场太大 | 强制切细，不允许停留在宽泛市场 |
| 用户给不出答案 | 先基于行业背景生成合理候选，不把压力全丢给用户 |
| 三环都找不到重叠点 | 如实告知，探讨是否扩大行业范围或调整资源方向 |
