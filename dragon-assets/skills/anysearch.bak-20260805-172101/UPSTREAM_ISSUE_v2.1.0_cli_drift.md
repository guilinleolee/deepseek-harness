## 🇬🇧 English Version

### Title

`[Bug] CLI ↔ SKILL.md drift: list_domains/get_sub_domains not registered, --sdp alias missing`

### Body

#### Summary

I integrated `anysearch-ai/anysearch-skill@v2.1.0` and ran an end-to-end smoke test against the Node CLI. I found **three CLI/documentation inconsistencies** that block vertical search workflows from being used as documented. This is an upstream bug report — not a request for new features. The fix scope is small (3–5 lines per file).

#### Environment

- Upstream: `anysearch-ai/anysearch-skill` @ `main` (commit from 2026-07-19)
- Binary under test: `scripts/anysearch_cli.js` (13,630 bytes, last modified 2026-06-13)
- Platform: Windows 11 / Node.js v24.16.0
- API key: none (anonymous access)

#### Bug 1 — `list_domains` and `get_sub_domains` commands do not exist in CLI

**What the docs say**:
- `SKILL.md` frontmatter mentions `get_sub_domains` as the discovery command.
- `node scripts/anysearch_cli.js doc` (CLI's offline help) outputs a section titled "### 2. list_domains — Query vertical domain directory" that documents a `--domain` / `--domains` command.
- `README_zh.md` and `README.md` both reference "list sub_domains" / "discover sub_domains" before any vertical search.

**Actual CLI behavior** (minimal reproduction):

```bash
$ node scripts/anysearch_cli.js get_sub_domains --domain finance
Unknown command: get_sub_domains

$ node scripts/anysearch_cli.js list_domains --domain finance
tool 'list_domains' not found: tool not found
```

The CLI prints the offline `doc` text as a fallback, but never actually discovers sub-domains. This blocks any agent workflow that follows the documented "always call get_sub_domains first" rule.

**Suggested minimal patch** (one line in `scripts/shared/doc_spec.md`, plus routing in each of the 4 CLI files):

```js
// In anysearch_cli.{js,py,ps1,sh}: add to the command dispatcher
case 'list_domains':
case 'get_sub_domains':
  return await callTool('list_domains', { domain, domains });
```

The backend already exposes `list_domains` as a JSON-RPC tool (per the doc string), so this is purely a CLI routing fix.

#### Bug 2 — `--sdp` alias not implemented in `search`

**What the docs say** (README_zh.md, §"Command Cheat Sheet"):

```
<cmd> search "AAPL" --domain finance --sub_domain finance.quote --sdp type=stock,symbol=AAPL,cn_code=
```

**Actual CLI behavior**:

```bash
$ node scripts/anysearch_cli.js search "AAPL" \
    --domain finance --sub_domain finance.quote \
    --sdp 'type=stock,symbol=AAPL,cn_code='
Unknown flag: --sdp
# (correct flag is the long form --sub_domain_params)
```

**Suggested minimal patch** (one line per CLI):

```js
const SUBDOMAIN_PARAMS_ALIASES = ['--sdp', '--sub_domain_params', '-p'];
const sub_domain_params = SUBDOMAIN_PARAMS_ALIASES.includes(arg)
  ? next()
  : args.sub_domain_params;
```

#### Bug 3 — `runtime.conf.example` and `.env.example` missing from the repo

The upstream README instructs users to copy `.env.example` and write a `runtime.conf` after installation. Both files are `.gitignore`-listed but the repo does not contain them, so users see "No such file or directory" when they try to copy.

**Suggested minimal patch** (add 2 files):

`.env.example`:
```
# Optional: paste your AnySearch API key here for higher rate limits.
# Get one for free at https://anysearch.com/console/api-keys
ANYSEARCH_API_KEY=
```

`runtime.conf.example`:
```
# Auto-generated by the AnySearch installation entry test.
# Replace <skill_dir> with the absolute path to this skill.
Runtime=Node.js
Command=node <skill_dir>/scripts/anysearch_cli.js
```

#### Workaround used by downstream (for context only)

While waiting for the fix, my fork (`dragon-engine/skills/anysearch-*/SKILL.md`) hard-codes the three known sub-domain schemas — `academic.arxiv`, `business.market`, `finance.quote` — and supplies the required params directly. This works because the backend correctly returns `Missing required params for tag '<tag>'` (which is a good validation message — that part is fine).

#### Test matrix used

| # | Test | Result | Time |
|---|---|---|---|
| 1 | `node scripts/anysearch_cli.js doc` | ✅ offline schema | <100ms |
| 2 | `search "AnySearch skill github integration 2026" -m 2` | ✅ 2 results | 1235ms |
| 3 | `search "AAPL" -d finance -s finance.quote -p 'type=stock,symbol=AAPL,cn_code='` | ✅ schema ok | <1s |

The first 4 are end-to-end green; #5 and #6 are the bugs reported here.

Happy to open a PR with the three minimal patches above if you ack the approach.

#### 摘要

我在天龙引擎（dragon-engine）里集成了 `anysearch-ai/anysearch-skill@v2.1.0`，用 Node CLI 跑了端到端冒烟测试，发现**三处文档与 binary 不一致**的问题，导致按文档走的 vertical search 流程跑不通。这不是新功能请求——bug 修复合计 3-5 行/文件。

#### 环境

- 上游：`anysearch-ai/anysearch-skill` @ `main`（2026-07-19 commit）
- 受测 binary：`scripts/anysearch_cli.js`（13,630 bytes，2026-06-13 last modified）
- 平台：Windows 11 / Node.js v24.16.0
- API key：无（匿名访问）

#### Bug 1 — `list_domains` / `get_sub_domains` 在 CLI 未注册

**文档怎么写**：
- `SKILL.md` frontmatter 把 `get_sub_domains` 列为 discovery 命令
- `node scripts/anysearch_cli.js doc` 输出的 schema 里有一节 "### 2. list_domains — Query vertical domain directory"，描述 `--domain` / `--domains`
- `README_zh.md` 与 `README.md` 都强调 vertical search 前必须先 "list sub_domains" / "discover sub_domains"

**CLI 实际行为**（最小复现）：

```bash
$ node scripts/anysearch_cli.js get_sub_domains --domain finance
Unknown command: get_sub_domains

$ node scripts/anysearch_cli.js list_domains --domain finance
tool 'list_domains' not found: tool not found
```

CLI 退回打 `doc` 文本，但**从不真正查 sub-domain**。任何按文档写的"先调 get_sub_domains"工作流都被堵死。

**最小补丁**（每个 CLI 文件加 1 行路由）：

```js
case 'list_domains':
case 'get_sub_domains':
  return await callTool('list_domains', { domain, domains });
```

后端 JSON-RPC 端点本来就有 `list_domains`（见 doc），纯 CLI 路由问题。

#### Bug 2 — `--sdp` 别名在 `search` 未实现

**文档这么写**（README_zh.md "Command Cheat Sheet"）：

```
<cmd> search "AAPL" --domain finance --sub_domain finance.quote --sdp type=stock,symbol=AAPL,cn_code=
```

**CLI 实际行为**：

```bash
$ node scripts/anysearch_cli.js search "AAPL" \
    --domain finance --sub_domain finance.quote \
    --sdp 'type=stock,symbol=AAPL,cn_code='
Unknown flag: --sdp
# 必须用全名 --sub_domain_params
```

**最小补丁**：

```js
const SUBDOMAIN_PARAMS_ALIASES = ['--sdp', '--sub_domain_params', '-p'];
```

#### Bug 3 — `runtime.conf.example` 与 `.env.example` 仓库里缺失

README 教用户装完跑 entry test 后写 `runtime.conf` 与 `.env`，但这俩文件都在 `.gitignore` 里、仓库里没有，导致 `cp` 时报 "No such file or directory"。

**最小补丁**（加 2 文件）见上方英文版。
