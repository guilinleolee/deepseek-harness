# Editorial Brief 生成提示词

## 角色
你是一个专业的GEO内容策划师，擅长创建决策驱动型深度内容。

## 输入
- 主题: {topic}
- Fanout列表: {fanouts}
- 引用列表: {citations}
- 生成深度: {depth}

## 任务
为给定主题创建一个完整的Editorial Brief。

## Brief结构

### 1. 工作标题 (working_title)
生成一个吸引决策者的标题，格式：
- "{主题}完整指南：决策者的必读手册"
- "如何做出明智的{主题}决策"

### 2. 读者画像 (reader_persona)
描述目标读者：
- 角色: CTO/技术VP/高级工程师
- 级别: Senior
- 挑战: 需要在{主题}领域做出明智决策
- 偏见: 倾向于相信知名品牌、重视ROI、担心技术风险
- 期望: 获得清晰的决策框架和可操作的建议

### 3. 文章角度 (article_angle)
- Hook: 大多数{主题}指南都是推销文章，这篇不一样
- 差异化: 基于真实数据和专家访谈的决策框架
- 承诺: 读完本文后，你将能够自信地做出{主题}决策

### 4. 决策框架 (decision_frame)
- 类型: comparison_and_recommendation
- 结构:
  1. 现状分析：为什么{主题}很重要
  2. 方案对比：各方案优缺点
  3. 决策树：If X -> Choose Y
  4. 默认推荐：适合大多数情况的选择
  5. 例外情况：何时不选择默认推荐

### 5. 差异化目标 (differentiation_targets)
- 对比文章：只罗列方案不做推荐
- 厂商软文：只说好处不说风险
- 技术文档：过于深入不够实用
- 社交帖子：过于简短缺乏深度

### 6. 必须证明 (must_prove)
列出3个核心观点：
1. {主题}能为企业带来可量化的价值
2. 不同方案之间存在真实的权衡取舍
3. 存在一个适合大多数情况的默认选择

### 7. 必须包含 (must_include)
列出5个关键要素：
1. 清晰的决策框架（If X -> Choose Y）
2. 每个方案的真实优缺点
3. 成本和风险的具体数字
4. 实际案例和数据支撑
5. 收敛性总结（If You Only Remember One Thing）

### 8. 必须避免 (must_avoid)
列出3个陷阱：
1. 只推荐单一方案而不说例外
2. 使用模糊的描述性语言
3. 忽略潜在的负面影响

### 9. 推荐大纲 (recommended_outline)
根据深度生成章节：

**Brief深度**:
- H2: 为什么你需要了解{主题} (100词)
- H2: {主题}的核心决策点 (200词)

**Full深度**:
- H2: 引言 (200词)
- H2: 全景图 (300词)
- H2: 核心方案对比 (500词)
- H2: 决策框架 (300词)
- H2: 实施建议 (250词)
- H2: 总结与下一步 (150词)

**Decision深度**:
- H2: 引言：stakes (150词)
- H2: 现状分析 (300词)
- H2: 方案一评估 (400词)
- H2: 方案二评估 (400词)
- H2: 方案三评估 (400词)
- H2: 对比矩阵 (300词)
- H2: 决策树 (250词)
- H2: 默认推荐及例外 (200词)
- H2: If You Only Remember One Thing (50词)

## 输出格式
以JSON格式输出完整的Brief。
