# dbs-benchmark

## L0: 一句话描述
五维对标分析——在努力程度、方法、时机、运气、环境五维度对标评估。

## L1: 使用场景
当用户抱怨努力但无回报，或在反思失败原因时使用。区分努力方向（内卷 vs 有效努力）与外部因素，避免错误的归因。

## L2: 详细文档

### 核心能力
五维度对标分析法，将结果归因到可改进因素与不可控因素。

### 五维度定义

| 维度 | 问法 | 可控性 | 评估问题 |
|------|------|--------|---------|
| **努力** | "投入够吗？" | 高 | 时间、质量、一致性 |
| **方法** | "方法对吗？" | 高 | 策略、工具、路径 |
| **时机** | "时机对吗？" | 中 | 市场窗口、节奏、准备度 |
| **运气** | "随机因素影响？" | 无 | 随机波动、竞争态势 |
| **环境** | "外部条件有利吗？" | 无 | 市场、竞争、政策 |

### 对标评估矩阵

```
评估标准（每维度1-10分）:

努力维度:
  1-3: 投入不足，三天打鱼两天晒网
  4-6: 有一定投入，但不够持续
  7-10: 全力以赴，一致性高

方法维度:
  1-3: 方法错误南辕北辙
  4-6: 方法基本正确但有优化空间
  7-10: 方法正确，策略清晰

时机维度:
  1-3: 时机不对，提前或滞后
  4-6: 时机一般，有更好窗口
  7-10: 时机精准

运气维度:
  1-3: 运气极差，随机因素严重不利
  4-6: 运气一般，无明显好坏
  7-10: 运气极好

环境维度:
  1-3: 环境极不利，竞争激烈市场萎缩
  4-6: 环境一般，机会与挑战并存
  7-10: 环境有利，蓝海市场政策支持
```

### 诊断决策树

```
结果不如预期?
  │
  ├─ 努力 < 5?
  │    └─ 结论: 努力不足，先解决投入问题
  │
  ├─ 方法 < 5?
  │    └─ 结论: 方法有问题，重新审视策略
  │
  ├─ 时机 < 5?
  │    └─ 结论: 时机不对，考虑节奏调整
  │
  ├─ 环境 < 5?
  │    └─ 结论: 环境不利，降低预期或换环境
  │
  └─ 运气 < 5?
       └─ 结论: 运气因素，接受并坚持
```

### 归因比例模型

```python
结果 = 努力 × 0.25 + 方法 × 0.30 + 时机 × 0.15 + 运气 × 0.15 + 环境 × 0.15

# 权重说明:
# 方法权重最高: 策略正确性决定天花板
# 努力权重次高: 努力是最低门槛
# 时机/运气/环境: 各占15%，不可控但需承认
```

### 输出格式

```markdown
## dbs-benchmark 对标报告

### 五维评分
- 努力: [1-10] [具体评估]
- 方法: [1-10] [具体评估]
- 时机: [1-10] [具体评估]
- 运气: [1-10] [具体评估]
- 环境: [1-10] [具体评估]

### 综合评估
- 总分: [加权总分]/10
- 最高分: [维度] - [说明]
- 最低分: [维度] - [说明]

### 归因分析
- 可控因素贡献: [努力+方法] = [%]
- 不可控因素影响: [时机+运气+环境] = [%]

### 建议
1. [基于最高分的优势发挥]
2. [基于最低分的改进方向]
3. [对不可控因素的接受策略]
```

### 使用命令

```bash

```

### 关键提问

```
"你每天为这件事投入多少时间？持续多久了？"
"你是怎么判断方法是否正确的？有没有参考对象？"
"如果重来一次，你会改变什么？"
"在这个过程中，有哪些是你无法控制的？"
```

### 常见归因偏差

| 偏差类型 | 表现 | 纠正方法 |
|---------|------|---------|
| 自利偏差 | 成功归自己，失败归外因 | 强制五维度评分 |
| 基本归因错误 | 忽视情境因素 | 检查环境/运气维度 |
| 努力陷阱 | 以为努力=结果 | 重点评估方法维度 |
| 后见之明 | 事后认为必然 | 假设未发生会怎样 |
