# dbs-diagnosis

## L0: 一句话描述
问题诊断——从症状追溯根因，判断问题是"可解决"还是"需接受"。

## L1: 使用场景
当用户面临困境（业务问题、技术障碍、人生选择）且无法确定根本原因时使用。区分可控因素与不可控因素，避免在死胡同里浪费精力。

## L2: 详细文档

### 核心能力
Wittgenstein语言哲学驱动的问题诊断框架，通过"七表解构"揭示问题本质。

### 七步诊断流程

```
Step 1: 症状识别
  - 具体表现是什么？（可观测事实）
  - 首次出现是什么时候？
  - 频率和强度如何变化？

Step 2: 边界划定
  - 问题边界在哪里？
  - 哪些是问题内，哪些是问题外？
  - 与哪些因素无关？

Step 3: 可控性判断
  - 我能控制的部分是什么？
  - 我无法控制的因素是什么？
  - 边界在哪里？

Step 4: 根因追溯
  - 如果可控 → 找最近一次成功是什么时候？
  - 如果不可控 → 这是否是无法改变的事实？

Step 5: 行动分类
  - 可控+可解决 → 制定解决计划
  - 可控+难解决 → 寻找替代路径
  - 不可控 → 制定接受策略
  - 不可控+严重 → 制定缓解计划

Step 6: 最小行动承诺
  - 如果只做一件事，是什么？
  - 能否承诺一个5分钟行动？

Step 7: 验证与迭代
  - 48小时后回检症状变化
  - 根据反馈调整诊断
```

### 三类问题处理策略

| 问题类型 | 判断标准 | 处理策略 |
|---------|---------|---------|
| **可解决** | 可控因素 + 信息充分 + 存在先例 | 聚焦解决，制定计划 |
| **可缓解** | 部分可控 + 资源有限 | 最小化伤害，降低期望 |
| **需接受** | 不可控因素主导 + 无先例 | 区分事实与情绪，制定应对预案 |

### 输出格式

```markdown
## dbs-diagnosis 诊断报告

### 问题分类
- 类型: [可解决/可缓解/需接受]
- 可控部分: [具体描述]
- 不可控部分: [具体描述]

### 根因分析
[问题本质描述]

### 推荐行动
1. 即时行动: [5分钟内可做]
2. 短期计划: [本周内完成]
3. 长期策略: [本月内推进]

### 需接受的现实
[如果存在不可控因素，明确列出]

### 回检节点
- 48小时: [具体回检问题]
- 1周后: [具体回检问题]
```

### 关键判断语句

```
如果可控:
  "最近一次成功是什么时候？那次和现在有什么不同？"

如果不可控:
  "这个问题如果无法解决，你是否能继续前行？"
  "最坏情况下，你如何应对？"

如果是借口:
  "你是在告诉我一个事实，还是在表达一种感受？"
```

### 使用命令

```bash
/dbs-diagnosis              # 启动完整诊断流程
dbs-diagnosis "问题描述"    # 直接分析给定问题
```

### 诊断清单

- [ ] 症状已被具体描述（非模糊感受）
- [ ] 问题边界已明确
- [ ] 可控/不可控因素已分离
- [ ] 用户对不可控部分已有心理准备
- [ ] 至少一个即时行动被承诺
