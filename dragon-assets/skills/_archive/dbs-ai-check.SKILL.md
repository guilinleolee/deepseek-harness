# dbs-ai-check

## L0: 一句话描述
AI核查——验证AI输出质量与原始需求的一致性，确保交付物符合预期标准。

## L1: 使用场景
当AI执行完任务后需要验证输出质量时使用。通过"需求对照→输出审查→偏差检测→修正建议"四步，确保AI输出与原始需求一致。解决AI幻觉、需求漂移、执行偏差问题。

## L2: 详细文档

### 核心能力
基于维特根斯坦语言哲学（"语言即契约"），通过"契约对照→输出审查→偏差度量→修正闭环"四步，验证AI输出是否符合需求契约。

### AI核查光谱

```markdown
┌─────────────────────────────────────────────────────────────┐
│ AI输出质量光谱                                           │
├─────────────────────────────────────────────────────────────┤
│ L1: 完全合规（零偏差）                                  │
│     - 输出与需求100%一致                                │
│     - 无需修正，可直接交付                               │
│                                                             │
│ L2: 轻微偏差（可接受）                                  │
│     - 偏差<10%，不影响整体                             │
│     - 记录观察，无需修正                                │
│                                                             │
│ L3: 中度偏差（需修正）                                  │
│     - 偏差10-30%，影响部分功能                        │
│     - 需要修正后交付                                    │
│                                                             │
│ L4: 严重偏差（需重做）                                  │
│     - 偏差>30%，核心功能不符                          │
│     - 需求重新解构后执行                                │
│     - 建议调用 dbs-deconstruct                          │
│                                                             │
│ L5: 完全偏离（方向错误）                                │
│     - 输出与需求根本不符                                │
│     - 建议回滚到需求澄清阶段                            │
│     - 建议调用 dbs-austrian                            │
└─────────────────────────────────────────────────────────────┘
```

### 四步核查流程

```markdown
Step 1: 契约对照
  - 提取原始需求的契约条款（交付物、标准、约束）
  - 建立核查清单（checklist）
  - 标注关键指标

Step 2: 输出审查
  - 逐项对照输出与契约
  - 识别显性偏差（直接可观测）
  - 识别隐性偏差（需推理验证）

Step 3: 偏差度量
  - 计算偏差程度（数量/百分比/严重度）
  - 分类偏差类型（范围/质量/格式/遗漏）
  - 评估偏差影响（阻断/严重/轻微）

Step 4: 修正闭环
  - 高偏差→修正后复查
  - 中偏差→部分修正+记录
  - 低偏差→直接交付
```

### 核查维度矩阵

| 维度 | 检查内容 | 偏差指标 | 权重 |
|------|---------|---------|------|
| **范围** | 是否覆盖全部需求 | 遗漏率 | 25% |
| **质量** | 是否达到质量标准 | 缺陷率 | 25% |
| **格式** | 是否符合交付格式 | 格式偏差率 | 15% |
| **边界** | 是否遵守约束条件 | 违反数 | 20% |
| **时效** | 是否满足时间要求 | 延迟率 | 15% |

### 偏差类型分类

| 类型 | 符号 | 说明 | 修正策略 |
|------|------|------|---------|
| **范围偏差** | ⊘ | 遗漏或超出需求范围 | 补充或裁剪 |
| **质量偏差** | ⚠ | 输出质量不达标 | 重新生成 |
| **格式偏差** | ⚡ | 交付格式不符 | 格式转换 |
| **遗漏偏差** | ◌ | 关键部分未完成 | 补充完成 |
| **误解偏差** | ✗ | 理解错误方向错误 | 重新解构 |

### 天龙引擎协同

| 天龙岗位 | 协同方式 |
|---------|---------|
| **00分析师** | 偏差分析 → 需求澄清前置 |
| **03构建师** | 修正执行 → 输出修复 |
| **04验证师** | 质量验证 → 偏差复查 |
| **dbs-deconstruct** | L4严重偏差 → 重新解构 |
| **dbs-austrian** | L5完全偏离 → 追问澄清 |
| **dbs-diagnosis** | 偏差诊断 → 根因分析 |

### 使用命令

```bash
/dbs-ai-check               # 启动核查分析
/dbs-ai-check --quick      # 快速核查（仅范围检查）
/dbs-ai-check --deep      # 深度核查（含质量+偏差度量）
/dbs-ai-check --report    # 生成完整报告
```

### 自检清单

- [ ] 原始需求已明确提取
- [ ] 核查清单已逐项建立
- [ ] 每个偏差已量化度量
- [ ] 偏差类型已正确分类
- [ ] 修正建议已明确标注
- [ ] 质量评级已客观给出
- [ ] 核查报告已完整输出

### 禁忌

- ❌ 不建立核查清单直接审查（无标准审查）
- ❌ 不量化偏差程度（主观判断）
- ❌ 偏差分类错误（范围偏差当作质量偏差）
- ❌ L4偏差不重新解构（强行修正）
- ❌ L5偏差不追问澄清（继续执行错误方向）
- ❌ 轻微偏差过度修正（杀鸡用牛刀）
- ❌ 核查报告不输出（无记录追溯）
