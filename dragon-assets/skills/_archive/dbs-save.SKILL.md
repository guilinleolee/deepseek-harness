# dbs-save

## L0: 一句话描述
会话快照——提取当前会话关键信息，生成结构化存档。

## L1: 使用场景
当需要保存当前会话的决策、结论、待办事项时使用。生成可追溯、可复用的会话快照文档。

## L2: 详细文档

### 核心能力
基于结构化快照模板，从会话中提取关键决策、行动项、上下文，生成标准化的存档文档。

### 会话快照结构

```
┌─────────────────────────────────────────────────────────────┐
│ 📋 会话快照文档                                            │
├─────────────────────────────────────────────────────────────┤
│ 1. 会话概览                                               │
│    - 主题: [一句话描述]                                    │
│    - 时间: [YYYY-MM-DD HH:MM]                            │
│    - 时长: [X分钟]                                       │
│    - 决策数: [N个]                                       │
├─────────────────────────────────────────────────────────────┤
│ 2. 关键决策                                               │
│    - 决策1: [描述] + [理由]                              │
│    - 决策2: ...                                          │
├─────────────────────────────────────────────────────────────┤
│ 3. 行动项                                                 │
│    - [ ] 行动1 - 负责人 - 截止日期                        │
│    - [ ] 行动2 ...                                       │
├─────────────────────────────────────────────────────────────┤
│ 4. 关键洞察                                               │
│    - 发现1: [描述]                                       │
│    - 发现2: ...                                          │
├─────────────────────────────────────────────────────────────┤
│ 5. 未解决问题                                            │
│    - 问题1: [描述] - 阻塞因素                             │
│    - 问题2: ...                                          │
├─────────────────────────────────────────────────────────────┤
│ 6. 上下文延续                                             │
│    - 继续点: [下一步做什么]                               │
│    - 风险点: [需要注意什么]                               │
└─────────────────────────────────────────────────────────────┘
```

### 快照提取标准

| 要素 | 提取标准 | 示例 |
|------|---------|------|
| **决策** | 包含"决定/选择/结论"的语句 | "我们决定采用方案A" |
| **行动项** | 包含"要/会/应该"的未来行动 | "我会在周五前完成" |
| **洞察** | 非显而易见的新发现 | "发现B端用户更在意..." |
| **问题** | 待解决的疑问或障碍 | "还不清楚C如何实现" |

### 快照质量标准

```
快照质量 = 完整性 × 可追溯性 × 可执行性

完整性:
  - 决策都有理由支撑？
  - 行动项都有负责人？
  - 风险点都有标注？

可追溯性:
  - 能从快照还原决策过程？
  - 关键节点有记录？

可执行性:
  - 行动项具体可操作？
  - 截止日期明确？
```

```markdown

### 会话概览

### 关键决策

**[决策1]**
- 内容: [描述]
- 理由: [支持决策的论据]
- 依据: [信息来源/讨论过程]

**[决策2]**
...

### 行动项

- [ ] [行动1] | 负责人: [X] | 截止: [日期]
- [ ] [行动2] | ...

### 关键洞察

1. [洞察1] - 来源: [如何发现]
2. [洞察2] ...

### 未解决问题

| 问题 | 阻塞因素 | 可能的解决方案 |
|------|---------|---------------|
| [问题1] | [描述] | [方向] |
| [问题2] | ... | ... |

### 延续提示
- **继续点**: [下一步]
- **风险点**: [需要注意]
- **上下文延续**: [关键背景信息]
```

### 使用命令

```bash
/dbs-save                    # 生成当前会话快照
dbs-save --format markdown  # 输出为Markdown
dbs-save --save memory      # 保存到长期记忆
```

### 快照自检清单

- [ ] 决策都有明确理由吗？
- [ ] 行动项都有负责人吗？
- [ ] 关键洞察有来源吗？
- [ ] 未解决问题标注了阻塞因素吗？
- [ ] 延续提示足够清晰吗？

### 最佳实践

- 每50分钟会话生成一份快照
- 决策后立即记录
- 行动项使用具体动词
- 快照命名包含日期和主题
