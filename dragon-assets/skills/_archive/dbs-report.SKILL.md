# dbs-report

## L0: 一句话描述
结构化汇报——基于受众需求设计信息架构，提升汇报说服力。

## L1: 使用场景
当需要准备正式汇报（工作汇报、项目汇报、会议汇报）时使用。基于受众分析和信息优先级，设计最具说服力的汇报结构。

## L2: 详细文档

### 核心能力
基于汇报场景和受众需求，通过"受众分析→信息分层→结构设计→话术优化"四步，设计高效有说服力的汇报方案。

### 受众分析矩阵

```
┌─────────────────────────────────────────────────────────────┐
│ 受众四维分析                                               │
├─────────────────────────────────────────────────────────────┤
│ 身份: 谁在听？                                             │
│  - 决策层（CEO/总监）→ 关注结果和价值                     │
│  - 执行层（经理/主管）→ 关注方法和资源                     │
│  - 专业层（专家/同事）→ 关注数据和细节                    │
│                                                             │
│ 态度: 他们的立场？                                          │
│  - 支持者 → 强化信心，提供行动方案                          │
│  - 中立者 → 提供证据，解答疑虑                            │
│  - 反对者 → 预判异议，准备回应                            │
│                                                             │
│ 需求: 他们关心什么？                                        │
│  - 业务目标 → 收入/增长/效率                               │
│  - 成本控制 → 投入产出/风险                                │
│  - 个人利益 → 功劳/晋升/学习                               │
│                                                             │
│ 限制: 他们有什么约束？                                      │
│  - 时间限制 → 汇报要短                                     │
│  - 信息过载 → 结论先行                                      │
│  - 注意力分散 → 抓注意力技巧                               │
└─────────────────────────────────────────────────────────────┘
```

### 信息分层金字塔

```
                    ┌─────────┐
                    │ 结论    │  ← 一句话核心结论（最重要）
                   ┌┴─────────┴┐
                  ┌┤ 关键论点  ┤┌ ← 3个支撑论点（其次）
                 ┌┴┴─────────┴┴┐
                ┌┤   证据层    ┤┌ ← 数据/案例/引用（最后）
               ┌┴┴───────────┴┴┐
              ┌┤     背景层     ┤┌ ← 背景/问题（按需）
             ┌┴┴───────────────┴┴┐
            ┌┤       附录层       ┤┌ ← 详细数据/参考（备用）
            └┴─────────────────┴┘
```

### 汇报结构模板库

| 场景 | 结构 | 适用情况 |
|------|------|---------|
| **项目汇报** | 背景→目标→进展→问题→方案→资源 | 需要审批或支持 |
| **结果汇报** | 结论先行→关键成果→数据支撑→下一步 | 汇报时间有限 |
| **问题汇报** | 问题描述→影响分析→原因诊断→解决建议 | 需要决策支持 |
| **进展汇报** | 里程碑→完成情况→风险预警→下周计划 | 周期性同步 |
| **复盘汇报** | 结果回顾→成功因素→失败因素→经验沉淀→行动计划 | 项目结束后 |

### 话术优化

```
结论先行话术:
  - "结论是...，理由是..."
  - "我建议...，原因有三点..."
  - "核心问题是...，解决方案是..."

数据呈现话术:
  - "从数据看...，这意味着..."
  - "对比上次...，提升了X%"
  - "关键指标达到...，超过预期"

异议预判话术:
  - "可能有人会问...，我的回答是..."
  - "关于成本问题，我们已经..."
  - "我也考虑到了...的风险，所以..."

行动闭环话术:
  - "接下来我需要...，预计..."
  - "请各位确认...，我们就..."
  - "谢谢大家，我会..."
```

### 输出格式

```markdown

### 受众分析
- **身份**: [描述]
- **态度**: [支持/中立/反对]
- **核心需求**: [他们关心什么]
- **约束条件**: [时间/注意力/信息偏好]

### 信息分层
**核心结论**: [一句话]
**支撑论点1**: [论点] - 证据: [数据/案例]
**支撑论点2**: [论点] - 证据: [数据/案例]
**支撑论点3**: [论点] - 证据: [数据/案例]

### 结构设计
- 选用模板: [模板名称]
- 时间分配: [X分钟]
- 节奏设计: [关键节点]

### 话术准备
- 开场: [准备的开场白]
- 转折: [准备的话术]
- 异议回应: [预判的问题及回应]

### 辅助材料
- PPT页数: [N页]

```

### 天龙引擎协同

| 天龙岗位 | 协同方式 |
|---------|---------|
| **28-01文案策划** | 汇报结构 → 正式文案 |
| **00分析师** | 受众分析 → 需求理解 |
| **07记录师** | 汇报归档 → 模板沉淀 |

### 使用命令

```bash
/dbs-report                    # 启动汇报设计
dbs-report "向领导汇报XX"     # 直接设计汇报
```

### 汇报自检清单

- [ ] 结论先行，3秒内听到核心？
- [ ] 每个论点都有数据支撑？
- [ ] 预判了受众可能的异议？
- [ ] 有明确的行动呼吁？
- [ ] 时间控制在要求范围内？

### 禁忌

- ❌ 没有结论的汇报（让受众猜）
- ❌ 数据堆砌没有结论（信息过载）
- ❌ 不了解受众（对牛弹琴）
- ❌ 时间失控（超时被打断）
