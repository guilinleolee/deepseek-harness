# Benchmark 设计指南

## 概述

本指南用于设计高质量的 LLM Benchmark 评估数据集，确保评估结果具有可靠性和可重复性。

## 数据集设计原则

### 1. 题目质量

```
✅ 正确性：答案必须经过验证
✅ 清晰性：问题表述无歧义
✅ 适当难度：覆盖简单到困难的范围
✅ 领域覆盖：涵盖目标评估领域
❌ 避免：模糊表述、多重解释、偏见内容
```

### 2. 题目格式

#### 选择题格式
```json
{
  "id": "unique-id",
  "question": "问题描述",
  "choices": ["选项A", "选项B", "选项C", "选项D"],
  "answer": "正确答案",  // 与choices中某一项匹配
  "category": "领域",
  "difficulty": "easy|medium|hard",
  "metadata": {
    "source": "来源",
    "explanation": "答案解析（可选）",
    "tags": ["标签1", "标签2"]
  }
}
```

#### 开放式格式
```json
{
  "id": "unique-id",
  "question": "开放性问题",
  "answer": "参考答案或评分标准",
  "rubric": {
    "full_score": "满分标准",
    "partial_score": "部分得分标准",
    "zero_score": "零分标准"
  },
  "category": "领域",
  "difficulty": "easy|medium|hard"
}
```

### 3. 难度分级

| 难度 | 描述 | 适用场景 |
|------|------|---------|
| easy | 单步推理、基本事实 | 基础能力筛选 |
| medium | 多步推理、部分理解 | 标准评估 |
| hard | 复杂推理、深度理解 | 高级能力评估 |

### 4. 类别分布

```
推荐类别分布：

基础评估：
├── factual (25%)      # 事实问答
├── comprehension (25%) # 理解能力
├── reasoning (25%)    # 推理能力
└── application (25%)  # 应用能力

高级评估：
├── analysis (20%)     # 分析能力
├── synthesis (20%)    # 综合能力
├── evaluation (20%)   # 评估能力
└── creation (20%)    # 创造能力
```

## 最佳实践

### 1. 数据集构建

```
步骤1: 定义评估目标
         ↓
步骤2: 收集原始题目
         ↓
步骤3: 专家审核答案
         ↓
步骤4: 标注难度和类别
         ↓
步骤5: 平衡分布检查
         ↓
步骤6: 小规模预测试
         ↓

```

### 2. 评估执行

```
✅ 固定随机种子确保可重复性
✅ 使用相同prompt格式
✅ 控制temperature参数

✅ 保存原始响应用于分析
```

## 常见陷阱

| 陷阱 | 问题 | 解决方案 |
|------|------|---------|
| 题目泄露 | 测试集被训练数据包含 | 使用私有验证集 |
| 样本偏差 | 题目分布不均 | 分层采样 |
| 评估者偏差 | 评分标准不一致 | 使用自动评估或多人评分 |
| 过拟合 | 过度优化单一指标 | 多指标综合评估 |
| 选择偏差 | 选择题有猜测机会 | 使用F1或其他校正指标 |
