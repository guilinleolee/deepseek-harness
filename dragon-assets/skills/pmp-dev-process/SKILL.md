# PMP式迭代开发流程

本技能定义了一套类似于项目管理专业（PMP）框架的结构化流程，确保每个开发周期都清晰、高效且有据可查。

## 触发条件

- 用户说"新功能开发"、"重大变更"、"PMP流程"
- 开启新功能或进行重大变更
- 需要严谨的文档记录
- 项目章程无特殊规定时的默认工作流

## 流程步骤

### 步骤1: 修订章程 (Revise Charter)

在开启任何一项新功能或重大变更前：

1. 首先共同修订项目级别的文档 (`GEMINI.md` / `AGENTS.md` / `CLAUDE.md`)
2. 确保目标和范围在章程中清晰定义
3. 输出更新后的章程内容，等待用户确认

### 步骤2: 规划与确认 (Plan & Confirm)

基于更新后的文档：

1. 助手提出具体的执行计划
2. 计划包含：目标、里程碑、任务拆分、时间预估
3. 获得用户对计划的明确确认
4. **绝不能**在未确认前提前开发

### 步骤3: 执行 (Execute)

根据确认的计划进行操作：

1. 按计划顺序执行任务
2. 每完成一个阶段停下来等待用户确认
3. 记录执行过程中的发现和问题

### 步骤4: 验证 (Verify)

通过代码审查和功能测试进行验证：

1. 执行单元测试
2. 执行集成测试
3. 代码审查
4. 功能验证

### 步骤5: 持续更新 (Collect & Update)

在整个流程中：

1. 随时将新想法更新到章程
2. 将待办事项更新到对应文档
3. 记录经验教训

## 天龙引擎集成

### 与02架构师协同

此技能为天龙引擎02架构师提供结构化规划框架：
- **章程驱动**: 先文档后行动
- **阶段确认**: 每步都有用户确认
- **可追溯**: 完整的决策记录

### 与Plan Mode协同

与天龙引擎Plan Mode互补：
- **Plan Mode**: 复杂任务，完整规划
- **pmp-dev-process**: 功能开发，迭代流程

### 使用示例

```bash
# 触发技能
"使用PMP流程开发这个新功能"

# 查看当前阶段
"显示当前开发阶段"

# 确认进入下一阶段
"确认继续下一步"
```

## 核心原则

无论什么项目，项目级别的 `CLAUDE.md` 或 `AGENTS.md` 都是协作的核心。如果它定义了特定工作流，优先遵循其中的规范；否则以本流程为指导。
