# prove-it-skill

## L0: 一句话描述 (≤15字)
测试先行验证Bug，复现修复闭环。

## L1: 使用场景 (50-100字)
当Bug报告不明确、修复方案不确定、或需要防止修复引入新问题时，使用Prove-It模式。先写测试证明Bug存在，再实现修复，最后验证测试通过。核心价值在于将修复过程变成可验证的闭环。

## L2: 详细文档

# Prove-It 修复模式 (修复即测试)

> **核心理念**: "Don't fix what you can't prove broken."
> 每个修复必须始于一个失败的测试，结束于一个通过的测试。

## 核心循环

```
┌─────────────────────────────────────────────────────────────┐
│                 Prove-It Loop (证明-修复循环)                  │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   STEP 1: 写测试证明Bug存在 (PROVE)                         │
│   ├── 写一个会失败的测试（描述Bug行为）                      │
│   ├── 运行测试确认失败                                      │
│   └── 记录失败输出作为基准                                  │
│                                                             │
│   STEP 2: 确认测试失败 (VERIFY)                             │
│   ├── 测试确实失败了吗？                                    │
│   ├── 失败原因是否与报告的Bug 一致？                        │
│   └── 如果不一致，需要更多测试或重新理解Bug                  │
│                                                             │
│   STEP 3: 实现修复 (FIX)                                    │
│   ├── 只修复能通过测试的代码                                │
│   ├── 不添加未测试的新功能                                  │
│   └── 保持最小改动原则                                      │
│                                                             │
│   STEP 4: 验证测试通过 (CONFIRM)                            │
│   ├── 运行测试确认全部通过                                  │
│   ├── 检查没有引入新问题                                    │
│   └── 记录修复证据                                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 与TDD的对比

| 维度 | TDD RED-GREEN-REFACTOR | Prove-It |
|------|-------------------------|----------|
| **触发点** | 新功能开发 | Bug修复 |
| **首次测试** | 描述期望行为（应失败） | 描述Bug行为（应失败） |
| **修复方向** | 向前（实现功能） | 向后（消除缺陷） |
| **测试数量** | 功能测试 | Bug复现测试 |
| **目的** | 确保功能正确 | 确保Bug已消除 |

## Prove-It 执行流程

### Phase 1: 理解Bug (Understand)
```markdown
## Bug理解模板
- Bug描述: [原始报告]
- 期望行为: [用户期望]
- 实际行为: [当前错误行为]
- 复现步骤: [如何触发Bug]
- 影响范围: [哪些模块/功能受影响]
```

### Phase 2: 写测试 (Prove)
```markdown
## 测试编写规范
1. 测试命名: `test_bug_<id>_<short_description>`
2. 测试内容: 精确复现Bug的触发条件
3. 断言: 描述期望的"正确"行为
4. 注释: 引用Bug报告链接

// 示例: Bug #1234 - 登录时密码验证返回错误信息
test('bug_1234_login_invalid_password_returns_user_friendly_error', async () => {
  const response = await login('user@example.com', 'wrong_password');
  // Bug: 当前返回 "Internal Server Error"
  // 期望: 返回 "Invalid email or password"
  expect(response.error).toBe('Invalid email or password');
});
```

### Phase 3: 验证失败 (Verify Failure)
```markdown
## 失败验证检查清单
- [ ] 测试运行失败了吗？
- [ ] 失败消息是否指向预期的问题？
- [ ] 失败是否与Bug报告一致？
- [ ] 没有意外的失败吗？

失败类型分析:
- ✅ 预期失败: 测试通过则Bug仍存在
- ❌ 非预期失败: 测试本身有问题
- ⚠️ 无失败: Bug可能已修复或无法复现
```

### Phase 4: 实现修复 (Fix)
```markdown
## 修复执行规范
1. 只改能通过当前测试的代码
2. 不重构、不添加功能
3. 保持最小改动
4. 记录修复前后的差异

修复检查:
- [ ] 修改范围最小化
- [ ] 没有修改测试文件
- [ ] 没有添加未测试的新代码
- [ ] 代码风格一致
```

### Phase 5: 确认通过 (Confirm)
```markdown
## 通过确认检查清单
- [ ] 所有Prove-It测试通过了吗？
- [ ] 相关回归测试仍然通过吗？
- [ ] 没有引入新的lint错误吗？
- [ ] 代码覆盖率没有下降吗？

通过的含义:
- Bug已消除（测试通过）
- 没有引入新Bug（回归通过）
- 修复有效且安全
```

## Prove-It 反模式

| 反模式 | 描述 | 正确做法 |
|--------|------|---------|
| **跳过测试** | "修复很简单，不需要写测试" | 必须写测试证明修复 |
| **修改测试** | "测试写错了，修改一下" | 测试描述正确行为 |
| **过度修复** | "既然改了，顺便加上新功能" | 只修复问题区域 |
| **测试通过但未确认** | "测试通过了，应该好了" | 必须运行完整测试套件 |
| **没有复现就修复** | "根据报告直接改代码" | 必须先复现Bug |

## 触发条件

自动触发 Prove-It 模式的情况：
- Bug报告描述不清时
- 修复方案不确定时
- 同一Bug反复出现时
- 高风险修复（影响核心模块）
- 修复后需要回归测试时

## 常用命令

```bash
# 启动Prove-It模式
/prove-it <bug-id> "<bug-description>"

# 复现Bug
/prove-it reproduce <bug-id>

# 验证修复
/prove-it confirm <bug-id>

# 查看Prove-It状态
/prove-it status
```

## 示例工作流

```
[@验证师] 报告: Bug#2024 用户无法上传超过10MB的文件

→ [@03构建师] 启动Prove-It:
  STEP 1: 写测试 test_bug_upload_10mb_succeeds
  运行测试 → 失败 ✓ (文件过大被拒绝)

  STEP 2: 审查失败
  失败消息: "File size exceeds limit"
  与Bug报告一致 ✓

  STEP 3: 实现修复
  修改上传配置: maxFileSize: 10MB → 50MB
  只改配置文件 ✓

  STEP 4: 确认通过
  test_bug_upload_10mb_succeeds → 通过 ✓
  相关测试全部通过 ✓

→ Bug#2024 修复完成 ✓
```
