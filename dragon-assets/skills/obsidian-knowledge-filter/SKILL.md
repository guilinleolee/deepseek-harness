# 技能: Obsidian 知识筛选器 (Obsidian Knowledge Filter)

## 描述

此技能旨在从由大量 Markdown 文件组成的知识库（例如 Obsidian Vault）中，通过一个精确且分阶段的工作流，进行知识的检索、筛选和提取。它采用带编号前缀的 YAML 和 Markdown 文件来管理每一步的中间数据，并在每个关键步骤暂停以供用户审阅，确保最终产出的内容高度相关且无重复。

**核心理念**: 此技能的目标是在用户的指导下，通过一系列独立的脚本和分析步骤，精确地从知识库中提炼与特定主题相关的信息，并通过结构化的方式呈现，最终形成综合分析报告。

## 何时使用

当用户请求您通过查找、关联和综合分散在个人知识库中的信息来解决复杂问题时，请使用此技能。此工作流特别适用于需要高精度、希望减少冗余信息并全程参与筛选过程的场景。

**触发条件**:
- 用户请求从知识库中检索特定主题
- 需要综合分散在多个文件中的知识
- 周期性知识复盘和整理

## 工作流程

该过程分为四个主要阶段，每个阶段都以用户审阅为节点。

### 阶段 1: 关键词搜索与分析

#### 步骤 1.1: 运行分析

使用 Grep 工具递归搜索所有 `.md` 文件:
- **文件排除**: 自动跳过任何路径中包含 `tmp-`, `_attachments`, 或 `.trash` 的文件/目录。
- **关键词分析**: 查找包含指定关键词的文件，记录每个关键词的出现频率。
- **上下文合并**: 将包含关键词的行的上下文（默认为前后 10 行）合并成连续的行号区间。

**输出**: 在一个新建的 `tmp-YYYY-MM-DD-HH-MM-SS-analysis/` 临时目录中，生成 `001_analysis.yaml`。

```yaml
# 001_analysis.yaml 格式
- file_path: '文件夹/2025-12-29-示例文件.md'
  keyword_counts:
    - word: '关键词1'
      count: 5
    - word: '关键词2'
      count: 2
  line_ranges:
    - [10, 30]   # 第一个内容提取区间
    - [45, 65]   # 第二个内容提取区间
```

#### 步骤 1.2: 用户审阅分析文件

暂停并请求用户审阅 `001_analysis.yaml`，用户可手动编辑此文件以增删文件或修改行号区间。

### 阶段 2: 内容提取与清理

#### 步骤 2.1: 提取内容

读取 `001_analysis.yaml`，并根据其中的 `file_path` 和 `line_ranges` 提取相应的内容。

**内容清理**:
1. 合并换行: 将连续的多个换行符合并为一个
2. 移除加粗: 删除所有的 Markdown 加粗标记 (`**`)
3. 移除图片: 删除所有的 Markdown 图片链接 (`![[...]]`)

**输出**: 生成 `002_content.yaml`，每个对象增加 `content` 字段。

#### 步骤 2.2: 用户审阅内容文件

暂停，请求用户审阅 `002_content.yaml`，确保提取和清理后的内容符合预期。

### 阶段 3: 内容洞察综合

#### 步骤 3.1: 分块综合分析

采用分块「读取-分析-写出」循环模式：
1. **分块读取**: 以 1000 行为单位逐块读取
2. **综合分析**: 提炼与任务相关的洞察、观点和联系
3. **单次写入**: 追加写入到 `003_content_analysis.md`
4. **循环执行**: 直到处理完所有内容块

**输出**: `003_content_analysis.md`

#### 步骤 3.2: 用户审阅洞察文件

暂停并请求用户审阅 `003_content_analysis.md`。

### 阶段 4: 最终报告合成

#### 步骤 4.1: 生成最终报告

以 `003_content_analysis.md` 为素材，撰写逻辑连贯、结构清晰的最终报告。

**输出**: `004_report.md`
