# Structure Suggester

> 内容结构优化建议模块 - 基于多种框架提供结构重组建议

## 模块定位

本模块为演示文稿提供内容结构分析和优化建议，帮助构建更具说服力的演讲结构。

## 核心框架

### 1. 金字塔原理 (Pyramid Principle)

**适用场景**: 商业汇报、方案建议、问题分析

**核心原则**:
1. 结论先行 - 先说结论，再说支撑
2. 分组归纳 - 相关信息归为一组
3. 逻辑递进 - 组与组之间有逻辑关系

**结构模板**:

```
├── 核心结论 (1个)
│   ├── 支撑点1
│   │   ├── 论据1.1
│   │   └── 论据1.2
│   ├── 支撑点2
│   │   └── 论据2.1
│   └── 支撑点3
│       └── 论据3.1
└── 行动建议 (可选)
```

**使用场景**:
- 管理层汇报
- 方案建议
- 问题分析报告

### 2. 叙事结构 (Narrative Structure)

**适用场景**: 故事讲解、品牌宣传、案例分享

**核心要素**:
1. 背景设定 - 时间/地点/人物
2. 冲突呈现 - 问题/挑战/困境
3. 高潮发展 - 转折/突破/创新
4. 结局呈现 - 成果/价值/启示

**结构模板**:

```
├── 开场 Hook
│   └── 吸引注意力的开场
├── 背景 Context
│   └── 设定场景，引出问题
├── 冲突 Challenge
│   ├── 问题呈现
│   └── 痛点分析
├── 解决 Solution
│   ├── 方案介绍
│   └── 实施过程
├── 成果 Results
│   ├── 数据支撑
│   └── 价值呈现
└── 收尾 Close
    └── 总结/号召
```

**使用场景**:
- 创业故事
- 客户案例
- 品牌宣讲

### 3. 流程式结构 (Process Structure)

**适用场景**: 操作培训、方法论讲解、流程说明

**核心要素**:
1. 步骤分解 - 分阶段说明
2. 关键节点 - 标注重要环节
3. 注意事项 - 提醒常见问题
4. 结果验证 - 确认达成目标

**结构模板**:

```
├── 概述 Introduction
│   └── 流程目标与价值
├── 步骤1 Step 1
│   ├── 操作说明
│   └── 要点提示
├── 步骤2 Step 2
│   └── ...
├── 步骤N Step N
│   └── ...
├── 常见问题 FAQ
│   └── 避坑指南
└── 检查清单 Checklist
    └── 验收标准
```

**使用场景**:
- 培训课程
- 操作手册
- 方法论分享

### 4. 对比式结构 (Comparison Structure)

**适用场景**: 方案对比、产品选型、优劣势分析

**核心要素**:
1. 对比维度 - 明确比较维度
2. 选项呈现 - 客观展示各选项
3. 差异分析 - 突出关键差异
4. 建议结论 - 基于分析给出建议

**结构模板**:

```
├── 背景 Background
│   └── 为什么要对比
├── 维度 Criteria
│   ├── 维度1: [权重]
│   ├── 维度2: [权重]
│   └── 维度3: [权重]
├── 选项A Option A
│   ├── 维度1表现
│   ├── 维度2表现
│   └── 维度3表现
├── 选项B Option B
│   └── ...
├── 分析 Analysis
│   ├── 综合评分
│   └── 差异总结
└── 建议 Recommendation
    └── 基于分析的推荐
```

**使用场景**:
- 竞品分析
- 方案选型
- 供应商评估

### 5. 问题解决结构 (Problem-Solution Structure)

**适用场景**: 问题汇报、解决方案、咨询提案

**核心要素**:
1. 问题定义 - 明确问题边界
2. 原因分析 - 深入分析根因
3. 方案设计 - 提出解决方案
4. 价值呈现 - 说明预期收益

**结构模板**:

```
├── 问题概述 Problem
│   ├── 问题描述
│   └── 影响范围
├── 根因分析 Root Cause
│   ├── 表层原因
│   └── 深层原因
├── 解决方案 Solution
│   ├── 方案概述
│   ├── 实施路径
│   └── 资源需求
├── 预期收益 Benefits
│   ├── 量化收益
│   └── 质量收益
└── 行动计划 Next Steps
    └── 下一步建议
```

**使用场景**:
- 问题汇报
- 咨询提案
- 改革方案

## 结构评估

### 评估维度

| 维度 | 权重 | 评估标准 |
|------|------|----------|
| 逻辑性 | 30% | 前后逻辑是否连贯 |
| 完整性 | 25% | 是否覆盖所有要点 |
| 重点突出 | 25% | 核心信息是否突出 |
| 受众适配 | 20% | 是否适合目标受众 |

### 评估标准

| 分数 | 等级 | 说明 |
|------|------|------|
| 90-100 | 优秀 | 结构完美，可直接使用 |
| 80-89 | 良好 | 结构合理，可微调使用 |
| 70-79 | 可用 | 结构基本合理，需优化 |
| 60-69 | 待优化 | 结构有明显问题 |
| <60 | 需重构 | 建议重新设计结构 |

## 结构优化规则

### 应该做

✅ **结论先行** - 重要信息放在前面
✅ **分组清晰** - 相关内容归为一组
✅ **逻辑递进** - 组与组之间有逻辑关系
✅ **重点突出** - 核心信息要有视觉强调
✅ **过渡自然** - 页面之间要有逻辑衔接

### 不应该做

❌ **信息堆砌** - 一页放太多内容
❌ **逻辑混乱** - 各部分之间无关联
❌ **重点分散** - 没有突出核心信息
❌ **结构扁平** - 所有内容平铺直叙
❌ **缺少过渡** - 页面之间跳跃

## 结构重组示例

### 示例: 月度汇报

**原始结构**:
```
1. 上月工作回顾
2. 数据分析
3. 竞品动态
4. 下月工作计划
```

**问题分析**:
- 数据分析与工作回顾分离
- 竞品动态与工作内容关联不强
- 逻辑顺序不清晰

**优化后结构**:
```
1. 核心成果（结论先行）
   - KPI完成情况
   - 亮点工作
2. 支撑数据
   - 详细数据分析
   - 趋势变化
3. 外部环境
   - 竞品动态
   - 市场变化
4. 下月计划
   - 目标
   - 关键行动
5. 需要支持
   - 资源需求
   - 决策事项
```

### 示例: 产品发布会

**原始结构**:
```
1. 公司介绍
2. 产品功能
3. 技术架构
4. 定价策略
5. 联系方式
```

**问题分析**:
- 公司介绍占篇幅过长
- 功能介绍缺乏重点
- 缺少情感连接

**优化后结构**:
```
1. Hook (开场)
   - 用户痛点场景
   - 引发共鸣
2. 解决方案 (核心)
   - 产品定位
   - 核心功能
   - 差异化优势
3. 价值呈现
   - 用户收益
   - 使用场景
4. 信任背书
   - 技术实力
   - 客户案例
5. 行动号召
   - 定价
   - 联系方式
   - 限时优惠
```

async def structure_analysis(content):
    # 1. 分析内容特征
    content_features = analyze_content_features(content)

    # 2. 推荐最佳框架
    framework = recommend_framework(
        content_type=content_features.type,
