# 需求提炼 (Demand Refiner)

> **自媒体工作台 · 需求层核心** | 把用户声音变成内容选题弹药

## 用途

把 TikHub 采集（或手动收集）的用户评论/笔记，提炼成可指导内容生产的《需求库》：
- 用户真实痛点（高频 → 低频）
- 用户高频问题
- 目标用户画像
- 内容选题建议

## 输入

- **原始数据**：采集到的用户评论/笔记（JSON/CSV/纯文本）
  - 来自 TikHub `social-listening` / `comments-analysis` 采集结果
  - 或手动整理的用户评论/社群聊天记录/问答

## 工作流（5 步）

### Step 1 · 准备数据
把原始采集数据整理为统一格式（每条一条记录）：
```json
[
  {"text": "用户评论原文", "source": "小红书/AI训练师笔记", "platform": "xiaohongshu"},
  {"text": "……", "source": "……", "platform": "……"}
]
```
> 若数据量大（>50 条），先用 `scripts/prepare.py` 做清洗去重和词频统计，
> 再进入 LLM 分析；数据少（<50 条）可直接人工阅读分析。

### Step 2 · 文本清洗
- 去除广告、水军、与主题无关的灌水评论
- 去除表情符号、@提及、纯链接、无意义短句
- 统一错别字/同义表达（如"ai训练师"和"AI训练师"）

### Step 3 · LLM 痛点聚类（核心）
对清洗后的每一条用户声音，判断它表达的**需求类型**：

| 类型 | 说明 | 示例 |
|---|---|---|
| 🩹 **痛点** | 正在遇到的困难/不满 | "训练 AI 客服老是不理解用户意图" |
| ❓ **问题** | 想了解怎么做 | "AI训练师证书到底有没有用？" |
| 💰 **购买意向** | 想买/在比较 | "这种陪跑服务一般多少钱？" |
| 😊 **正反馈** | 用了效果不错 | "照这个方法调 prompt 效果好多了" |
| 🧐 **观望** | 有兴趣但犹豫 | "怕被割韭菜，先看看" |

按语义归类后，统计每个痛点的出现频次，提炼**Top 痛点**。

### Step 4 · 生成需求库（输出）

输出格式为结构化 Markdown，保存到用户指定路径（默认 `~/viral-content-reports/demand-library/{关键词}.md`）：

```markdown
# 需求库 · {关键词}

> 提炼时间：{date}
> 数据来源：{平台/采集方式} | 有效样本：{n} 条

## 🎯 Top 痛点（按频次排序）
| 痛点 | 频次 | 证据（原话摘录） | 情绪 |
|---|---|---|---|
| 痛点1 | 23 | "原话……" | 焦虑 |
| 痛点2 | 15 | "原话……" | 迷茫 |

## ❓ 用户高频问题
1. 问题1（提到 X 次）
2. 问题2（提到 Y 次）

## 👤 用户画像
- 典型人群：{描述}
- 常用平台：{平台}
- 关注点：{关键词}

## 💡 内容选题建议（基于痛点）
| 选题 | 对应痛点 | 建议平台 | 内容形式 |
|---|---|---|---|
| 选题1 | 痛点1 | 小红书 | 图文 |
| 选题2 | 痛点2 | 抖音 | 短视频 |

## 📎 原始样本（Top 20，供复核）
- {原话} — {来源}
```

### Step 5 · 反馈到内容生产
- 把《需求库》存入知识库/输出目录，供后续内容生产（天龙 /viral）调用
- 建议每次采集后提炼一次，形成**持续更新的需求库**

## 脚本：prepare.py（可选，数据量大时用）

```bash
# 清洗去重 + 词频统计
python scripts/prepare.py --input raw.json --output clean.json
```

- 输入：原始评论 JSON 数组 `[{"text": "...", "source": "..."}]`
- 输出：`clean.json`（清洗后）+ 控制台打印 Top 30 高频词
- 不依赖第三方库（仅 Python 标准库）

## 质量门（交付前自查）

1. 每条痛点都有**原话证据**（可复核，不编造）
2. 痛点按**频次**排序，不是按 LLM 偏好
3. 区分「痛点」和「问题」（痛点=已遇到困难，问题=想知道怎么做）
4. 情绪标注准确（焦虑/迷茫/急切/满意/中立）
5. 选题建议必须**对应具体痛点**，不能泛泛而谈
