# Futures DeepView Analysis Playbook

> 本文件是 `pandadata-deepview` 技能的核心操作手册。当请求需要多主题分析、跨模块对比，或需生成正式 Markdown/HTML 报告时，必须加载此文件。

---

## 📋 请求分诊（Request Triage）

在调用任何数据之前，先分类用户的请求：

| 用户意图 | 最少模块 | 可扩展模块 |
|---|---|---|
| "席位怎么看""主力是否看多" | 行情、主力合约、席位持仓 | 盈亏排行、建仓过程、资金流、多空比 |
| "基差/期限结构" | 行情、基差、期限结构 | 跨期套利、主力相关性、库存 |
| "仓单/库存压力" | 行情、仓单、库存 | 虚实盘比、现货报价、现货利润 |
| "跨期套利机会" | 期限结构、跨期套利、自由价差/价比 | 成交持仓、主力合约、库存变化 |
| "全品种扫描" | 排行或池子类接口 | 对排名靠前品种做二级验证 |

### 日期窗口默认值

- 如果用户未指定日期，使用首次成功调用返回的最近可用 `trade_date`
- 如果用户未指定回看窗口：
  - 近端行为分析：**20 个交易日**
  - 分位上下文：**120 个交易日**

## 🔄 数据调用模式（Data Calling Pattern）

### 标准四步流程

```
Step 1: 使用 pandadata-api 查阅每个计划调用方法的完整文档
   ↓
Step 2: 小样本试调：单品种 + 单日 或 短日期范围
   ↓
Step 3: 记录验证笔记：列名、日期覆盖范围
   ↓
Step 4: 仅在确认单位与字段含义后，计算比率或衍生指标
```

### 验证笔记必须包含

```yaml
method: Pandadata 方法名（精确）
params: 关键过滤条件，尤其是 variety/symbol/date
rows: 过滤后行数
latest_date: 返回数据的最大 trade_date
empty_reason: 如果为空，记录执行的下一个检查
```

## 📊 信号配方（Signal Recipes）

### 1️⃣ 席位博弈（Broker Position Game）

**使用接口**：
- `get_broker_netmarg` - 席位净保证金
- `get_broker_netmarg_change` - 席位净保证金变化
- `get_broker_totlmarg` - 席位总保证金
- `get_broker_build_process` - 建仓过程
- `get_future_netposi_rank` - 净持仓排行

**计算指标**：

| 指标 | 计算方法 |
|------|---------|
| 净方向 | 多头保证金 - 空头保证金，或文档中的净字段 |
| 强度 | 净变化 / 总持仓保证金（或近期均值，当存在兼容的分母时） |
| 确认信号 | 价格变化、开仓量变化、净持仓变化同向移动 |
| 背离信号 | 价格上升但净多仓减弱，或价格下跌但净多仓增强 |
| 集中度 | 前列席位的净暴露占比 |

**用词规范**：
- ✅ "净多增加" → 事实
- ⚠️ "多头更主动" → 推断（需谨慎）
- ❌ "必然上涨" → 禁止使用

---

### 2️⃣ 席位盈亏与资金流（Broker Profit And Flow）

**使用接口**：
- `get_broker_profit` - 席位盈亏
- `get_broker_variety_profit` - 品种盈亏
- `get_broker_profit_rank` - 盈亏排行
- `get_broker_loss_rank` - 亏损排行
- `get_broker_flow_daily` - 席位日资金流

**观察要点**：

| 信号 | 含义 |
|------|------|
| 盈利席位在加仓还是减仓？ | 盈利方信心指标 |
| 亏损席位是否被迫砍仓？ | 强制止损压力 |
| 大额日资金流与净持仓方向是否一致？ | 资金确认信号 |
| 是单一席位主导还是群体行为？ | 信号广泛性 |

---

### 3️⃣ 基差与期限结构（Basis And Term Structure）

**使用接口**：
- `get_future_basis` - 基差
- `get_future_term_structure` - 期限结构
- `get_future_calendar_arbitrage` - 日历套利
- `get_future_free_spread` - 自由价差
- `get_future_free_ratio` - 自由价比

**计算指标**：

| 指标 | 说明 |
|------|------|
| 基差及基差率 | 使用文档中的字段计算 |
| 基差分位 | 相对于回看窗口的历史分位 |
| 曲线形态 | Contango / Backwardation / 局部反转 / 扁平化或陡峭化 |
| 日历价差变化 | 必须与期限结构快照使用同一 trade_date |

⚠️ **禁止**：比较不同 trade_date 的合约，必须明确标注为异步对比

---

### 4️⃣ 仓单库存与现货（Inventory, Warehouse Receipts, And Cash Market）

**使用接口**：
- `get_future_warehouse_receipt` - 仓单
- `get_future_inventory` - 库存
- `get_future_virtual_ratio` - 虚实盘比
- `get_future_trader_quote` - 贸易商报价
- `get_future_spot_profit` - 现货利润

**分析要点**：

| 指标 | 分析维度 |
|------|---------|
| 仓单与库存方向 | 日环比、周环比、年同比（视历史数据深度） |
| 虚实盘压力 | 必须使用文档中的精确分母解释高或上升的虚实盘比 |
| 现货利润 | 生产利润扩张或收缩，是否支持供给增长或减产 |
| 现货报价一致性 | 贸易商报价是否支持期货升贴水叙事 |

---

### 5️⃣ 全品种扫描（Full-Market Scan）

**执行顺序**（禁止一开始就拉全部明细）：

```
1. 使用排行/池子接口粗筛
   ├── get_future_contract_rank     # 合约排行
   ├── get_future_contract_pool     # 合约池
   ├── get_future_net_flow        # 净流向
   ├── get_future_netcap_change   # 净持仓变化
   └── get_future_calendar_arbitrage  # 日历套利

2. 明确声明过滤条件
   ├── 流动性阈值
   ├── 排行门槛
   ├── 变化幅度门槛
   └── 同一日期可用性

3. 选取 Top 5-10 候选品种

4. 仅对这些候选品种执行明细验证

5. 返回表格：候选品种、信号、使用的方法、最新日期、待验证项
```

## 📄 报告骨架（Report Skeleton）

### 完整报告（9段标准结构）

```markdown
## 1. 摘要结论
   - 3-5 bullets，含方向、置信度、最大矛盾点

## 2. 数据范围
   - 品种/合约、日期窗口、最新数据日、调用的方法列表

## 3. 行情与合约背景
   - 价格趋势、主力合约、流动性/持仓量上下文

## 4. 席位博弈
   - 净持仓、建仓过程、席位盈亏、资金流

## 5. 基差与期限结构
   - 基差分位、曲线形态、日历价差/套利信号

## 6. 仓单库存与现货
   - 仓单、库存、虚实盘比、现货利润、贸易商报价

## 7. 交叉验证
   - 各模块一致之处、冲突之处、可能推翻观点的数据

## 8. 风险与限制
   - 披露限制、空数据、陈旧日期、合约移仓、流动性

## 9. 附录
   - 方法/参数表、行数统计
```

### 快速问答（4段压缩结构）

```markdown
## 结论
   [一句话核心判断]

## 关键证据
   - 证据1
   - 证据2

## 矛盾点
   [与结论相悖的信号]

## 数据来源
   [使用的方法和数据日期]
```

## ⚠️ 空数据与冲突处理

### 当方法返回空数据时

1. **检查是否为交易日**，方法期望的是 `trade_date`、`start_date/end_date` 还是其他日期字段
2. **检查品种代码格式**：是 variety code、symbol code、交易所后缀还是合约月份
3. **尝试已知主力合约**：先用 `get_future_dominant` 获取
4. **减少可选过滤条件**：如果方法文档允许，请求所有字段
5. **报告空状态**：必须声明"该接口在所选条件下无返回"，并记录已测试的方法和参数

### 当模块之间冲突时

- **不要强行统一结论**：声明哪些证据是基于价格的、基于持仓的、基于现货的、还是基于套利的
- **降低置信度**：当价格、持仓、现货指标不一致时
- **指明下一个验证点**：例如"下一交易日席位持仓"或"更新的仓单数据"

## 🚫 禁止事项

| 禁止 | 正确做法 |
|------|---------|
| "主力资金大举买入" | "前5席位净多持仓增加X手" |
| "多头主导行情" | "净多持仓占总持仓Y%" |
| "期货上涨，现货跟涨" | "基差从Z1收窄至Z2" |
| "后市必然上涨" | "若基差持续收窄，可能支撑期货价格" |
| 输出交易指令 | 移交64-02算法交易员 |
