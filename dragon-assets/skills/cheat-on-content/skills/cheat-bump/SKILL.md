# Cheat-Bump — Rubric升级刹车系统

## L0: 一句话描述
防止自我欺骗的公式升级验证机制

## L1: 使用场景
当连续三次同方向偏差时，必须走完整的升级验证流程

## L2: 详细文档

### 触发词
- "触发升级"
- "bump rubric"
- "升级公式"
- "更新rubric"

### 三条铁律

```
1. Bump = 全量重打分
   → 新公式必须重判所有历史样本

2. 验证阈值：≥4/5样本排名匹配实际数据
   → 否则拒绝升级，必须重新调整

3. Rubric是工作台不是博物馆
   → 被数据推翻的观察必须删除
```

### 升级流程

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 触发条件检测                                             │
│    连续三次同方向偏差 → 进入升级流程                        │
├─────────────────────────────────────────────────────────────┤
│ 2. 提出新公式                                               │
│    解释调整逻辑 + 权重变化 + 新旧对比                       │
├─────────────────────────────────────────────────────────────┤
│ 3. 全量重打分 (Bump = Full Re-Score)                        │
│    用新公式重判所有历史样本（≥5个）                        │
├─────────────────────────────────────────────────────────────┤
│ 4. 验证检查                                                 │
│    ≥4/5样本排名匹配实际数据 → ✅放行                        │
│    <4/5样本排名匹配 → ❌拒绝，重新调整公式                  │
├─────────────────────────────────────────────────────────────┤
│ 5. 发布新公式                                               │
│    验证通过 → 更新rubric_notes.md                          │
│    验证失败 → 记录原因，维持原公式                         │
└─────────────────────────────────────────────────────────────┘
```

### 验证报告格式

```markdown
# Rubric升级验证报告

## 升级原因
连续三次播放量预测偏高（实际均低于预测）

## 新公式提议
```
综合分 = (ER×2.0 + SR×1.5 + HP×1.5 + QL + NA + AB + SAT) / 9.0 × 2.0
```
变化：ER权重 1.5→2.0

## 历史重打分结果
| 样本 | 旧排名 | 新排名 | 实际排名 | 匹配? |
|------|--------|--------|----------|-------|
| 视频A | 2 | 1 | 1 | ✅ |
| 视频B | 1 | 3 | 2 | ✅ |
| 视频C | 3 | 2 | 3 | ✅ |
| 视频D | 4 | 4 | 4 | ✅ |
| 视频E | 5 | 5 | 6 | ❌ |

## 验证结果
- 匹配率: 4/5 = 80%
- 阈值: ≥80% ✅
- 结论: **通过，放行升级**

---
```

### 关键约束

- ✅ 新公式必须解释调整逻辑
- ✅ 必须全量重打分所有历史样本
- ✅ 匹配率必须 ≥80% 才放行
- ❌ 不能只测新样本就发布新公式
- ❌ 不能用新公式只打部分样本
