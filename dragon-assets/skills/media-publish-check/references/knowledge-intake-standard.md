# 新资料筛选与吸收标准

把用户提供的 PDF、截图、网页、词表和课程资料先作为“候选证据”，完成筛选后再进入 Skill。不要边读边把所有说法写成硬规则。

## 目录

1. 建立资料登记
2. 完整提取与去重
3. 证据分级
4. 内容分类
5. 规则原子化
6. 冲突与时效处理
7. 接纳结论
8. 需要询问用户的情况
9. 吸收报告格式

## 1. 建立资料登记

为每份资料记录：

- 文件名、标题、作者/机构、原始链接、提供日期；
- 声称适用的平台、账号类型、行业、内容形式和地区；
- 发布、更新、生效和本次核验日期；
- PDF 页数、截图页、可提取文本比例、是否有水印/课程宣传；
- 是否能追溯到平台官方或监管原文。

缺少作者、日期或来源时不要补猜，标记“来源信息不足”。

## 2. 完整提取与去重

- PDF 按页提取文字并渲染检查截图页、表格、脚注、红框和小字；
- 图片执行 OCR，同时保留页码或图片编号；
- 去掉重复页眉页脚、课程水印和纯宣传内容，但保留可能影响来源判断的信息；
- 合并完全重复的条目，保留最清晰、来源最高的一条；
- 相似条目不要只按关键词合并，先比较适用范围、例外和风险动作。

## 3. 证据分级

按从高到低标记：

- `E1 法律/监管官方`：法律法规、主管部门通知、执法指南和官方数据库；
- `E2 平台官方`：协议、规则中心、创作者中心、发布页、账号通知、官方公告；
- `E3 可核验专业来源`：法院文书、标准、持证机构或权利人材料，且与当前问题直接相关；
- `E4 行业经验`：MCN、课程、运营团队、媒体总结或第三方工具；
- `E5 无法核验`：匿名截图、转述、无日期清单、所谓内部规则或流量玄学。

E4/E5 不能单独支持“违法”“平台明令禁止”“一定限流”或“保证过审”。

## 4. 内容分类

每条候选内容只能先进入下列一类：

- `硬规则`：有 E1 直接支持，且适用范围明确；
- `平台规则`：有 E2 直接支持，写明平台、账号/行业、形式和日期；
- `权利/事实要求`：需要授权、资质、证明、同意或一手来源；
- `经验提示`：可能有用但不能决定发布结论；
- `运营建议`：标题、封面、节奏、互动等质量建议，与合规分开；
- `绕审风险样例`：暗号、谐音、小号、隐藏二维码、伪装联系方式等；
- `无关/宣传`：课程售卖、个人战绩、重复口号或与发布审核无关；
- `待核验`：无法确认来源、含义或适用范围。

资料若在教绕审，把它反向吸收为风险样例，绝不作为操作建议。

## 5. 规则原子化

把长段落拆成一条一义的规则记录，至少包含：

```text
rule_id:
platform:
content_type:
topic_or_industry:
account_type:
trigger_or_condition:
risk_statement:
required_action:
exceptions:
default_severity:
evidence_level:
source_title:
source_url_or_file:
page_or_section:
published_or_effective_date:
verified_date:
status: active | superseded | pending
```

不要只保存“违禁词”。保存它在什么语境、为什么有风险、需要什么动作和有哪些例外。

## 6. 冲突与时效处理

按以下规则解决：

1. 生效中的 E1 优先于其他来源；
2. 目标平台当前 E2 优先于旧平台规则和行业经验；
3. 更具体的行业、账号类型和内容形式规则优先于泛化表述；
4. 新版规则替代旧版时，把旧条目标记 `superseded`，不要继续触发；
5. 官方来源互相不清楚时保留冲突，降低确定性并要求人工复核；
6. 仅有 E4/E5 支持时只能生成候选命中或经验提示。

规则没有日期时设置复核提醒；平台 UI 截图还要记录 App 版本或截图日期（若可得）。

## 7. 接纳结论

为每条资料给出一种处置：

- `接纳为硬规则`；
- `接纳为平台专项规则`；
- `接纳为权利/事实检查项`；
- `降级为经验提示`；
- `反向吸收为绕审风险`；
- `暂缓，等待官方核验`；
- `拒绝，无关/重复/明显错误`。

只有前五类可以进入正式参考文件或检测候选；“暂缓”和“拒绝”保留在本次吸收报告，不进入触发规则。

## 8. 需要询问用户的情况

仅在以下情况问用户：

- 资料是否来自官方但缺少可验证的原始链接；
- 同一条内容可能是用户希望采用的运营策略，也可能是需要拦截的绕审方法；
- 资料与用户已经确认的产品策略冲突；
- 采用该条会明显改变风险等级、默认平台策略或对外承诺。

提问时展示：`原片段 + 页码/位置 + 拟分类 + 不确定原因 + 一个问题`。不要一次丢给用户十几条模糊问题。

## 9. 吸收报告格式

```markdown
# 资料吸收报告

## 概览
- 文件：
- 页数/条目：
- 可追溯官方来源：
- 需要用户确认：

## 接纳清单
| 原位置 | 主题 | 证据级别 | 处置 | 进入文件 | 说明 |
|---|---|---:|---|---|---|

## 降级/拒绝清单
| 原位置 | 原说法 | 处置 | 原因 |
|---|---|---|---|

## 冲突与待核验
- ...

## 需要用户确认
- [只列会改变策略的问题]
```
