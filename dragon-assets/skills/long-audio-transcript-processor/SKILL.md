# 语音转写处理工作流 (Long Audio Transcript Processor)

此技能通过文件系统辅助，安全、有序地处理超长语音转写文本。它通过分段处理、上下文维护（术语表、主题记录）和状态追踪，确保处理过程的可持续性和高质量。

## 触发条件

- 用户提供长篇语音转写文件需要校对
- 全天会议、深度访谈的整理
- 文本过长无法一次放入上下文
- 需要中断恢复的工作

## 工作流

### 1. 准备阶段 (Initialization)

创建工作区：
```text
语音转写处理_YYYY-MM-DD-HH-MM/
├── 0-工作日志.md           # 进度追踪与计划
├── 1-原始文件/             # 存放用户提供的原始语音文本
├── 2-要求和信息/           # 存放活动背景、发言人等信息
├── 3-校对和术语表.md       # 动态更新的术语库和错误模式
├── 4-分段主题.md           # 记录已处理分段的主题脉络
└── 5-最终输出/             # 存放校对完成的分段文件
```

### 2. 分段处理循环

每次处理前，先读取上下文文件：
- `0-工作日志.md` (检查进度)
- `2-要求和信息/` 下的背景文档
- `3-校对和术语表.md` (加载术语和校对规则)
- `4-分段主题.md` (加载已有上下文主题)

**处理步骤**：
1. 确定任务：从工作日志中找到第一个未完成的分段
2. 读取内容：使用 Read 的 offset/limit 参数分段读取
3. 执行校对：修正错别字、重复、同音错误
4. 输出结果：写入最终输出目录
5. 更新状态：标记分段为已完成

### 3. 中断恢复

如果对话中断，**不要重新初始化**。直接读取上下文文件恢复状态。

### 4. 衍生任务

除了标准转写外，可并行生成：
- Q&A 问答库
- 摘要
- 待办事项

### 5. 订正标记

使用 Emoji 标记修改痕迹：
- `{🔴 原始内容}` - 被修改或删除的原始文本
- `{🟢 新内容}` - 新增或修正后的文本
- `{‼️ 需特别留意}` - 存在矛盾、风险或不确定的地方

## 天龙引擎集成

此技能增强天龙引擎07记录师的转写处理能力:
- **超长文本处理**: 分段处理突破上下文限制
- **断点续传**: 支持中断恢复
- **术语一致性**: 动态维护术语表

### 使用示例

```bash
# 触发技能
"帮我处理这个全天会议的转写稿"

# 指定文件
"整理这个访谈的语音转写，保持术语一致"
```

## 注意事项

- **只追加原则**: 术语表和主题文件只追加不修改
- **背景驱动**: 禁止在不读取背景文档的情况下开始处理
- **说话人识别**: 根据上下文区分真实角色
