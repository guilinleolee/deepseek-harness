# Step 02: 互联网检索

## 目标
通过互联网搜索收集相关技术信息、最佳实践和社区方案，为架构设计提供依据。

## 执行流程

### 1. Brave 搜索（3轮）

采用"逐步聚焦"策略：

#### 第1轮：广泛搜索
```
搜索词: "n8n [功能] workflow best practices"
示例: "n8n email automation workflow best practices"

目标:
- 发现常见模式和架构
- 识别主流节点组合
- 收集最佳实践建议
```

#### 第2轮：具体问题
```
搜索词: "n8n [具体节点] [具体问题]"
示例: "n8n gmail filter attachment save"

目标:
- 解决具体技术问题
- 获取节点配置示例
- 发现常见陷阱
```

#### 第3轮：社区方案
```
搜索词: "n8n community template [场景]"
示例: "n8n community template email to slack"

目标:
- 找到现成模板
- 学习社区方案
- 对比不同实现
```

### 2. WebFetch 深度抓取

对于有价值的页面，深入阅读：

```yaml
优先级:
  - n8n.io 官方文档
  - n8n 社区论坛
  - GitHub 上的工作流示例
  - 技术博客教程

抓取要点:
  - 完整的节点配置示例
  - 表达式使用技巧
  - 常见错误和解决方法
  - 性能优化建议
```

### 3. search_nodes 交叉验证

使用 n8n-mcp 或本地 INDEX.md 验证：

```yaml
验证清单:
  - 节点是否存在
  - 节点版本是否匹配
  - 是否需要社区节点
  - 节点间的兼容性

示例流程:
  1. 搜索方案推荐 "@n8n/n8n-nodes-xxx"
  2. 在 INDEX.md 中查找该节点
  3. 确认 typeVersion 和参数
  4. 检查是否有替代方案
```

### 4. search_templates 3轮 + 模板 diff

#### 第1轮：功能匹配
```
搜索: templates matching "[核心功能]"
目标: 找到功能相似的模板
```

#### 第2轮：节点组合
```
搜索: templates using "[节点A] [节点B]"
目标: 发现节点组合模式
```

#### 第3轮：架构参考
```
搜索: templates with "[架构模式]"
目标: 参考整体架构设计
```

#### 模板 diff
```yaml
对比维度:
  - 节点选择差异
  - 数据流向差异
  - 错误处理差异
  - 配置复杂度

输出: 推荐方案 + 理由
```

## 搜索间隔约束

⚠️ **重要**: 互联网搜索串行调用，间隔 ≥ 2 秒

```javascript
// 伪代码示例
for (const query of searchQueries) {
  await braveSearch(query);
  await sleep(2000); // 必须等待2秒
}
```

## 验证条件

- [ ] 完成3轮 Brave 搜索
- [ ] 至少深度抓取2个页面
- [ ] 验证所有推荐节点存在

## 错误处理

| 错误 | 处理 |
|------|------|
| 搜索无结果 | 调整关键词，使用同义词 |
| 页面抓取失败 | 尝试备用链接或缓存 |
| 节点不存在 | 寻找替代节点或社区包 |
| 模板不匹配 | 分析不匹配原因，调整方案 |
