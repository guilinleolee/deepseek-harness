## 🔴 高风险操作

### 回滚操作 (rollback.sh)

**风险**: 回滚版本可能导致工作丢失，且操作不可逆

**症状**:
- 回滚后无法恢复已删除的工作
- 多人协作时可能影响其他成员

**安全操作流程**:
```bash
# 1. 先查看回滚预览
./rollback.sh v1.2.0 --dry-run

# 2. 确认影响范围
./rollback.sh v1.2.0 --show-affected

# 3. 通知团队成员后执行
./rollback.sh v1.2.0
```

### 审批流程 (approve/reject)

**风险**: 错误的审批可能导致安全漏洞或合规问题

**症状**:
- 审批了包含漏洞的代码
- 拒绝了合法的紧急修复

**安全操作流程**:
```bash
# 1. 查看待审批操作详情
./governance.sh show ACTION-001

# 2. 运行安全检查
./governance.sh check ACTION-001

# 3. 确认后审批
./governance.sh approve ACTION-001 --comment "已验证安全性"
```

## 🟡 中风险操作

### 版本发布 (release)

**风险**: 发布到生产环境可能影响用户

**安全操作流程**:
```bash
# 1. 确保测试通过
npm test && npm run e2e

# 2. 创建发布分支
git checkout -b release/v1.2.0

# 3. 发布
./release.sh v1.2.0
```

## 🐛 常见陷阱

### 陷阱1: 回滚到错误的版本

**症状**: 回滚后发现是错误的版本

**原因**: 未确认版本号

**解决方案**:
```bash
# 列出所有可用版本
./rollback.sh --list

# 使用 --dry-run 预览
./rollback.sh v1.2.0 --dry-run
```

### 陷阱2: 审批超时

**症状**: 审批请求长时间未处理

**原因**: 未设置审批提醒

**解决方案**:
```yaml
# 在配置中设置自动提醒
governance:
  approval_timeout: 24h
  reminder_interval: 4h
  escalate_after: 8h
```

## 📞 紧急联系

如果发生误操作：

1. **立即通知团队**: 在相关Slack频道发布警告
2. **暂停相关服务**: 如有需要，暂停受影响的服务
3. **保留日志**: 不要删除任何日志文件，用于事后分析
4. **联系管理员**: 紧急情况联系系统管理员
