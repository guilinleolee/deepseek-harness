# OPC-Conversion-Loop 转化闭环设计

## 定位陈述

**职能**: 转化路径设计 | **协议**: OPC | **边界**: 只做路径结构，不进入内容/文案/运营SOP

## 核心价值

帮助用户设计"怎么触达、怎么承接、怎么成交"的路径，而不是直接替用户定一条路线。

## 核心概念

### 转化闭环三阶段

```
┌─────────────────────────────────────────────────────────────┐
│                    转化闭环                                  │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  触达 ──→ 承接 ──→ 成交                                   │
│                                                             │
│  在哪里      怎么接住     怎么完成第一单                   │
│  找到用户    线索         转化                             │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 关键认知

- **关键不只是流量，而是有没有承接和成交动作**
- **转化闭环决定了如何拿到第一批用户**
- 流量进来但没有承接和成交 = 无效流量

## 三阶段定义

### 1. 触达（Reach）

目标用户**最常出现**的地方：
- 内容平台（小红书/抖音/公众号/知乎）
- 社区（微信群/知识星球/Discord）
- 搜索（百度/Google/小红书搜索）
- 工具（SaaS产品/浏览器插件）

### 2. 承接（Lead Capture）

线索来了**怎么接住**：
- 私信/微信（强关系，高维护成本）
- 表单/问卷（中等强度，可批量处理）
- 微信群/社群（中等强度，社区运营）
- 订阅/关注（弱关系，低维护成本）

### 3. 成交（Conversion）

**第一次成交**怎么发生：
- 低价产品/体验装（降低决策门槛）
- 一对一咨询（高价值，高信任）
- 内容/资源包（虚拟产品，即时交付）
- 直接高客单（高信任，高门槛）

## 常见转化路径示例

| 路径类型 | 触达 | 承接 | 成交 | 适用场景 |
|---------|------|------|------|---------|
| 内容→私信→咨询→成交 | 内容平台 | 私信 | 一对一咨询 | 高客单服务 |
| 内容→表单→诊断→成交 | 内容平台 | 表单 | 诊断服务 | 专业服务 |
| 低价产品→升级服务 | 搜索/内容 | 产品页 | 低价购买 | SaaS产品 |
| 社群→私信→成交 | 社群 | 私信 | 高客单 | 培训/咨询 |

## 执行协议

### SCP协议（苏格拉底对话）

- 默认**一次只问一个问题**
- 如果几个问题都很轻且紧密相关，可合并成2-3个
- 给出**3条转化路径**，并附加"4. 我有自己的方案"
- **用户确认后再写入正式结果**
- 不直接给推荐结论，只做方案分析

### 执行步骤

```
1. 解释本步目标和转化闭环概念
   └→ 转化闭环是从被看见到最终成交的完整路径
   └→ 关键不只是流量，而是有没有承接和成交动作
   └→ 这一步决定如何拿到第一批用户

2. 一次只问一个问题（或2-3个轻量相关问题）
   └→ 你的目标用户最常出现在哪？
   └→ 你更擅长内容、私聊还是直接销售？
   └→ 你愿意先卖低价入口还是直接卖高客单？

3. 每轮回答后，给即时反馈

4. 生成3条转化路径：
   路径1：[内容 → 私信 → 咨询 → 成交]
   - 触达方式：[具体渠道]
   - 承接方式：[具体动作]
   - 成交方式：[具体动作]
   - 适用情况：[什么情况下这个路径最合适]
   - 优点：[具体优势]
   - 代价：[需要注意的点]

   路径2：[内容 → 表单 → 诊断 → 成交]
   （同上格式）

   路径3：[低价产品 → 升级服务]
   （同上格式）

5. 默认增加"4. 我有自己的方案"

6. 让用户选择、组合、修改，或直接提出自己的版本

7. 用户确认后，再写入正式结果
```

## 本阶段边界

### ✅ 本步做什么

- 确认目标渠道（在哪里触达用户）
- 确认线索承接方式（怎么接住）
- 确认第一次成交动作（怎么完成第一单）
- 确认完整转化路径结构

### ❌ 本步不做什么

- 不写具体内容选题、帖子结构或文案（→opc-asset-ops）
- 不设计具体产品包装话术（→opc-asset-ops）
- 不做运营SOP或交付细节（→opc-asset-ops）

**越界检测**：如果出现"第一篇帖子怎么写""具体怎么说服用户""封面怎么设计"：
> "这些属于内容资产阶段的工作。现在先把转化路径的结构确认好，后面的内容才有方向。"

## 落盘文件

用户确认转化路径后，**立即**写入：

```
opc-doc/outputs/07-conversion-loop/
├── channel-strategy.md      # 目标渠道选择及依据
├── content-plan.md          # 内容触达方式类别（非具体选题）
└── conversion-path.md      # 完整转化路径：触达 → 承接 → 成交

opc-doc/state/
├── current-stage.json       # {"stage": "07-conversion-loop", "status": "completed"}
└── decisions.json           # 追加转化路径确认
```

**落盘完成后告知用户**：
> "✅ 转化闭环方案已保存。下次对话可以从资产沉淀继续。"

**只有落盘完成后，才可以提示进入 `opc-asset-ops` 或 `opc-dashboard-review`**。

## 完成标准

- [ ] 明确目标渠道
- [ ] 明确线索承接动作
- [ ] 明确低摩擦成交动作
- [ ] 明确完整转化路径
- [ ] 用户已确认当前主路径

## 异常处理

| 情况 | 处理 |
|------|------|
| 渠道太多 | 帮助用户收缩到1-2个 |
| 没有线索承接动作 | 不算闭环，引导补全 |
| 不知道怎么成交 | 引导思考"第一次成交在哪里发生" |
