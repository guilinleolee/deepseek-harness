# China Risk Matrix（中国市场风险矩阵）

> **版本**: V1.0 | **来源**: XiaomingX/ai-money-maker-handbook | **更新**: 2026-05-05

## L0: 一句话描述
程序员副业三维风险评估工具箱：法律边界+平台规则+交付能力系统性检查

## L1: 使用场景

**触发词**: 风险评估、合规检查、平台规则、交付能力、法律边界、灰产识别

**适用场景**:
- 评估副业项目的法律风险
- 检查平台规则合规性
- 判断自身交付能力边界
- 识别灰产和擦边行为
- 制定风险应对策略

### 法律风险详解

#### 灰产边界清单

```
绝对禁止（100%违法）:
❌ 账号买卖（实名认证账号）
❌ 虚假流量（刷单/刷粉/刷阅读量）
❌ 数据爬取（未经授权抓取用户数据）
❌ 侵权内容（盗版软件/影视/教材）
❌ 传销模式（拉人头分销）

灰色地带（谨慎操作）:
⚠️ API聚合转售（需查看平台TOS）
⚠️ 内容搬运（二次创作边界模糊）
⚠️ 套现操作（信用卡/积分套现）

安全区（合规操作）:
✅ 自研产品销售
✅ 知识付费（原创内容）
✅ 技术服务（按工时/项目收费）
✅ 内容创作（原创素材）
```

#### 税务合规指南

```
中国个人税务要点:
┌─────────────────────────────────────────────────────────────┐
│ 收入类型         | 税率        | 免税额度                │
├─────────────────────────────────────────────────────────────┤
│ 工资薪金         | 3%-45%     | 60000元/年              │
│ 劳务报酬         | 20%-40%    | 800元/次免征           │
│ 经营所得         | 5%-35%     | 60000元/年            │
│ 偶然所得         | 20%         | 1000元/次免征         │
└─────────────────────────────────────────────────────────────┘

合规建议:
- 年收入超过12万需年度个税申报
- 保留收入凭证和支出发票
- 考虑注册个体工商户（税率更优惠）
- 技术入股需专业律师指导
```

#### 知识产权风险

```
高风险行为:
❌ 未经授权使用他人代码/设计
❌ 复制竞品的产品逻辑和UI
❌ 使用未授权字体/图片/音乐
❌ 破解软件或提供破解教程

低风险行为:
✅ 开源协议合规使用（GPL需开源，MIT/Apache可商用）
✅ 自研代码和设计
✅ 购买正版授权素材
✅ 合理引用（注明来源）
```

### 平台风险详解

#### 平台规则变化监控

```
高风险平台（规则多变）:
┌─────────────────────────────────────────────────────────────┐
│ 平台      | 主要风险              | 监控建议              │
├─────────────────────────────────────────────────────────────┤
│ 抖音      | 算法变化快，限流严    | 关注官方公告          │
│ 小红书    | 笔记审核严格          | 避免敏感词            │
│ 咸鱼      | 商品审核严格          | 合规描述            │
│ 微信公众号 | 诱导关注/分享限制   | 规范措辞            │
└─────────────────────────────────────────────────────────────┘

低风险平台（规则稳定）:
✅ 知乎（规则相对稳定）
✅ B站（社区规则明确）
✅ 知识星球（封闭平台，规则宽松）
```

#### 封号风险自检

```
封号高危行为:
❌ 频繁发布广告内容
❌ 多个账号操作（关联封号）
❌ 违规词汇（平台敏感词库）
❌ 异常流量（短时间内大量曝光/点赞）
❌ 用户投诉过多

防封号最佳实践:
✅ 养号阶段：正常互动，不急于变现
✅ 内容质量：原创优先，避免搬运
✅ 账号隔离：多账号使用不同设备和IP
✅ 合规措辞：避免诱导关注、虚假宣传
```

### 交付风险详解

#### 技术能力自评表

```
┌─────────────────────────────────────────────────────────────┐
│ 能力维度      | 自评问题（满分10分）                       │
├─────────────────────────────────────────────────────────────┤
│ 需求理解      | 能准确理解客户需求吗？                     │
│ 技术实现      | 能按时交付合格代码吗？                    │
│ 问题解决      | 遇到难题能独立解决吗？                    │
│ 沟通能力      | 能清晰解释技术方案吗？                    │
│ 文档能力      | 能编写清晰的使用文档吗？                  │
└─────────────────────────────────────────────────────────────┘

交付能力公式:
交付可信度 = 技术能力分 × 0.4 + 沟通能力分 × 0.3 + 时间保障分 × 0.3

低于6分的维度需要在接单前补足
```

#### 时间投入评估

```
自评问题:
1. 每天可用于副业的时间是多少？
   - <1小时 → 高风险，只能做被动收入
   - 1-2小时 → 中风险，适合知识付费
   - 2-4小时 → 低风险，可做服务类产品
   - >4小时 → 极低风险，可规模化运营

2. 是否有稳定的空闲时间？
   - 不稳定 → 时间风险高，需预留缓冲
   - 稳定但可能被加班打断 → 中风险
   - 稳定且可掌控 → 低风险

3. 项目截止日期压力大吗？
   - 极大 → 交付风险高，可能影响质量
   - 适中 → 正常风险
   - 无压力 → 低风险
```

### 风险应对策略

```
风险等级与应对措施:
┌─────────────────────────────────────────────────────────────┐
│ 等级  | 评分范围  | 应对策略                                │
├─────────────────────────────────────────────────────────────┤
│ 绿色  | 0-30分   | 可以立即开始，注意保持                  │
│ 黄色  | 31-60分  | 制定风险缓解计划，逐步推进                │
│ 红色  | 61-100分 | 暂缓或调整方案，降低风险后再行动         │
└─────────────────────────────────────────────────────────────┘

通用风险缓解措施:
1. 法律风险 → 咨询律师，保留合规证据
2. 平台风险 → 多平台布局，降低单平台依赖
3. 交付风险 → 小单试水，积累口碑后再提价
```

## 使用命令

```bash
# 风险评估
/china-risk --assess [变现模式]

# 法律边界检查
/china-risk --legal [项目描述]

# 平台规则检查
/china-risk --platform [平台名称]

# 交付能力评估
/china-risk --delivery [服务类型]

# 综合风险报告
/china-risk --full [你的情况描述]
```
