# Audit Checklist
# 审计检查清单 - 用于身份审计的完整检查列表

## 天龙引擎身份审计检查清单 V1.0

---

## Stage 1: 角色定义检查 (Role Definition)

### 1.1 基本信息
- [ ] Agent编号是否唯一且符合天龙命名规范？
  - 格式: `[中心-序号]` 或 `[序号-序号]`
  - 示例: `07`、`09-02`、`35-05`

- [ ] Agent名称是否清晰可识别？
  - 长度: 2-10个中文字符
  - 格式: `XX师`、`XX总监`、`XX工程师`

- [ ] 版本号是否符合规范？
  - 格式: `VX.Y` 或 `VX.Y.Z`
  - 示例: `V1.0`、`V8.95`

- [ ] 所属部门是否正确？
  - 必须在config.yaml的scope.departments中定义

### 1.2 核心职责
- [ ] 主要职责是否用一句话清晰描述？
  - 字数: 10-50字
  - 必须包含Agent的核心价值

- [ ] 次要职责是否不超过3项？
  - 数量: ≤3
  - 每项职责有明确边界

- [ ] 触发关键词是否覆盖主要使用场景？
  - 数量: ≥3
  - 覆盖80%以上的触发场景
  - 与其他Agent的关键词无显著重叠

### 1.3 汇报关系
- [ ] 是否明确汇报关系？
  - 定义了直接上级Agent
  - 或标注为"独立"角色

---

## Stage 2: 能力盘点检查 (Capability Inventory)

### 2.1 SKILL列表
- [ ] SKILL列表是否完整？
  - 包含所有必需SKILL
  - 每个SKILL有明确来源和版本

- [ ] SKILL是否有明确的用途说明？
  - 用途清晰可理解
  - 与Agent职责相关

### 2.2 工具权限
- [ ] 工具权限是否最小必要？
  - 只包含执行任务必需的权限
  - 遵循最小权限原则

- [ ] 工具权限是否不超过20项？
  - 数量: ≤20
  - 超过需拆分Agent

### 2.3 知识领域
- [ ] 知识领域是否有明确边界？
  - 定义了主领域
  - 定义了次领域
  - 可选：定义了新兴领域

### 2.4 能力版本
- [ ] 能力版本是否与CLAUDE.md同步？
  - 版本号一致
  - 更新时同步

---

## Stage 3: 协作接口检查 (Collaboration Interface)

### 3.1 上游接口
- [ ] 上游接口是否完整记录？
  - 记录所有调用方
  - 定义触发条件
  - 定义优先级

- [ ] 上游接口是否避免循环依赖？
  - 检查A→B→C→A模式

### 3.2 下游接口
- [ ] 下游接口是否明确调用目的？
  - 记录被调用方
  - 明确调用目的
  - 定义调用时机

### 3.3 通信协议
- [ ] 通信协议是否标准化？
  - 定义格式 (markdown/json/yaml)
  - 定义频率 (on_demand/daily/weekly)
  - 定义是否需要输出

### 3.4 错误处理
- [ ] 错误处理机制是否完整？
  - 定义重试次数
  - 定义升级条件
  - 定义升级目标

---

## Stage 4: 边界界定检查 (Boundary Definition)

### 4.1 can_do列表
- [ ] can_do列表是否明确？
  - 每项能力有清晰描述
  - 能力有明确边界
  - 与cannot_do互斥

### 4.2 cannot_do列表
- [ ] cannot_do列表是否完整？
  - 每项限制有明确原因
  - 包含常见越权场景
  - 与can_do互斥

### 4.3 禁止事项
- [ ] 禁止事项是否有法律/安全依据？
  - 安全类禁止
  - 合规类禁止
  - 道德类禁止

### 4.4 升级路径
- [ ] 升级路径是否清晰可执行？
  - 定义触发条件
  - 定义升级目标
  - 定义升级原因

### 4.5 能力上限
- [ ] 能力上限是否合理？
  - 定义最大并发任务数
  - 定义任务复杂度上限
  - 定义需要审批的操作

---

## Stage 5: 一致性验证检查 (Consistency Verification)

### 5.1 文档vs配置一致性
- [ ] Agent文档与实际配置是否一致？
  - 角色定义一致
  - 关键词一致
  - 能力边界一致

### 5.2 配置vs行为一致性
- [ ] 配置与实际行为是否一致？
  - 执行能力与can_do匹配
  - 拒绝行为与cannot_do匹配

### 5.3 自我认知vs实际能力
- [ ] Agent自我认知是否与能力匹配？
  - 文档描述的能力与配置一致
  - 不存在声称但不具备的能力

### 5.4 角色冲突
- [ ] 是否存在与其他Agent的角色冲突？
  - 检查已知冲突矩阵
  - 检查自动检测结果
  - 冲突有解决方案

---

## Stage 6: 演进追踪检查 (Evolution Tracking)

### 6.1 变更历史
- [ ] 变更历史是否完整记录？
  - 每次变更有记录
  - 包含变更内容和原因
  - 按时间排序

### 6.2 能力成长轨迹
- [ ] 能力成长是否有量化指标？
  - can_do数量变化
  - 协作接口数量变化
  - 关键词数量变化

### 6.3 风险预警
- [ ] 风险预警机制是否有效？
  - 及时检测风险
  - 风险有状态跟踪
  - 有改进建议

### 6.4 演进同步
- [ ] 演进是否与业务需求同步？
  - 能力成长支持业务发展
  - 版本更新及时

## 审计评分标准

| 维度 | 权重 | 评分标准 |
|------|------|----------|
| 角色定义 | 15% | 职责清晰度×10 + 关键词覆盖率×5 |
| 能力盘点 | 20% | SKILL完整性×10 + 工具权限合理性×10 |
| 协作接口 | 15% | 接口完整性×8 + 依赖合理性×7 |
| 边界界定 | 20% | can_do完整性×10 + cannot_do合理性×10 |
| 一致性验证 | 15% | 配置一致性×8 + 行为一致性×7 |
| 演进追踪 | 15% | 历史完整性×8 + 预警有效性×7 |

## 审计操作指南

### 运行完整审计
```bash
python scripts/identity_auditor.py audit --agent "{agent_id}"
```

### 运行冲突检测
```bash
python scripts/conflict_detector.py --auto-detect
```

### 运行一致性检查
```bash
python scripts/consistency_checker.py --agent "{agent_id}"
```

### 追踪演进
```bash
python scripts/evolution_tracker.py --agent "{agent_id}" --notes "审计后更新"
```

### 生成身份配置
```bash
python scripts/identity_auditor.py generate --agent "{agent_id}"
```

## 常见问题处理

### Q1: 发现角色冲突怎么办？
1. 记录到known_conflicts
2. 定义明确的职责边界
3. 建立协作协议
4. 定期复审

### Q2: 发现能力边界模糊怎么办？
1. 细化can_do描述
2. 补充cannot_do场景
3. 与相关Agent协商
4. 更新配置文件

### Q3: 发现协作接口缺失怎么办？
1. 分析实际协作关系
2. 补充上游/下游接口
3. 定义通信协议
4. 更新配置文件

### Q4: 发现不一致怎么办？
1. 确定正确的数据源
2. 更新不一致的配置
3. 重新运行一致性检查
4. 记录变更原因

## 与天龙引擎协同

本检查清单与以下组件协同：
- `config.yaml` - 审计配置和部门范围
- `identity_auditor.py` - 主审计脚本
- `conflict_detector.py` - 冲突检测
- `consistency_checker.py` - 一致性检查
- `evolution_tracker.py` - 演进追踪
- MemPalace - 审计报告存储
- llm-wiki-compiler - 知识归档
