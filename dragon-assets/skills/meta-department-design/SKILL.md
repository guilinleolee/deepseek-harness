# Meta-Department Design - 元部门设计模式

## V1.0 | 来源: Jin, Yongxun (2026) | 结构分离的质量监督

### L0: 一句话描述
结构分离的质量监督部门，四Agent协作驱动自演化

### L1: 使用场景

**适用场景**:
- 需要独立于业务部门的质量评估
- 双层评估交叉验证
- 驱动的Agent自演化

**触发条件**:
- 业务Manager评估可能存在偏差
- 需要客观的质量监督
- 评估一致性需>80%

### 四Agent职责矩阵

| Agent | 类型 | 核心职责 | 输出 |
|-------|------|---------|------|
| **Warden** | Manager | 质量协调、演化驱动 | 演化指令、评估调度 |
| **Forge** | Worker | 架构质量分析 | 技术债报告 |
| **Prism** | Worker | 质量评分(20分制) | 评分报告→自演化 |
| **Scout** | Worker | 工作流监控 | 效率分析 |

### 双层评估机制

```python
# 双层评估 = Business Manager + Meta-Department
# 一致性目标: >87.5%

evaluation_flow = """
用户提交任务
    ↓
Business Manager评估 → Score_A
    ↓
Meta-Department评估 → Score_B
    ↓
交叉验证 → Cohen's κ
    ↓
一致性>87.5% → 接受
    ↓
一致性<87.5% → Warden裁定
"""
```

### Prism评分标准(20分制)

```yaml
scoring_matrix:
  20-19: "卓越 - 超出预期，建议推广"
  18-17: "优秀 - 完全满足要求"
  16-15: "良好 - 基本满足，有小问题"
  14-13: "一般 - 满足基本需求"
  12-10: "需改进 - 存在明显问题"
  <10:   "不合格 - 需重大修订"
```

### 自演化驱动

```python
# Prism评分 → 自演化触发
evolution_trigger = {
    "score >= 18": "记录为优秀模式",
    "score 15-17": "继续观察",
    "score < 15": "触发自我改进循环"
}
```

### 使用命令

```bash

/meta-department evaluate --task <task_id>

/meta-department cross-validate --department game

/meta-department evolve --trigger prism-score --threshold 15
```

| 维度 | Business Manager | Meta-Department |
