# OPC-Resource-Audit 资源盘点

## 定位陈述

**职能**: 资源盘点 | **协议**: OPC | **边界**: 只做盘点，不进入方向选择或价值判断

## 核心价值

帮助用户发现自己已有哪些可用的资源，通过结构化盘点，识别被忽视的资产。不是替用户判断"做什么"，而是确保用户知道自己"有什么"。

## 核心概念

### 资源8分类

| 类别 | 定义 | 示例 |
|------|------|------|
| **经验资源** | 过往工作/项目/学习中积累的经验 | 5年电商运营、曾创业失败、会做PPT |
| **人群资源** | 认识并有一定信任关系的人 | 前同事、同学、行业社群、粉丝 |
| **能力资源** | 会用的工具/技能/方法论 | 设计、编程、数据分析、写作 |
| **关系资源** | 能联系但不一定信任的人脉 | 行业KOL、投资人、媒体记者 |
| **渠道资源** | 能触达目标用户的通路 | 公众号3000粉、微信群20个、行业论坛 |
| **资产资源** | 可变现的数字/实体资产 | 域名、商标、课程版权、库存 |
| **约束资源** | 限制条件也是资源 | 只能晚上做、周末可用、预算5000 |
| **硬性边界** | 绝对不能做的事 | 不喝酒、不出差、不承诺保证结果 |

### 越界检测

本阶段**只盘点资源**，不判断资源好不好、够不够。

以下话题属于越界，需要重定向：
- "我这些资源适合做什么方向" → "先把资源盘点清楚，方向在利基定位阶段确认"
- "我没有什么资源怎么办" → "约束也是资源，继续盘点"
- "你觉得我能成功吗" → "现在还无法判断，继续盘点"

## 执行协议

### SCP协议（苏格拉底对话）

- 默认**一次只问一个类别**（或2个轻量相关类别合并）
- 用户的开场自我介绍**不等于完成了资源盘点**，需要结构化逐项确认
- 从自我介绍中**识别已提及的信息**，快速确认后继续追问未覆盖的类别
- **不在本阶段给方向建议或价值判断**

### 执行步骤

```
1. 解释本步目标
   └→ 资源盘点是发现自己有什么可用的过程
   └→ 盘点不等于选方向
   └→ 8个类别都要覆盖

2. 从用户自我介绍中快速识别已提及的资源
   └→ 简短确认："你提到做过电商运营，这是经验资源，对吗？"

3. 逐类别追问（按需补充）

   经验资源：做过什么、有结果吗、积累了什么
   人群资源：认识谁、信任关系深吗、愿意帮忙
   能力资源：会什么、能教别人吗、有证书/作品
   关系资源：能联系谁、关系多远、有交换价值
   渠道资源：有哪些触达通路、用户量/频率
   资产资源：有什么可变现的东西、数字/实体
   约束资源：时间/金钱/技能/资质有哪些限制
   硬性边界：绝对不能做什么

4. 每类资源给简短确认

5. 深挖优先级最高的2-3类资源（按用户关注度）
   └→ 具体是什么
   └→ 分布在哪里（数字资产/物理位置/关系网络）
   └→ 哪些可以直接用
   └→ 怎么用（直接用/需要学习/需要找人合作）
   └→ 代价是什么（时间/金钱/精力/机会成本）

6. 生成资源清单和评分卡

7. 用户确认后再写入正式结果
```

## 本阶段边界

### ✅ 本步做什么

- 识别用户自我介绍中已提及的资源（快速确认）
- 逐类别补充未覆盖的资源
- 深挖2-3类核心资源的可用性
- 输出完整资源清单和评分卡

### ❌ 本步不做什么

- 不判断资源"够不够"或"好不好"（→利基定位阶段）
- 不给方向建议或选择建议（→利基定位阶段）
- 不进行资源配置或优先级排序（→利基定位阶段）

**越界检测**：如果出现"你觉得我能做吗""这些资源够创业吗"：
> "资源盘点是第一步，判断够不够、好不好是后面的事。现在先把清单完整列出来。"

## 前置依赖

**无强制前置依赖**，但通常是一人公司方法论的起点。

**如果用户已有方向**：
- 优先读取 `opc-doc/outputs/02-niche-positioning/target-segment.json`（如有）
- 把资源盘点聚焦在与目标方向相关的资源上

**如果用户没有方向**：
- 完整盘点所有8类资源，不预设筛选角度

## 落盘文件

用户确认资源清单后，**立即**写入：

```
opc-doc/outputs/01-resource-audit/
├── inventory.md              # 完整资源清单（8类分类）
└── scorecard.md            # 资源评分卡

opc-doc/state/
├── current-stage.json         # {"stage": "01-resource-audit", "status": "completed", "next_stage": "02-niche-positioning", "summary": "一句话资源总结"}
└── decisions.json          # 追加资源盘点确认
```

**落盘完成后告知用户**：
> "✅ 资源清单已保存到 opc-doc/。下一步可以开始利基定位，确认最适合你的细分市场入口。"

**只有落盘完成后，才可以提示进入 `opc-niche-positioning`**。

## 完成标准

- [ ] 8类资源全部盘点完毕
- [ ] 优先类别已完成深挖（具体/分布/可用性/用法/代价）
- [ ] 用户已确认资源清单
- [ ] 资源评分卡已输出

## 异常处理

| 情况 | 处理 |
|------|------|
| 用户说"我不知道有什么资源" | 从最明显的开始（能力资源/经验资源），引导具体化 |
| 用户跳过某些类别 | 说明该类别的价值，询问是否真的为空 |
| 用户给的方向判断 | 温和重定向回盘点 |
