## 🔧 详细优化方案

### 优化1: 数据库慢查询优化

**问题分析**:
```sql
-- 慢查询 (Avg Time: 2000ms)
SELECT * FROM orders
WHERE user_id = 123
  AND status = 'pending'
  AND created_at > '2026-01-01'
ORDER BY created_at DESC;
```

**根因**: 缺少索引，全表扫描（100万行）

**优化方案**:
```sql
-- 添加复合索引
CREATE INDEX idx_user_status_created
ON orders(user_id, status, created_at);

-- 优化后查询 (Avg Time: 5ms)
-- 使用索引，只扫描100行
```

**效果**: 响应时间从2000ms降至5ms (**400x提升**)

**验证**:
```sql
EXPLAIN ANALYZE
SELECT * FROM orders WHERE ...;
-- 确认使用了索引
```

---

### 优化2: 消除N+1查询

**问题代码**:
```python
# N+1查询: 1次查订单 + 100次查用户
orders = db.query("SELECT * FROM orders")
for order in orders:
    user = db.query(f"SELECT * FROM users WHERE id = {order.user_id}")
    order.user = user
```

**优化方案**:
```python
# 批量查询: 2次查询
orders = db.query("SELECT * FROM orders")
user_ids = [o.user_id for o in orders]
users = db.query(f"SELECT * FROM users WHERE id IN ({','.join(user_ids)})")
user_map = {u.id: u for u in users}
for order in orders:
    order.user = user_map[order.user_id]
```

**效果**: 查询次数从101次降至2次 (**50x减少**)

### 优化3: Redis缓存

**缓存策略**:
```
缓存命中率目标: >80%

缓存内容:
- 用户信息 (TTL: 1小时)
- 商品详情 (TTL: 10分钟)
- 热门商品列表 (TTL: 5分钟)

更新策略:
- Cache-Aside: 先查缓存，未命中查DB，然后写入缓存
- 写穿透: 更新DB时，同步更新缓存
```

**实现**:
```python
def get_user(user_id):
    # 先查缓存
    cache_key = f"user:{user_id}"
    user = redis.get(cache_key)
    if user:
        return json.loads(user)

    # 缓存未命中，查DB
    user = db.query(f"SELECT * FROM users WHERE id = {user_id}")

    # 写入缓存
    redis.setex(cache_key, 3600, json.dumps(user))

    return user
```

**效果**:
- 缓存命中率: 85%
- DB负载降低: 80%
- 响应时间: 从200ms降至20ms

## ⚠️ 性能陷阱

### 常见误区

| 误区 | 说明 | 正确做法 |
|------|------|----------|
| 过早优化 | 没有测量就优化 | 先建立性能基线，再优化瓶颈 |
| 盲目缓存 | 缓存所有数据 | 只缓存热点数据（80/20法则） |
| 忽略复杂性 | 为了性能牺牲可读性 | 平衡性能和可维护性 |
| 一次性优化 | 优化完就不管 | 建立监控，持续优化 |
| 局部优化 | 只优化一个点 | 全链路优化，避免木桶效应 |

### 反模式

**反模式1: 为了优化而优化**
```python
# ❌ 差: 过度优化，代码可读性差
def calc(a,b,c): return (a*b)+(a*c)+(b*c) #节省3个变量

# ✅ 好: 清晰表达意图
def calculate_total(price_a, price_b, price_c):
    return price_a * quantity_a + price_b * quantity_b + price_c * quantity_c
```

**反模式2: 缓存失效**
```python
# ❌ 差: 缓存永不过期，数据不一致
redis.set(key, value)  # 无TTL

# ✅ 好: 合理设置TTL
redis.setex(key, 3600, value)  # 1小时过期
```

**反模式3: 批量查询过大**
```python
# ❌ 差: 一次查10万条，内存溢出
users = db.query("SELECT * FROM users")  # 10万行

# ✅ 好: 分页查询
for page in range(0, 1000):
    users = db.query(f"SELECT * FROM users LIMIT 100 OFFSET {page*100}")
```

## 🎓 优化原则

### 1. 80/20法则

20%的代码占用了80%的资源，优先优化那20%：
```
找到热点函数（Hot Spots）
优化前: 执行100万次，每次1ms = 1000s
优化后: 执行100万次，每次0.1ms = 100s
节省: 900s (90%)
```

### 2. 缓存层次

```
浏览器缓存 (CDN) → 应用缓存 (Redis) → 数据库
    命中率: 30%        命中率: 50%      命中率: 20%

综合命中率: 1 - (1-30%) * (1-50%) * (1-20%) = 72%
最终DB负载: 28%（降低72%）
```

### 3. 异步化

将同步改为异步，提升吞吐量：
```
同步: 请求1 → 处理(1s) → 响应
      请求2 → 等待 → 处理(1s) → 响应
      总时间: 2s

异步: 请求1 → 队列 → 立即返回
      请求2 → 队列 → 立即返回
      后台处理: 1s + 1s = 2s (并行)
      总时间: 1s
```
