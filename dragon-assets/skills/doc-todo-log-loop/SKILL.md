# Skill: doc-todo-log-loop

## 概述

本技能定义了一种人机协作的开发工作流，核心是文档驱动、日志记录的迭代循环。它通过清晰的步骤和产出物，确保开发过程的规范性、可追溯性和高质量。

特别适用于需要设计、过程记录和阶段性确认的软件功能开发或问题修复任务。

## 触发条件

- 用户在项目章程提及使用此技能
- 需要轻量级开发流程
- 中小型项目开发

## 核心工作循环

### 步骤 1: 背景描述 → 文档撰写 (User → Agent)

**触发**: 用户提出功能目标或问题背景

**Agent 行动**:
1. 与用户充分沟通，理解背景、目标和约束
2. 撰写正式的功能设计或背景分析文档
3. 命名约定: `YYYY-MM-DD-hh-mm-设计-{需求简述}.md`

### 步骤 2: 需求描述 → TODO 拆分 (User → Agent)

**触发**: 用户基于设计文档提出具体需求

**Agent 行动**:
1. 将高阶需求拆解为具体的、可执行的待办事项
2. 结构化更新到 `TODO.md` 文件
3. 每个待办事项应清晰、原子化

### 步骤 3: 任务指派 (User → Agent)

**触发**: 用户从 `TODO.md` 中选择待办事项

**Agent 行动**:
1. 确认任务指令
2. **绝不能**在收到用户明确指令前提前开发

### 步骤 4: 开发与确认 (Agent → User)

**触发**: Agent 接收到开发指令

**Agent 行动**:
1. 执行具体的开发任务
2. 每完成一个原子操作后停下等待用户确认
3. 用户作为审查者对结果进行确认

### 步骤 5: 开发日志记录 (Agent → User)

**触发**: 阶段性功能经用户确认完成后

**Agent 行动**:
1. 撰写新的开发日志
2. 日志命名: `-开发日志-` 部分
3. 日志内容:
   - 实现了哪些功能点
   - 主要修改
   - 遇到的问题和修正
   - 后续建议

### 步骤 6: 版本控制 (User)

**触发**: Agent 完成开发日志

**用户行动**:
1. 审查代码变更和开发日志
2. 执行 `git add` 和 `git commit`

## Agent 的主动性与约束

### 可以主动
- 完成步骤后主动查阅 `TODO.md` 和开发日志
- 向用户建议下一步可执行的任务

### 禁止主动
- **绝对禁止**在未获得用户明确指令的情况下提前开发

此约束确保用户始终对开发节奏拥有完全控制权。
