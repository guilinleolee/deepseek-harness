# silence-protocol - 留白协议

> **版本**: V1.0
> **来源**: 老金元组织方法论 × 天龙引擎V8.96
> **核心**: 留白三原则 + 默认沉默设计 + 打断成本评估

---

## 核心概念

### 什么是"留白"？

**留白** = 有些时候，最好的动作不是什么都推出来，而是什么都不做。

### 核心原则

> "因为用户有时需要的是消化，不是更多刺激。"
>
> "如果没有明确证据证明'打断更优'，那默认先不打断。"

### 留白三原则

```
┌─────────────────────────────────────────────────────────────┐
│ 留白三原则                                                │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│ 原则1: 无明确证据，不打断                                   │
│ → 除非有证据证明打断的收益 > 打断的成本，否则默认沉默       │
│                                                             │
│ 原则2: 给用户消化空间                                      │
│ → 用户需要时间理解和处理信息，过早打断会打断思维流          │
│                                                             │
│ 原则3: 系统越会判断越高级                                  │
│ → 知道什么不该发，是系统成熟度的标志                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 默认沉默设计

### 默认沉默场景

```yaml
default_silence:
  # 无明确必要性的场景
  unnecessary:
    - "用户正在深度工作中"
    - "当前信息可能很快自动失效"
    - "用户之前已表示不感兴趣"
    - "打断成本 > 发牌收益"

  # 可能适得其反的场景
  counterproductive:
    - "用户正在做创意性工作"
    - "用户正在处理复杂问题"
    - "用户明确表示需要安静时间"
    - "当前氛围是沉浸式体验"

  # 信息过载的场景
  overload:
    - "用户刚刚收到大量信息"
    - "队列中已有其他待处理牌"
    - "用户正在做决策"
```

## 沉默协议设计

### 协议设计模板

```yaml
# silence-protocol.yaml

protocol_id: "协议ID"
protocol_name: "协议名称"

# 沉默场景定义
silence_conditions:
  mandatory_silence:
    # 必须沉默的场景
    - condition: "场景描述"
      reason: "沉默原因"
      alternative: "替代方案（延后/合并/不发送）"

  default_silence:
    # 默认沉默的场景（除非有明确理由）
    - condition: "场景描述"
      exception_criteria: "可以发牌的例外条件"

  conditional_silence:
    # 条件性沉默
    - condition: "场景描述"
      silence_until: "沉默直到..."
      wake_condition: "唤醒条件"

# 沉默时长设计
silence_duration:
  immediate: "立即沉默（不发送）"
  short_term: "短暂沉默（<5分钟）"
  medium_term: "中等沉默（5-30分钟）"
  long_term: "长期沉默（>30分钟）"
  permanent: "永久沉默（除非用户主动开启）"

# 唤醒机制
wake_up:
  conditions:
    - "用户主动询问"
    - "状态发生重大变化"
    - "任务关键节点到达"
    - "沉默时长达到上限"

  escalation:
    - "沉默超时时自动升级为发牌"
    - "高优先级信息绕过沉默"

# 用户控制
user_control:
  override_silence: true/false
  customize_silence: true/false
  silence_history_visible: true/false
```

## 沉默场景设计示例

### 示例1: 深度工作保护

```yaml
deep_work_protection:
  # 检测深度工作信号
  signals:
    - "连续键盘输入 > 10分钟"
    - "当前任务标记为深度工作"
    - "用户未主动交互 > 5分钟"
    - "IDE/编辑器处于焦点"

  silence_policy:
    - "信息牌: 沉默，直到深度工作结束"
    - "确认牌: 延后，深度工作结束后发"
    - "推荐牌: 沉默，除非紧急"
    - "警示牌: 评估后决定，允许高风险绕过"

  wake_conditions:
    - "用户主动询问"
    - "任务关键节点"
    - "系统检测到异常"
```

### 示例2: 创意工作保护

```yaml
creative_work_protection:
  # 检测创意工作信号
  signals:
    - "当前任务类型: 写作/设计/构思"
    - "用户正在编辑非格式化内容"
    - "最近活动: 大量文本输入"

  silence_policy:
    - "所有非必要提醒: 沉默"
    - "状态更新: 静默合并"
    - "低优先级信息: 延后1小时"

  exception:
    - "安全问题: 立即告警"
    - "用户明确请求反馈"
```

### 示例3: 决策过程保护

```yaml
decision_process_protection:
  # 检测决策过程信号
  signals:
    - "用户正在查看选项比较"
    - "最近活动: 多选项切换"
    - "任务标记: 决策中"

  silence_policy:
    - "推荐牌: 沉默，决策后发送"
    - "不相关信息: 沉默"
    - "辅助信息: 静默收集团队，直到决策完成"

  wake_conditions:
    - "用户做出决策"
    - "决策超时（30分钟）"
    - "用户主动请求"
```
