# launch-checklist (上线前20项检查清单)

## L0: 一句话描述 (≤15字)
上线前必检20项，不漏关键项

## L1: 使用场景 (50-100字)
在产品正式上线/发布前，逐项检查这20个检查点。每一个"未完成"都是潜在风险。完成所有检查项后，你就可以有信心地说：产品已经准备好了。

### 逐项检查说明

#### 核心价值 (4项)

**□ 01 客户3分钟内理解产品**

```
验证方法: 给一个不了解你产品的人看首页，计时。
- 30秒内：他们能说出产品是做什么的吗？
- 1分钟内：他们能说出谁应该用它吗？
- 3分钟内：他们能说出为什么它比别的强吗？

❌ 未通过: 产品定位不清晰，首页需要重新设计
✅ 通过: 用户能快速理解价值主张
```

**□ 02 客户5分钟内完成注册**

```
验证方法: 实际走一遍注册流程，记录每一步。
- 注册步骤数: ___步
- 每步所需信息: ___
- 总时间: ___分钟

❌ 未通过: 注册步骤>3步，或需要太多信息
✅ 通过: 邮箱+密码即可注册，步骤≤3步
```

**□ 03 客户10分钟内体验核心价值**

```
验证方法: 新用户注册后，第一次体验核心价值需要多久？

❌ 未通过: 用户需要探索>10分钟才能用到核心功能
✅ 通过: onboarding引导用户直接到达核心功能
```

**□ 04 客户愿意向朋友推荐**

```
验证方法: 问自己/测试用户："你会把这个产品推荐给朋友吗？"

✅ NPS > 0: 用户有推荐意愿
✅ NPS > 30: 推荐意愿较强
✅ NPS > 50: 推荐意愿很强
```

#### 商业闭环 (4项)

**□ 05 支付已接通**

```
验证方法: 实际完成一次支付测试。

✅ Stripe/支付宝等已开通并测试通过
✅ 支付后状态更新正确
✅ 收据/确认邮件已发送
✅ Webhook处理正常（如适用）
```

**□ 06 退款政策已写明**

```
验证方法: 检查是否有退款政策页面。

✅ 退款条件已写明
✅ 退款流程已说明
✅ 退款时限已明确
```

**□ 07 服务条款和隐私政策已发布**

```
验证方法: 检查footer是否有链接，页面内容是否完整。

✅ 服务条款已发布
✅ 隐私政策已发布
✅ GDPR/CCPA合规（如面向欧盟/加州用户）
```

**□ 08 客户能联系到真人**

```
验证方法: 检查联系渠道是否有效。

✅ 邮件地址可联系（不是noreply）
✅ 响应时间承诺已说明
✅ 支持渠道已验证（至少一个能联系到你）
```

#### 技术底线 (4项)

**□ 09 核心页面加载<3秒**

```
验证方法: 用PageSpeed Insights测试主要页面。
- 首页: ___秒
- 核心功能页: ___秒
- 注册页: ___秒

目标: 所有页面 < 3秒
⚠️ 警告: 3-5秒
❌ 未通过: >5秒
```

**□ 10 注册/登录无bug**

```
验证方法: 测试以下场景各3遍。
- ✅ 正常注册流程
- ✅ 邮箱格式错误
- ✅ 密码强度不足
- ✅ 重复邮箱注册
- ✅ 正常登录
- ✅ 错误密码登录
- ✅ 忘记密码流程

❌ 未通过: 任一场景有bug
```

**□ 11 移动端可用**

```
验证方法: 在手机上测试核心流程。

✅ iOS Safari: 核心流程可完成
✅ Android Chrome: 核心流程可完成
✅ 响应式布局正常显示
⚠️ 警告: 部分功能在移动端体验不佳（但不影响核心）
```

**□ 12 关键数据有备份**

```
验证方法: 确认备份策略。

✅ 数据库每日备份
✅ 文件/上传内容备份
✅ 备份可恢复（已测试）
✅ 最近备份时间: ___
```

#### 获客准备 (4项)

**□ 13 有1条让人想分享的内容**

```
验证方法: 你能立刻说出这条内容是什么吗？

✅ 能说出：___
✅ 不能说出：需要准备内容营销策略
```

**□ 14 有1个收集邮箱的入口**

```
验证方法: 确认有邮箱订阅入口。

✅ 在首页/关键页面有邮箱输入框
✅ 订阅后有确认邮件
✅ 已准备好邮件序列（即使是一条欢迎邮件）
```

**□ 15 知道前10个客户在哪里**

```
验证方法: 列出前10个客户的具体来源。

1. ___
2. ___
3. ___
...

✅ 能列出5个以上具体渠道
⚠️ 不确定: 需要做用户调研
```

**□ 16 定价经过竞品对比**

```
验证方法: 对比竞品定价。

竞品A: $___/月 vs 你的: $___/月
竞品B: $___/月 vs 你的: $___/月
竞品C: $___/月 vs 你的: $___/月

✅ 定价有明确理由（更低/更高/差异化）
⚠️ 没研究过竞品定价
```

#### 法律合规 (4项)

**□ 17 明确的数据存储政策**

```
验证方法: 在隐私政策中确认。

✅ 数据存储位置已说明
✅ 数据保留期限已说明
✅ 数据删除政策已说明（GDPR权利）
```

**□ 18 明确的服务限制**

```
验证方法: 如果有使用限制，清晰告知用户。

✅ 无使用限制: 无需说明
✅ 有使用限制: 在服务条款中明确说明
   - API调用限制: ___
   - 存储限制: ___
   - 用户数限制: ___
```

**□ 19 有紧急联系信息**

```
验证方法: 确认在产品中有紧急联系信息。

✅ 安全问题联系: ___
✅ 服务中断联系: ___
✅ 法律问题联系: ___
```

**□ 20 准备好客户支持时间**

```
验证方法: 诚实评估你能投入的支持时间。

承诺响应时间: ___
实际可用时间: ___

✅ 承诺≤实际
⚠️ 承诺>实际: 需要调整承诺或自动化支持
```

### 关键心态

> **上线不是结束，而是开始**。这份检查清单的目标不是让你完美，而是让你有准备地开始。用户的真实反馈会告诉你什么真正重要。不要等到完美再上线，在有准备的情况下尽快上线，然后迭代。
