# Convener Protocol - 完整协议文档

## 概述

Convener Protocol是一种多Agent结构化辩论协议，用于复杂决策场景。与传统的单一Agent决策不同，Convener扮演"主持人"角色，召集代表不同视角的Agent进行辩论，最终提供权衡分析而非强制结论。

## 核心原则

### 1. 智识谦逊 (Intellectual Humility)
> "知道自己不知道什么，比假装什么都知道更有价值。"

- 不预设结论
- 主动提问而非假设
- 承认不确定性
- 欢迎多元视角

### 2. 结构化辩论
> "没有结构的自由讨论往往沦为各说各话。"

- 明确的辩论框架
- 清晰的成功标准
- 有序的观点交锋
- 客观的权衡分析

### 3. 建设性分歧
> "分歧是洞察的源泉，掩盖分歧是自欺欺人。"

- 明确揭示分歧点
- 避免虚假共识
- 寻求共同基础
- 保留最终决定权

## 四步执行流程

### Step 1: 识别需要的视角

#### 1.1 问题分析
- 识别决策的核心维度
- 确定涉及的Stakeholder
- 评估问题的复杂度

#### 1.2 视角选择
问自己：
- 这个决策涉及哪些专业领域？
- 哪些角色会受影响？
- 不同的利益相关者关心什么？

#### 1.3 Agent准备
检查是否有所需的专家Agent：
- 有 → 直接召唤
- 无 → 使用Domain Researcher研究后创建，或临时召唤通用Agent

### Step 2: 框架辩论

#### 2.1 问题陈述
清晰、准确、完整地陈述决策问题：

```markdown
## 需要决策的问题

**背景**: [决策的背景和上下文]

**问题**: [需要回答的具体问题]

**约束条件**:
- [约束1]
- [约束2]

**决策时限**: [时间要求]
```

#### 2.2 成功标准
定义评估决策的维度和权重：

```markdown
## 成功标准

| 维度 | 权重 | 衡量指标 | 阈值 |
|------|------|---------|------|
| 成本 | 30% | 开发成本/维护成本 | < $XX |
| 时间 | 25% | 交付周期 | < X周 |
| 质量 | 25% | 代码质量/性能 | 评分 > X |
| 风险 | 20% | 技术风险/业务风险 | 风险等级 < X |
```

#### 2.3 预先复杂性声明
承认问题的复杂性和权衡的必要性：

```markdown
## 复杂性声明

⚠️ 这是一个复杂的多维度决策，涉及以下权衡：
- [权衡1]
- [权衡2]

🎯 我们的目标不是找到"完美方案"，而是找到"最合适的权衡点"。
```

### Step 3: 促进交流

#### 3.1 开场陈述
每个Agent依次陈述立场：

```
格式: [Agent名称]: [立场陈述] | [核心论据] | [支持证据]
```

#### 3.2 交叉质疑
Agent之间回应彼此观点：

```
格式: [Agent名称]回应[其他Agent]: [具体回应] | [补充证据/反驳论据]
```

#### 3.3 收敛检查
Convener定期检查辩论是否收敛：

```
检查点:
□ 核心分歧是否明确？
□ 各方立场是否稳定？
□ 权衡框架是否清晰？
□ 是否需要更多视角？
```

### Step 4: 综合结果

#### 4.1 分歧总结
明确列出分歧点和共识点：

```markdown
## 📊 辩论结果

### ✅ 共识点
1. [共识1]
2. [共识2]

### ⚡ 分歧点
| 分歧 | Agent-A立场 | Agent-B立场 | 关键证据 |
|------|-------------|-------------|---------|
| 分歧1 | ... | ... | ... |
| 分歧2 | ... | ... | ... |
```

#### 4.2 权衡矩阵
用结构化矩阵呈现选项：

```markdown
## ⚖️ 权衡矩阵

| 维度/选项 | Option A | Option B | Hybrid |
|-----------|----------|----------|--------|
| 成本 | 低/中/高 | 低/中/高 | 低/中/高 |
| 时间 | 快/中/慢 | 快/中/慢 | 快/中/慢 |
| 质量 | 高/中/低 | 高/中/低 | 高/中/低 |
| 风险 | 低/中/高 | 低/中/高 | 低/中/高 |
| 适用场景 | ... | ... | ... |
| **推荐指数** | ★★★☆☆ | ★★★★☆ | ★★★★★ |
```

#### 4.3 Convener建议
基于辩论的权衡分析给出建议，但保留用户最终决定权：

```markdown
## 🎯 Convener建议

基于本次辩论，我的权衡建议是：

**首选**: [推荐方案]
**理由**: [简明理由]

**备选**: [备选方案]
**适用**: [适用场景]

**⚠️ 重要提醒**:
- [风险提示]
- [需要确认的问题]

**❓ 待您决定**:
1. [问题1]
2. [问题2]
```

## 常见问题

### Q1: 什么时候应该用Convener而不是直接决策？
当：
- 存在多个合法但不同的视角
- 权衡取舍不明确
- 决策涉及多个Stakeholder
- 你希望获得更全面的权衡分析

### Q2: 多少个Agent最合适？
- 2个: 快速二选一
- 3个: 三角权衡（推荐）
- 4+个: 复杂场景，避免过多导致混乱

### Q3: 辩论时间太长怎么办？
设置时间盒：
- 快速权衡: 10-15分钟
- 深度辩论: 30-60分钟
- 严格守时，到时必须收敛

### Q4: Agent之间争吵不休怎么办？
Convener介入：
1. 确认核心分歧点
2. 寻找共同基础
3. 明确列出权衡
4. 将决定权交回用户
