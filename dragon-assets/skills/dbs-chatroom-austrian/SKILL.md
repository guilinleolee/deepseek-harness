# dbs-chatroom-austrian

## L0: 一句话描述
奥地利学派追问——基于边际效用递减和主观价值论，通过Socratic追问链挖掘深层需求。

## L1: 使用场景
当用户提出表面需求时使用。通过"为什么→然后呢→还有呢"三连追问，揭示真正的痛点和价值主张。解决需求表面化、信息不对称问题。

## L2: 详细文档

### 核心能力
基于奥地利学派经济学（边际效用、主观价值、机会成本），通过"边际追问→主观价值→机会成本"三步，挖掘用户的深层需求和真实价值判断。

### 奥地利学派追问模型

```
┌─────────────────────────────────────────────────────────────┐
│ 奥地利学派三连追问                                        │
├─────────────────────────────────────────────────────────────┤
│ 第一问：为什么？                                           │
│   - "你为什么想要这个？"                                  │
│   - 追问到边际效用递减的原点                               │
│   - 区分"想要"和"需要"                                   │
│                                                             │
│ 第二问：然后呢？                                           │
│   - "然后对你意味着什么？"                                │
│   - 追踪主观价值的连锁反应                                 │
│   - 揭示机会成本的真实权衡                                 │
│                                                             │
│ 第三问：还有呢？                                           │
│   - "除了这个，还有什么？"                                │
│   - 挖掘隐藏的替代方案                                     │
│   - 暴露需求的完整光谱                                     │
└─────────────────────────────────────────────────────────────┘
```

### 边际效用递减追问树

```
┌─────────────────────────────────────────────────────────────┐
│ 边际效用递减树                                            │
├─────────────────────────────────────────────────────────────┤
│ 初始需求：用户说"我想要X"                                 │
│                                                             │
│ 第一层追问（边际效用）                                     │
│   "为什么想要X？" → 得到"因为Y"                          │
│   评估：Y的价值是否递减？                                  │
│                                                             │
│ 第二层追问（主观价值）                                    │
│   "Y对你意味着什么？" → 得到"Z"                         │
│   评估：Z是主观的还是客观的？                              │
│                                                             │
│ 第三层追问（机会成本）                                    │
│   "如果选Y，放弃什么？" → 得到"W"                        │
│   评估：W的价值是否超过Y？                                │
└─────────────────────────────────────────────────────────────┘
```

### 主观价值判断矩阵

| 维度 | 强主观 | 弱主观 | 追问方向 |
|------|--------|--------|---------|
| **情感价值** | 个人偏好、审美 | 通用标准 | "这个对你特别吗？" |
| **功能价值** | 效率提升、便利 | 行业基准 | "能节省多少时间？" |
| **社会价值** | 身份认同、地位 | 群体规范 | "别人怎么看？" |
| **发展价值** | 成长潜力、自我实现 | 普遍需求 | "长期看有什么变化？" |

### 追问话术库

```markdown
边际效用追问：
  "这个对你来说有多重要？"
  "如果只能保留一个，你会选哪个？"
  "还有什么东西能达到类似的效果？"

主观价值追问：
  "这个价值是通用的还是你个人的感受？"
  "不同的人会怎么看这个问题？"
  "如果换一个场景，你的判断会变吗？"

机会成本追问：
  "选这个意味着放弃什么？"
  "如果不选A，能选什么替代方案？"
  "这个决定会锁定你多久？"

收敛追问：
  "现在回头看，最核心的是什么？"
  "如果只能做一件事，是什么？"
  "你的真实优先级是什么？"
```

### 需求澄清流程

```
Step 1: 初始陈述
  记录用户的原始需求，不做判断

Step 2: 第一轮追问（为什么）
  应用"为什么"追问链
  标记每个回答的边际效用点

Step 3: 第二轮追问（然后呢）
  应用"然后呢"追问链
  追踪主观价值的连锁反应

Step 4: 第三轮追问（还有呢）
  应用"还有呢"追问链
  挖掘替代方案和隐藏需求

Step 5: 价值排序
  根据边际效用递减原则排序
  识别核心价值主张

Step 6: 需求确认
  总结核心需求，征求用户确认
```

### 天龙引擎协同

| 天龙岗位 | 协同方式 |
|---------|---------|
| **00分析师** | 追问链→需求澄清→问题重构 |
| **01调研师** | 边际效用分析→价值判断追踪 |
| **dbs-diagnosis** | 追问结果→诊断输入 |
| **dbs-deconstruct** | 澄清需求→解构为子任务 |
| **dbs-goal** | 核心价值→目标设定 |

### 使用命令

```bash
/dbs-austrian                # 启动奥地利学派追问
/dbs-austrian "用户需求"     # 直接分析
/dbs-austrian --deep         # 深度追问模式（5轮）
/dbs-austrian --quick        # 快速澄清（2轮）
```

### 自检清单

- [ ] 第一问"为什么"被完整回答了吗？
- [ ] 追问链追踪到了边际效用递减点吗？
- [ ] 主观价值被显式表达了吗？
- [ ] 机会成本被明确分析了吗？
- [ ] 核心价值主张被用户确认了吗？
- [ ] 替代方案被充分探索了吗？

### 禁忌

- ❌ 跳过"为什么"直接执行表面需求
- ❌ 用自己的假设代替用户的真实价值判断
- ❌ 追问只停留在表面（问一次就停）
- ❌ 忽视机会成本（只算收益不算代价）
- ❌ 强制收敛（逼迫用户立刻做决定）
