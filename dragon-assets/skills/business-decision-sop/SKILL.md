# Business Decision SOP - 商业决策标准流程

> 来源：openclaw-strategist (https://github.com/wade56754/openclaw-strategist)
> 集成时间：2026-03-15

## 功能

结构化商业决策流程，从情报收集到明确建议的完整SOP。

## 触发词

- `/business-decision`
- "该不该做XX"
- "商业机会"
- "进入新市场"
- "要不要做"

## 决策复杂度路由

| 条件 | 流程 |
|------|------|
| <¥150 且 <1周 且 可逆 | ⚡ 快速版：可逆？→ 最坏能承受？→ 行动 |
| ¥150-¥1500 或 1周-1月 | 📋 标准版：完整SOP |
| >¥1500 或 >1月 或 不可逆 | 📊 完整版：标准版+情景规划+决策存档 |

## 完整SOP流程

```
Step 0: 双向门/单向门判断
   - 双向门（可逆）→ 可快速决策
   - 单向门（不可逆）→ 完整分析

Step 1: 深度情报收集（并行）
   1a. 竞品情报
   1b. 案例研究
   1c. 历史决策检查

Step 2: Hormozi 四要素筛查
   - Pain（痛点）：用户痛点有多痛？
   - Purchasing Power（购买力）：目标用户付得起吗？
   - Easy to Target（易触达）：能找到目标用户吗？
   - Growing（增长）：市场在增长吗？

   → 3个不通过 = 建议不做

Step 2.5: 假设拆解 + 压力测试
   Q1 — 隐性共识：市场里没人说出口的真相是什么？
   Q2 — 三大核心假设 + 崩塌条件 + 置信度
   Q3 — 5个投资人压力测试问题

Step 3: Pre-mortem（事前验尸）
   假设3个月后失败了——最可能的原因是？

Step 4: 资源匹配
   - 现有资源盘点
   - 能力匹配度
   - 需要补充的资源

Step 5: 明确建议
   - 建议：做/不做/等条件
   - 置信度：高/中/低
   - 第一步行动：具体可执行
```

## Hormozi四要素详解

| 要素 | 核心问题 | 通过标准 |
|------|---------|---------|
| **Pain** | 用户痛点有多痛？ | 必须是"止痛药"而非"维生素" |
| **Purchasing Power** | 目标用户付得起吗？ | 有明确的付费能力证明 |
| **Easy to Target** | 能找到目标用户吗？ | 有明确的触达渠道 |
| **Growing** | 市场在增长吗？ | 市场规模年增长>20% |

**判断规则**：
- 4个全通过 → 强烈推荐
- 3个通过 → 可以做，注意风险
- 2个通过 → 需要更多验证
- 1个通过 → 建议不做
- 0个通过 → 坚决不做

- **50-01 产品策划**：假设压力测试作为验证方法

## 使用示例

```bash
# 触发商业决策SOP
"我该不该开始做TikTok Shop?"

# 军师会：
# 1. 检查知识库中TikTok Shop相关案例
# 2. 运行Hormozi四要素分析
# 3. 压力测试3个核心假设
# 4. 事前验尸："3个月后你失败了，因为..."
# 5. 与你当前资源进行匹配
# 6. 给出明确建议 + 置信度
```

## 硬性规则

1. **必须先调研** - 没有数据不分析
2. **至少2个独立来源** - 交叉验证
3. **禁止"看情况"** - 必须给出明确建议
4. **必须标注置信度** - 高/中/低
5. **重大决策必须存档** - decisions/目录
