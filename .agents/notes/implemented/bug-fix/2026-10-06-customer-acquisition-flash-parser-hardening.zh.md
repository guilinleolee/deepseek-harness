# 获客插件 flash 模型解析器加固

Status: implemented

[English](2026-10-06-customer-acquisition-flash-parser-hardening.md) | 中文

## 背景

P1 抽取器与 P1/P3 打分器调用 flash 档模型，并按冻结的字段契约把回答解析为严格 JSON。对接真实 DeepSeek 端点时，原始回答在实质正确的前提下反复出现四种漂移：契约键的中文名回显（"公司名称" 而非 `company_name`）、字符串值内的裸换行、结构位置上的全角分隔符（，：、）、以及整个回答被包进随意的自然语言键（"抽取结果"…）。严格解析把这些全部拒之门外，真实 API e2e 在人工会认可的输出上失败。

## 决策

- **在解析缝隙处一次性修复，且只放一处。** `repairJsonBody` 是单趟字符串状态扫描：字符串内只转义裸换行、其余原样放行；字符串外把全角分隔符改写为 JSON 等价物。两件事共用一趟扫描才同时安全——朴素的全局正则分不清结构位置的 `，` 和 预算50万，3天答复 里的 `，`，而且数字前的分隔符（"score"：85）也必须修复。打分器复用同一函数。
- **漂移键经匹配表归一。** `canonicalKeyOf` 把中英文键变体映射到契约键；解析沿单键对象包装下钻（至多三层），逐层重新归一，直到某一层真正携带字段键。
- **漂移进 notes，绝不静默。** 未知的 `decision_role` 取值和未识别的键被丢弃但记入输出的 `notes`；缺 `company_name` 时注明模型实际输出的键。操作者能看到模型发明了什么。
- **一次自愈重试。** 解析失败后服务端用更硬的指令（严格只输出一个 JSON 对象，键名用英文契约键名）重发一次；再次失败即响亮报错。

## 否决

- **只靠提示词约束** —— flash 模型无论提示词多硬都会漂移；对每次漂移都重试会让延迟翻倍，而这是一个确定性的修复。
- **宽容 JSON 解析器（json5 一类）** —— 它会接受散文和带注释的正文；非 JSON 输出必须照样响亮失败，审计轨迹才能记录失败。
- **静默丢弃未识别键** —— 漂移恰恰是模板失配时操作者最需要看见的东西。

## 后果、风险与取舍

修复只作用于结构位置，值内文本的全角标点原样保留；字符串状态扫描的双向行为都有测试钉住。键归一由表驱动——表外的中文别名落入 `notes` 而非字段。重试只在失败场景多花一次模型调用。修复无法挽回的输出在重试一次后仍以友好报错拒绝。
