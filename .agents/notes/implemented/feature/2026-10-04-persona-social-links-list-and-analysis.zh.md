# Agent Note: 画像向导的社媒链接改为按平台固定的列表，最后一步获得一键社媒主页分析

Status: implemented

[English](2026-10-04-persona-social-links-list-and-analysis.md) | 中文

## 问题

向导第 2 步把每条社媒链接渲染成"下拉框 + 输入组"的行：平台的 `<select>` 会展开盖住表单（实测吐槽点），每行还要求填写主页链接根本配不上的账号简介；而"添加 / 移除 / 选平台"这套行机制表达的只是"平台 → 链接"——一个被平台枚举固定死的映射。与此同时，最后一步无法使用这些链接：用户填好了社媒主页，分析却从不读它们。

## 决策

- **第 2 步是固定列表：每个平台一行带标签的链接输入，无下拉、无简介、无增删。** 行由冻结的 `PERSONA_PLATFORMS` 表按共享中文标签渲染，列表与选择器词汇不可能漂移。`setLinkUrl(platform, url)` 对底层 `PersonaLink` 行做 upsert——行仅在其 URL 非空时存在、每平台至多一行——`inputFromForm` 丢弃无 URL 的链接，空白行永不落盘。`bio` 字段保留在 wire 类型上（已存储条目保留其值；报告事实仍渲染它），但新 UI 不再写它。向导草稿缓冲保持版本 1：表单形状未变，旧草稿可加载。
- **新 `social` AI 操作在最后一步分析主页。** 第 4 步页脚在通用补全按钮旁新增「分析社媒主页」——显式触发，符合插件"AI 不隐式进保存路径"的规则，且可重复执行。网关逐条抓取链接（与官网面同一抓取器：声明 UA、30 秒截止、2 MiB 上限、仅 http(s)），把每个可读页面按平台标签分节，单节 2 500 字符上限保证每条链接公平分享模型输入；登录墙或空白页被跳过——单个不可达主页不拖垮整批，全部不可读时才报错。合并分节后跑一次提取调用（`persona-social@1`，与官网面同一 JSON 契约），提示词说明素材是碎片化的主页文本、要求保守且有依据的取值。抓取的分节是临时的：与官网面不同，不回写表单——链接本身已存储，只有被采纳的字段进入条目。

## 被否决的备选

**进入第 4 步时自动运行分析。** 否决：每次导航进该步都会花一次模型调用加 N 次页面抓取，且违背审计钉下的显式触发约定（"AI 显式触发不进保存主路径"）。按钮就在最后一步，正是需求所指的位置。

**只渲染第 1 步选中的平台。** 否决：用户可能拥有自己并不运营的平台账号；固定列表让这种表达保持可能，也无需添加按钮。每平台一行的列表同时就是对下拉吐槽的直接回应。

**像官网面那样持久化抓取的社媒文本。** 否决：至多八个主页的临时文本会撑爆条目；官网面持久化是因为其文本要喂报告事实，社媒洞察经由被采纳的字段到达。

## 后果

代价：固定列表高八行，而旧表单每条已添加链接仅一行——用纵向空间换零隐藏状态；社媒平台的反爬意味着部分抓取只会拿回登录壳，跳过逻辑静默吸收（用户看到更少的分节，而非报错）。同平台存有两条链接的旧数据（先于唯一性规则）只显示第一条，且在该平台行被编辑前两条都保留。验证：两包共 61 个测试（按平台 upsert、空行过滤、`social` 操作的跳过/拒绝用例、第 2 步列表接线、第 4 步按钮流），两包类型检查干净，触及文件 oxlint 干净，typert 工件已为新 wire 成员再生。
