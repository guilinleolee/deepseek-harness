# Agent Note：三个结构性断点收口——对标收录进选题库、发布交接带上创作选题、对标账号视图补导航入口

Status: implemented

[English](2026-09-28-dsh-content-studio-loop-closure.md) | 中文

## 问题

2026-09-27 的总需求审计留下四个跨栏目断点，其中三个在代码侧：对标视图的【收录为选题】仍只写 `idea-<id>.md` 资产文件（规划自己的占位目标，选题库上线后一直没切换）；创作→发布交接硬编码 `topicId: null`，发布视图的回流按钮是不可达的死代码；已完整实现的 `CompetitorsView` 在 `NAV_ITEMS` 里没有条目——渲染分支背后的孤儿视图。本变更收口这三个；第四个（工作台数据源过窄）留给总览补齐工作。

## 决策

- **对标切换执行规划自己的"仅切换写入目标"。** `competitorWorkToTopicInput`（纯函数，`competitors.ts`）构建 `benchmark` 来源的 `TopicItemInput`：作品 id 作 `refId`、有链接带链接、创建时快照携带标题与第一条差异化选题建议。`addIdea` 先按 `refId` 查库再 put——一个对标作品只产出一条选题；然后照旧写 idea 文件与 `collectedIdeaRef` 标记，既有的禁用/重试 UX 保留，审计留痕保留。半途失败的对局会收敛：重试时查到已入库的选题、跳过 put、只补标记。共享的 `topics` 面走注入的对标面，不另开网关句柄。
- **发布交接把创作选题端到端带上。** `PickedManuscript` 增加可选 `topicId`；创作视图在编辑器有关联选题时发送 `manifest.topicRef?.topicId`；发布表单存入 `NewTaskForm` 并传给 `createTask`。手动建任务（从稿件卡片出发）带 `null`——任务只回流它真正出身的那条选题。非空 id 下，此前不可达的回流按钮接通，经既有的幂等写入把选题推到 `done`。
- **导航行就是它承诺的一行。** `competitors` 排在对标能力切片之后；locale 键早已钉好待用。

## 与规划文本的偏离

无新增。对标切换执行的是对标 v2 规划的既定指令（"选题库交付后仅切换写入目标"），交接 topicId 是审计自己的断点修复，双写（选题 + idea 文件）保留 v2 的标记语义而非丢弃。

## 备选方案

**选题库存在后去掉 idea 文件。** 否决：该文件是重试禁用所依赖的按作品收集标记，也是主题本地的一份审计副本；选题快照在库侧携带同样内容，文件零成本且让两侧投影都诚实。

**回流到独立的已发布选题状态。** 不在本次范围：`TopicStatus` 没有 published 成员，审计明确把该契约决策推迟——回流继续落到 `done`，待状态联合重新评估。

## 后果

跨栏目闭环真正打通：对标→选题库、选题→创作→发布→选题回流全部成为活路径。代价：发布表单信任交接来的 topicId（关联选题过期只在回流写入被拒时暴露）；`addIdea` 写前读——每次收录多一次 `topics.list()`，工作台规模下可忽略。验证：三包 581/581（新增三个 builder 用例）、客户端 typecheck 清零、bundle 重建。
