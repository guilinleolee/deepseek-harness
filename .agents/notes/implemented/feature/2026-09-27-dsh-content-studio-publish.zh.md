# Agent Note：发布视图冻结二期 MCP 发布包，而不是假装上传成功

状态：已实现

[English](2026-09-27-dsh-content-studio-publish.md) | 中文

## 问题

内容创作已有五个上线视图（信息收集、对标账号、选题库、画像、创作），但没有分发故事：定稿躺在主题根目录，没有任何环节把它送到目标平台。原始需求提示词（v1）承诺真实的多平台发布，但真实上传通道是不存在的二期 MCP 服务；定时发布没有后台进程来触发；v1 还把账号卡片放进 localStorage——既撞上本插件自己"跨端状态禁 localStorage"的共同教训，又没有先冻结数据契约。重写版（`D:\dsh-content-studio\docs\publish-dev-prompt-v2.md`）把整个栏目收敛到一个诚实的问题上：当没有任何东西真的被上传时，"发布"意味着什么？

## 决策

- **诚实的期语义。** 执行发布构建冻结的 `PublishPackage`（每个平台腿的衍生稿必须已存在，否则构建拒绝），任务进入终态 `recorded`，UI 文案明示"发布通道未接入"。没有任何东西假装上传发生过。二期的执行态（`executing` `partialSuccess` `success` `failed`）刻意不出现在状态并集中——闭联集只含四个月一期状态，后续阶段扩展时无需重新审计消费方。
- **主题级 sidecar、全局索引、`.dsh-output.json` 零接触。** 任务存在 `assets/_publish.json`（`formatVersion 0`，未知版本拒载），与 gather/create/persona 的 sidecar 同款；全局 `_publish-index.json` 是供跨主题历史列表使用的投影，与清单写入在同一把写者锁内刷新，损坏时可全量扫描重建。衍生稿落在 `assets/publish/<taskId>/<platformId>.md`，两个 id 都有路径守卫。新增的 `readPublishSource` 读面永远读不到元数据文件。
- **账号卡片落盘，不进 localStorage。** `_publish-profiles.json` 存别名、启用状态与适配偏好——设计上就没有凭据，所以没有任何理由阻止持久化；v1 的 localStorage 方案就是本插件共同教训的反例。平台规则是数据驱动的注册表（`publish/model.ts` 的 `PLATFORM_PROFILES`）；新增一个平台等于追加一行，这正是"后续支持海外平台"成为真话的原因。
- **只追加的 attempts 是幂等的基础。** 每次适配、手改、记录都追加一条 `attempts`；重试新增条目，从不改写日志。一次适配失败只波及自己的平台腿（失败隔离）；队列单并发、只对限速重试（共享策略）；适配计入 create 配额门的生成额度——freemium 分界保持在一处。

## 与方案文本的偏差

- 方案把任务元数据写进 `.dsh-output.json`；实际采用 sidecar，与此前列每一个视图对"schema 冻结"的裁决一致（也避开该文件的解析拒载门控）。
- 方案的回流目标状态"已发布上线"在选题库五态并集中不存在；回流经既有 `contentTopics.put` 写 `done`，复用创作视图的幂等路径。
- 本期的定时任务写入日历条目（`ScheduleItemInput` 新增可选字段 `publishTaskId`），打开视图时提示到期任务；没有任何自动触发——与对标账号视图一样，执行方案自己的反伪调度裁决。
- 违禁词预检直接用创作视图的本地 `banned-words.ts` 词库，不新建检查；方案里"上游读面不可达则隐藏"的降级适用于整个面板。

## 曾考虑的替代方案

**把任务元数据放进 `.dsh-output.json`。** 否决：该文件的 schema 对未知版本直接拒载，且它是内容库视图读取的作品级投影；把频繁变动的任务列表嵌进去会让分发变更与作品元数据耦合，还得对抗其余每个视图都用 sidecar 绕开的解析拒载门控。

**浏览器侧调度器自动触发到期任务。** 否决：在上传通道缺失时，自动触发只会把任务假装成已发布；而页面级定时器是一个关掉标签页就死掉的调度器。到期任务在打开视图时提示、由用户手动执行——与对标账号视图对监控采取的诚实裁决同款。

**记录时持久化 MCP 发布包。** 否决，改为按需构建：发布包是衍生稿与任务事实的纯投影，存副本会在任何一稿重新适配的瞬间漂移；`buildPublishPackage` 每次读盘新鲜构建，任何一腿缺失即响亮失败。

## 后果

分发闭环现在可以在没有任何上传通道的情况下端到端跑通：稿件池 → 任务 → 逐平台适配 → 手改 → 发布包构建 → `recorded` → 选题回流；除显式的 AI 适配外全部离线可用。代价：平台注册表本期只在客户端存在，AI 提示词的风格规则随请求携带（未来的服务端消费方需重新把它冻结进 wire 类型）；全局索引是缓存，其损坏重建路径是全库扫描；删除任务按契约保留衍生稿，清理是独立的手工动作。共享文件教训再次生效：创作视图只增加了一个可选的 `onSendToPublish` prop、studio 控制器一对 handoff、导航一项——在并行会话同仓库施工时，这是能合并的最小面。
