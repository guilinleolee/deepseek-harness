# Agent Note: 卡巴格管理台 v2 — 审计日志、登录安全、auditor 落地与配额点数模型

Status: implemented

[English](2026-09-25-kabage-console-v2-security-audit-quota.md) | [中文](2026-09-25-kabage-console-v2-security-audit-quota.zh.md)

## Problem

The console's original 9-section plan (v1) was reviewed against open-source peers (Open WebUI, LibreChat, one-api/new-api, authentik, Logto, FastGPT, Dify) and the DSH core's actual constraints. Four gaps mattered more than any missing page: (1) every console mutation — member create/disable/quota/reset, model/provider changes, instance ops, plugin jobs — left **zero audit trail**; (2) login had no rate limit and no password policy (the README itself flagged this); (3) the `auditor` role existed in the JWT role enum with **no pages and no API access**; (4) quotas counted raw tokens, which cannot express that different models differ in price by an order of magnitude, let alone per-department pricing. A revised plan, `卡巴格管理台栏目规划v2.md` (committed alongside), re-cuts the nav to 9 sections and specifies the audit taxonomy, security params, and the points-and-ratios quota model; this note covers its first two delivery phases.

## Decision

**Audit.** `platform/supervisor/audit.mjs` appends one JSON object per line to `data/audit.jsonl` through a serial promise chain (`fs.appendFile`; entries are `JSON.stringify`-serialized, so newlines/control characters in any field cannot break the line structure). Every event is `{ts, actor{account,role,ip}, action, target, result, detail}`; actions are namespaced (`auth.login_fail`, `member.reset_password`, `model.ratio_change`, `quota.exceeded`, `audit.export`, `security.config_change`, …). All 18 console mutation endpoints plus the three gateway auth outcomes are instrumented; deny (auditor mutation attempt) and fail (validation error, exception) paths are recorded too. Detail fields carry scalars only — old→new values for config-style changes — never password/key plaintext or session bodies. Query (`GET /console/api/audit`) and filtered export (`…/audit/export`, ndjson download) are open to admin and auditor; the export itself writes an `audit.export` event.

**Login security.** `security.mjs` keeps parameters in `data/security.json` (auto-created defaults: 15-min window / 10 failures / 15-min lockout / password ≥8 chars with ≥3 character classes / entity-name whitelist `^[\w@.\-…]{1,64}$` allowing Chinese department names). The gateway checks an in-memory per-`account+IP` sliding window before verifying credentials (rate-limited attempts write `auth.login_rate_limited`); password and name policies gate member create/update/reset at the data-entry functions, so console and CLI both refuse invalid values. Console security settings are editable from the new「安全与审计」page (admin-only writes, change events recorded).

**Auditor lands.** The console fence resolves the JWT role once, before dispatch: admin passes all; auditor passes pages, read-only GET APIs, and audit query/export; any mutation POST is 403「审计员为只读角色」and logged as a deny event; employee stays 403. Enforcement is centralized at the dispatch gate, not scattered per route case.

**Quota model v2.** Points replace raw tokens as the metering unit: `points = (inputTokens×modelRatio + outputTokens×modelRatio×completionRatio) × groupRatio`, with per-model ratios and per-department group ratios in `data/ratios.json` (defaults 1/3/1, edited inline on the models page and the new「部门与角色」page). The relay pre-deducts an estimate (request chars/4 input, `min(max_tokens,32768)` output) **into an in-memory pending map that never touches the ledger**, and the denial check is `booked points + pending ≥ monthlyPoints`; on response the real usage is booked directly and pending is released (settle / failure-refund / disconnect-refund are three mutually exclusive outcomes of one `settled` flag). A client disconnect destroys the upstream request (cancelling upstream generation), refunds the pre-deduction, counts `requests=1`, and logs `aborted:true` — a probe proved the pre-fix behavior leaked both the reservation and all token accounting on this everyday path. Accounts still carrying only the legacy `monthlyTokens` keep the old semantics (marked 旧制 in UI/CLI).

**Hardening found by adversarial review.** `__proto__`/`constructor`/`prototype` keys are rejected at ratio-write time, stripped by normalize, and treated as unset at resolve time (the write+normalize filtering alone still left a NaN path through `groups['__proto__']` hitting the prototype getter); `esc()` escapes quotes (reflected XSS via `?actor=`, stored XSS via department names); account mutations run behind a serial `withAccountLock` queue with tmp+rename saves.

## Alternatives considered

**Booking the pre-deduction into the ledger and denying on booked-points only** (the first implementation). Rejected: with usage-missing requests keeping their reservation, an attacker-controlled `max_tokens` permanently booked up to 3×10⁹ phantom points onto a victim account, and `max_tokens=1e308` produced `Infinity` that was silently dropped — free calls. The pending-map model keeps the ledger exact while still charging concurrent in-flight reservations against the denial check.

**On disconnect, letting the upstream response finish to settle normally.** Rejected: user cancellation should stop upstream generation (real cost), and "recovery" only worked when the upstream had already finished — an accounting semantic that differed by timing. Uniform "disconnect = refund pre-deduction, tokens unknown" is predictable and testable.

**Embedding the console into the DSH `:3080` web app** (v1 plan §5.4). Rejected on architecture: the web frontend is a prebuilt SPA that assumes the root path; there is no route or iframe mount point. The standalone console behind the host-routing gateway remains the only non-breaking integration, which is how the platform already ships.

**Adopting an off-the-shelf IAM (Casdoor/Logto) instead of the hand-rolled accounts.** Deferred, not rejected: it remains the stage-11 option if SSO demand materializes; integrating an external IdP with the per-user-instance gateway is a larger change than closing this phase's gaps.

## Consequences

Verified keylessly in the worktree: `test/security-audit-smoke.mjs` 39 (policy/rate-guard/audit/config), `test/quota-points-smoke.mjs` 40 (ratios resolution, unsafe keys, formula hand-checks), `test/auth-audit-http-verify.mjs` 85 — real HTTP flows against `test/mock-upstream.mjs` covering login audit paths, lockout, conservation (pre-deduct vs settle delta), ratio change next-request effect, points 429 with audit detail, disconnect refund, `__proto__` rejection at three endpoints, esc escaping, auditor read-only/403 matrix, and legacy-token hard-stop. An adversarial review pass (probe scripts, since deleted) drove the P0/P1 fixes above before commit.

Deferred, known: the login page shows a generic failure message for 429s (the specific copy is only in the JSON body); member rows lack last-login time/IP (derivable from the audit log later); the `add-account`/`set-password` CLI bypasses the password policy (admin bootstrap path); `audit.jsonl` has no rotation (export-and-archive is the process); the rate-limit map is in-memory and resets on daemon restart; logins POST without an Origin check (login CSRF, low risk behind SameSite=Strict); no CLI to migrate legacy `monthlyTokens` accounts to points (needs a ratio baseline first); a shared NAT exit makes the IP half of the lockout key collective. Stage 9+ (per-blueprint): instance-side tool RBAC via `ctx.tools.guard()` with `ctx.approval` events flowing back into the audit log, personal center, invite registration, 2FA/SSO/email.
