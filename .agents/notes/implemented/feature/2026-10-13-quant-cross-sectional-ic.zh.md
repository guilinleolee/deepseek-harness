# Agent Note：横截面 IC 在面板上评估因子

状态：已实现

[English](2026-10-13-quant-cross-sectional-ic.md) | 中文

## 问题

既有因子 IC 工具只回答一个窄问题——因子 X 能否预测标的 Y 自身的未来——走的是单标的时间序列 IC。因子研究的标准问题是横截面的：同一时刻，因子值的排序是否与各标的前视收益的实现排序一致？一个因子完全可能时间序列里很强、横截面上毫无区分力（甚至方向相反），只有面板视图能把这两种情况分开。

## 决策

- **新工具，而不是旧工具加模式。** `quant_factor_cross_ic`（第 18 个工具）启动一个后台任务，逐标的拉取K线（每标的一个内核子进程，2-10 只，`inspectCrossPanelCaps` 合规封顶——数组形状、去重、horizon 上限 1-20 并入既有 bar 与 broker-marker 规则）。旧的单标的 `quant_factor_ic` 保持原契约；两种 IC 分母不同，合并只会双双模糊。
- **纯面板数学放在 `paat/cross-ic.ts`。** `alignPanel` 求各标的日期交集（缺失日期丢行，共享日不足 2 天响亮失败）；`factorOnDates` 复用已审计的 `computeFactor` 且无前瞻；`crossSectionIC` 逐日计算因子值横截面与前视 h 日收益横截面之间的 Spearman；`summarizeIC` 聚合平均 IC、离散度、ICIR、正占比与 t 统计（IC 序列无离散度时按约定取 0）。四者均为表格级纯函数，单测不依赖内核。
- **报告自带判读纪律。** Markdown 声明横截面 IC 衡量的是"同一时刻横跨标的"的排序预测力（与时间序列含义不同），渲染聚合区块与最近六个截面 IC，并对照 |ICIR| ≥ 0.5 经验门槛给出直接结论——因子方向为负时另有反向提示。
- **JobKind `quant-cross-ic`，启动 envelope 与既有任务对齐。** 工具完全遵循 optimize/walk-forward 的任务模式：任务启动前完成预检校验，一个 AbortController 扇出到全部标的拉取，无 jobs 运行时时给友好 CONFIG envelope，启动卡片带 job id、面板、因子与收取提示。

## 考虑过的替代方案

**给 `quant_factor_ic` 加 `symbols` 数组。** 否决：该工具的参数、输出 schema 与合规规则都是单标的形状；原地加数组模式会让 schema 分叉，拒绝理由也说不清是哪个上限触发。

**面板计算下沉内核（一个新 op）。** 延期：内核已经交付已审计的逐标的K线；横截面只是对齐数组上的秩相关，TypeScript 算得完全一致。新内核 op 只会增加线上形状，不会改变任何一个数字。

**滚动窗横截面 IC（状态稳定性）。** 与其他滚动项一起延期：全面板聚合已经通过 IC 离散度暴露稳定性；分窗 IC 等消费者出现再做。

## 后果

代价：每次运行每标的一个内核子进程（至多 10 个），全部在一个可取消任务内。验证：quant 312 vitest 全绿——12 个新用例覆盖对齐（交集、排序、响亮失败）、完美排序 IC、退化与非法 horizon、null 摘要分支、报告两种结论、合规上限，以及工具任务生命周期全链路（拉取顺序、启动卡片、落定的 markdown）。工具数 17 → 18，注册断言、apply-spec 与 README 计数同步移动；双语 README 与 Agent Note 三件套已重新配对。
