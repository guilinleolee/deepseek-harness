# Agent Note：滚动 walk-forward 按窗口重新寻优

状态：已实现

[English](2026-10-13-quant-rolling-walk-forward.md) | 中文

## 问题

`quant_walk_forward` 只验证一次训练/测试切分：调用方只为一个参数选择拿到一条样本外路径。被点名的延期项是滚动窗口再寻优——对"每期重新选参数"这一真实交易方式的诚实检验。单次切分可能偏袒侥幸的参数对；滚动报告才能看出重选参数是否具备样本外生存能力。

## 决策

- **一个工具，一个新参数。** `quant_walk_forward` 新增 `windows`（2-10，合规封顶）；`windows ≥ 2` 将任务切换为扩展窗滚动。默认 `1` 逐字节保持已上线的单次切分行为——工具数保持 17，JobKind 保持 `quant-walk-forward`，既有调用方零感知。
- **扩展窗，几何可审计。** K线修剪到 `floor(n / (windows + 1)) * (windows + 1)`；第 0 段为初始训练段，其后每段依次是一个窗口的样本外测试。窗口 *i* 在其测试段之前的全部历史上重跑完整网格——包括更早的测试段——因此越晚的窗口在越多的历史上重新寻优，且任何窗口都看不到自己的未来。段长必须同时覆盖初始训练段与每个测试段的最宽慢线窗口。
- **聚合即结论。** 报告渲染逐窗表格（重选参数、训练收益、样本外收益、差距、夏普、回撤）加聚合区块：样本外收益均值/中位数、平均差距、正收益窗口占比，以及直接的结论——平均差距非负且正收益窗口过半读作样本外稳定，否则读作过拟合。免责声明点明承重重构：滚动样本外衡量的是*重选策略本身*，不是某对幸运参数。
- **合规把 `windows` 当一等上限。** `inspectRollingWindowsCap` 在任务启动前拒绝非整数与越界窗口数，并入既有 `quant_walk_forward` 规则链；`ROLLING_WINDOWS_LIMITS` 与其他硬上限同住 `compliance.ts`。
- **滚动运行不写结果快照。** 快照通道承载单次运行的全曲线报告；滚动任务产出的是聚合文档，快照 `kind` 的扩展等消费者出现再做。

## 考虑过的替代方案

**单独的 `quant_walk_forward_rolling` 工具。** 否决：两种模式共享网格、排名、任务生命周期与免责声明；第二个工具用一个整数的差异换来双倍表面积，还把模式选择推给模型。

**锚定（固定长度）训练窗。** 延期：扩展窗是更保守的估计（每窗更多训练数据），且不需要新的长度参数；在任何调用方提出需求前引入锚定窗只是多一个形状旋钮。

**并行执行窗口。** 否决：每窗网格是一个内核子进程，任务全程可取消；顺序窗口让中止语义平凡正确，内核扇出与已审计的单次切分路径完全一致。

## 后果

代价：一次滚动运行是 `windows` 次网格 + `windows` 次单回测（各一个内核子进程，封顶时最多 20 个）——启动 envelope 已说明形状，任务全程可取消。验证：quant 300 vitest 全绿——9 个新用例覆盖切分几何（等分切段、扩展训练窗、余数修剪、无前瞻）、滚动校验、合规上限、逐窗管线的调用顺序，以及工具级滚动任务与其聚合 detail 行。双语 README 已更新；延期项从"滚动缺失"改为"锚定窗与滚动快照"。
