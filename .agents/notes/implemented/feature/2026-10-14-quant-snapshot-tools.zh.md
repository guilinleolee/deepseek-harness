# Agent Note：快照生命周期工具——列表与经审核的删除

状态：已实现

[English](2026-10-14-quant-snapshot-tools.md) | 中文

## 问题

结果快照通道只有追加、没有模型侧表面：面板经 Remote 面读快照，但模型既看不到存了什么、也删不掉过期或误存的记录。滚动运行一次任务最多写 10 条，存活与否只由保留 50 条的修剪决定——探索性跑完想清理的调用方没有任何抓手。

## 决策

- **`quant_list_snapshots` 是读侧。** 面板数据源的模型可见投影：最新在前，id、标的、参数、头条指标（收益、回撤、交易数）与创建时间。渲染中 id 截断为 8 字符——足够在删除请求中引用，又不会让 UUID 刷屏。
- **`quant_delete_snapshot` 是经审核的删除，不是静默删除。** 持久域在设计上以追加为主，因此移除沿用与 PET 调仓相同的人工审核门：批准理由列明快照内容（标的、SMA 窗口、曲线点数、创建日期）加调用方自己的理由，只有 `allowed-once` 才继续。被拒响亮失败（`RISK`）、记录保持不变；id 缺失在任何审核请求之前就给友好的 `DATA` 错误。获准后，Remote 面下次读取就少一张卡。
- **批准携带内容，而非只有 id。** 审核者看到的是自己要删什么——只有 id 不构成知情的同意面。
- **工具数 18 → 20**，注册、apply-spec 与 README 计数同步；两个工具都落在既有合规 RULES 覆盖内（broker-marker 扫描适用；无数值参数，无需上限）。

## 考虑过的替代方案

**面板侧手动删除（一个按钮）。** 延期：面板在构造上只读，浏览器侧变更需要穿过宿主的独立审批路径——模型侧工具直接复用调仓已经在用的已审计 `dsh-user-approval` 接缝。

**跳过审核的 `force` 参数。** 否决：红线是持久域变更是经审核的动作；逃生门会让审核变成表演。

**按时间批量删除。** 暂缓：保留 50 的修剪已经限制表大小，批量移除只会放大一次误批的破坏半径。

## 后果

代价：静态无——工具是纯表读取与一次经审核的删除。验证：327 vitest 全绿——六个新用例（最新在前列表含指标、空列表、获准删除并校验批准载荷与表状态、被拒删除保持记录、缺运行时/agent 会话响亮失败、缺快照在任何审核请求前被拒）。双语 README 增两行并改二十工具计数；Agent Note 三件套已记录。
