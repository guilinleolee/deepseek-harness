# Agent Note: 参数寻优跑在 jobs 运行时上，每个内核进程算完整个被审计的网格

Status: implemented

[English](2026-10-07-quant-param-optimization.md) | 中文

## 问题

Phase 1 已确立重型回测工作不得长出守护进程："如果回测变重，jobs 运行时（phase 2 的参数寻优）是被认可的长任务路径，而不是守护进程。"参数网格寻优正是这个被点名的工作负载。直观做法——每个组合一个内核进程，或让工具阻塞地循环 `runBacktest`——会让一次请求拉起多达 200 个解释器，并在整个搜索期间占住模型的工具预算。另一种做法——把搜索做成 Python 内核里的独立引擎——会分叉插件刚审计完的成交模型。

## 决策

- **网格是一次内核请求，不是每组合一个进程。** 新的 `backtest_grid` 操作遍历调用方传入的 `(fast, slow)` 列表，对每个组合重新调用同一个被审计的 `run_backtest`，只返回指标——每组合的净值曲线与成交在线上被丢弃，使 200 个组合仍是一行有界响应。TS 侧（`src/pcpt/optimize.ts`）持有网格枚举、校验、排名与 Markdown 汇总，因此会话重放从同样的内核数字重新推导报告。
- **工具启动任务，而不是阻塞。** `quant_optimize_params` 先完成全部校验，然后在宿主 `ctx.jobs` 注册表（kind `quant-optimize`，经 `deps.jobs?.()` 每次调用解析，因为 jobs 服务可能在插件之后挂载）上启动一个可取消的后台任务。任务一次取回 K 线、发出一次 `backtest_grid` 请求，并以 `completed`（排名 Markdown）、`killed`（AbortController）或 `failed`（友好 detail）落定。组合里没有 jobs 运行时时，工具返回点名 `@deepseek-ai/dsh-jobs-local` / `dsh-tool-jobs` 的友好配置信封，而不是退化成阻塞调用。
- **门禁按工具的确切默认值解析网格。** 部分走私（只给 `slow_max: 250`、只给 `slow_step: 1`）会让解析后的网格爆表而每个可见字段都合法，因此 `inspectGridCaps` 从 `DEFAULT_GRID_SPEC`——工具应用的同一个冻结对象——重新推导生效轴，强制整数轴、窗口界限、轴内有序、快线整段严格低于慢线整段，以及 200 组合上限。`DEFAULT_GRID_SPEC` 与 `CONFIDENCE_LIMITS` 一样放在 `compliance.ts`，因为门禁必须持有它所依据的默认值；`FAST/SLOW_WINDOW_LIMITS` 随之迁移，经 `pcpt/backtest.ts` 转出口保持公共 API 稳定。
- **快照由 driver 驱动任务生命周期，而不是脚本化模型。** 完成通知的到达时机是后台任务转写唯一的不确定边；与其赛跑，headless driver 经 `ctx.tools.execute` 启动一次真实的 `quant_optimize_params` 调用、轮询 `job_output` 到落定，并经真实门禁走一次网格上限拒绝——与 pwsh 快照对 `run_in_background` 确立的模式一致。脚本化模型轮次保持不动。

## 备选方案

**每组合一个内核进程。** 否决：200 次进程拉起按每次 ~200 ms 计是一次搜索整整一分钟的纯解释器启动开销；每请求一进程的契约是为了无状态，不是为了扇出。

**TS 侧模拟器循环调用现有 `backtest` 操作。** 否决：同样的拉起开销，还要串行受工具的协作式截止约束。

**内核里独立的网格引擎。** 否决：插件的核心审计属性是一切模拟成交来自同一个成交模型；在参数搜索恰好放大信任面的时候分叉它，是最坏的时机。

**把寻优轮次脚本化进 mock 模型。** 否决：模型需要 `job_output` 轮次，其结果时机取决于任务落定与通知注入通道的赛跑；driver 拥有的阶段让转写保持确定，同时不削弱组合（注册表、内核、门禁全为真实路径）。

## 后果

代价：寻优报告只保留前 N 名（选中参数的完整曲线需要补一次 `quant_run_backtest`）；想要寻优的宿主必须组合 jobs 插件（缺失时工具友好失败）；门禁按默认值解析的网格检查意味着 `DEFAULT_GRID_SPEC` 的变更必须落在 `compliance.ts`——由构造保证，因为工具导入的是同一个对象。验证：新增 21 个 vitest 用例（纯网格函数、门禁规则、内核往返、任务生命周期含取消与失败），新代码全覆盖——包内套件 237 绿，另加内核 28 个 pytest（新增三例：网格与单次运行等价、网格校验、线上往返）；无钥快照增加 driver 阶段的寻优轮，断言排名报告、过拟合警告与拒绝。顺带修复一处既有损坏：快照的 `TOOL_CALL_SEQUENCE` 未随上一切片新增的因子轮更新，本次变更前分支头的快照测试本来就是失败的。延期：图表卡片与真面板仍是 Phase 3 点名的剩余项。
