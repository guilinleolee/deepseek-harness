# 获客运营 P3：培育文案 + 跟进 SOP

状态：已实现

[English](2026-10-05-customer-acquisition-p3-copy-sop.md) | 中文

## 背景

获客运营插件 P3 交付模块 4 与模块 5——A/B 两版的培育文案生成与跟进 SOP 任务编排——在 P1 合入、P2 以姊妹 geo 包落地之后。文案流复用 P1 确立的 PromptCompletion 端口与行级 AI 路由；SOP 流为确定性计算（无模型调用）。

## 决策

- **文案生成整体沿用 P1 的 AI 姿态。** 每个产物一次模型调用，经 PromptCompletion 端口：模板链（显式 id → 该类型启用 → 类型+行业 → 无行业 → 任一）、线索字段与知识注入、空输出严格拒绝、产物挂线索并记录模板 id。红线 3 成立：只出文本，无发送通道。
- **SOP 生成为确定性的节奏推算。** 模板中匹配线索意向等级的规则驱动每个跟进要点一条任务；`D+N` 偏移从节奏文本解析并排期；超出已解析偏移的要点收敛到最后一个偏移。未打分线索拒绝并提示先打分；公海线索需先领取。`todo_written` 恒 false——DSH 待办是 agent 自有的 `todo_write` 清单、无可写服务，设置开启时工具返回可直接转发的清单（平台事实已记录于 README）。
- **SOP 模板删除无引用守卫**——冻结的 sop_tasks schema 不含模板 id，删除不会孤立历史；已生成任务是独立行。文案模板保留引用守卫，因为生成产物记录了模板 id。
- **种子扩展同一 id 空间**——每个行业新增一套跟进 SOP（各意向等级均有规则）与两套文案模板（企微首触 + 行业特色第二套），沿用存在即跳过的播种策略。

## 否决

- **程序化写待办**——服务不存在；伪造 `todo_written=true` 会在审计链里说谎。改为渲染层转发可用清单。
- **SOP 模板删除加引用守卫**——没有可守卫的外键；给守卫加守卫是表演。
- **按类型拆分系统提示词**——单一文案系统提示词加用户提示词内的分类型指引，把提示词装配留在一处。

## 后果、风险与取舍

工具注册表现有 44 个工具（4 个 P0 + 40 个 P1/P3；manifest 计数对齐见 P1 说明）。文案生成与打分共享模型路由，路由不可达时文案按调用失败。任务排期信任节奏文本中的 `D+N` 标记；无标记的节奏把全部任务排在第 0 天。
