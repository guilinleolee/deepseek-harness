# Agent Note: 卡巴格成员最后登录列与登录失败文案透传

Status: implemented

[English](2026-10-02-kabage-console-last-login-and-login-copy.md) | 中文

## 问题

管理台 v2 评审（2026-09-25）遗留的两项：成员列表没有「最后登录」列（管理员看不到账号最近活跃时间，只能翻审计日志）；登录页对一切失败都显示固定的「账号或密码错误」——被限流（429）、已禁用、2FA 配置损坏的账号也被告知密码错误，误导员工并制造无谓的求助。

## 决策

账号记录新增 `lastLogin: {ts, ip}`。写入收敛在唯一一处：网关的 `issueSession(res, record, ip)`——三条登录路径共用。密码登录与 TOTP 登录此前各自内联了一段完全相同的令牌签名代码，本次一并替换为 `issueSession` 调用（SSO 两处本就走它，现在补传 `ip`）。写入走管理台的账号锁（与成员变更操作同一条串行队列，登录不会覆盖并发的禁用/改额度），锁内现读 `accounts.json`，整体异步（`void`）且绝不阻断登录响应——写失败只打日志。审计日志仍是完整登录历史；账号记录只存最新一次，成员列表渲染无需回扫审计。

呈现面：`listAccounts` 投影与 `/console/api/member/list` 增加 `lastLogin`（从未登录为 null，含 IdP 同步新建号）；成员页新增「最后登录」列（时间 + 来源 IP，从未登录显示占位，colspan 11）。

文案：错误凭据响应改为中文（`账号或密码错误`，与登录页、SSO 绑定路径一致），登录页原样渲染服务端返回的 `error` 并带 HTTP 状态兜底——429 锁定倒计时、账号禁用、2FA 损坏的原因现在能到达用户。TOTP 步骤原本就是此行为。

## 落选方案

**成员页逐账号回扫审计事件推导该列**（/me 设备列表的做法）。否决：N 个账号 × 每次渲染倒序扫审计；且 500 条窗口之外的账号会误显示「从未登录」。账号记录渲染时 O(1)，历史仍以审计为准。

**网关不经账号锁直写 lastLogin。** 否决：对 `accounts.json` 的裸读改写会与管理台加锁的成员变更竞争，可能丢掉一次并发的禁用操作。该锁本就为跨模块复用而导出（SSO 绑定在用）。

**只改前端文案。** 否决：原样透传会先暴露服务端英文 `invalid credentials`，所以先修服务端文案；只改页面是错的。

## 后果

`node test/me-invite-http-verify.mjs` 从 63 项增至 74 项（lastLogin 传播含异步锁轮询、成员页新列、401 中文文案、页面透传，以及在第二网关上断言连错锁定后 429 且文案可读的登录限流块）；九套 supervisor 测试全绿（426 项），覆盖了被重构的 TOTP/SSO 签发路径。成本与遗留：`accounts.json` 每次成功登录多一次写——≤100 人规模可忽略，控制面数据库落地后自然吸收；存量账号在下一次登录前显示「从未登录」；`kabage-admin-tools` 的 `user_list` 工具忽略新字段（输出契约不变，需要时再透出）。console v2 其余遗留项未动：审计轮转、限流 Map 持久化、登录 Origin 校验、旧制→点数迁移 CLI、NAT 共享 IP 锁定。
