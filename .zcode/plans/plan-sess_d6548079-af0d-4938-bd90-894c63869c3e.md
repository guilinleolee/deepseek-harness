## Phase3 第三切片：walk-forward 样本外验证

### 核心思路
`quant_optimize_params` 的过拟合警告（"网格最优参数来自同一段历史样本，存在过拟合风险"）自己点名了这片的需求。walk-forward 把数据切 train/test 两段：在 train 上网格寻优选最优参数，在 test 上用该参数跑一次回测，报告样本外指标与过拟合差距。

### 架构决策

1. **不新增内核操作**。`backtest_grid` 接受任意 `bars` 数组——传 train 切片跑网格、传 test 切片跑单次 `backtest`（test 腿要完整净值曲线，所以用 `backtest` 而非 `backtest_grid`）。两个内核请求，一个进程一个，与 optimize 一样。

2. **新纯函数模块 `src/pcpt/walk-forward.ts`**：
   - `splitBars(bars, trainRatio): { train, test }` — 纯切片
   - `TRAIN_RATIO_LIMITS = { min: 0.5, max: 0.9, default: 0.7 }` — 硬上限
   - `formatWalkForwardSummary(symbol, spec, best, trainMetrics, testReport, trainRatio, comboCount): string` — Markdown 报告（train 最优参数 + train 指标 + test OOS 指标 + 过拟合差距 + 警告）
   - `validateWalkForwardParams(bars, spec, trainRatio)` — 在 `validateGridSpec` 基础上额外校验两段都够长

3. **新工具 `quant_walk_forward`**：镜像 `optimizeParamsTool` 的 jobs 生命周期模式——`envelopeFrom` + `jobs.start` + `AbortController`。任务体内：fetchKline → splitBars → runBacktestGrid(train) → rankGridResults 取最优 → runBacktest(test, best params) → formatWalkForwardSummary。返回 `JobOutcome{status:'completed', output: markdown}`。

4. **合规红线**：`RULES.quant_walk_forward = [inspectBrokerMarkers, inspectBarCap, inspectGridCaps, inspectTrainRatioCap]`。前三个直接复用（参数形状与 optimize 一致）；新增 `inspectTrainRatioCap` 校验 `train_ratio` 在 0.5-0.9。`TRAIN_RATIO_LIMITS` 放 `compliance.ts`。

5. **JobKindMap** 新增 `'quant-walk-forward': 'quant-walk-forward'`。

6. **插件工具数 16 → 17**。
