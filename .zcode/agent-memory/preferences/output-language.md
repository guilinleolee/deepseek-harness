# 输出语言约定

**规则**：生成结果的**过程与结果一律使用中文**（简体）。

- 过程：推理、分析、说明、工具调用意图用中文表达。
- 结果：最终回复、生成的文档正文、面向人的说明文字用中文。

**用户指令**：2026-10-27 用户明确要求记住此约定。

## 适用边界（与仓库既有规范的关系）

用户的中文要求不覆盖以下既有规范，二者并存：

- **代码标识符保持英文**：类型名、函数名、变量名等按 `strict: true` 与现有代码风格保持英文，不因输出语言而翻译。
- **源码注释与 JSDoc 跟随所在包的既有语言**：`packages/*/*/src` 下的注释、JSDoc 现状一致为英文；改动时跟随该包/该文件的既有约定，不在同一文件内混用两种语言。注释只写代码本身表达不出的约束，不复述代码。
- **文档遵循双语配对契约**：`docs/` 及其他在配对范围内的文档由英文源与 `.zh.md` 中文副本成对维护，二者必须表达同一内容，结构一一对应，且需要 `foo.i18n.yaml` 一致性记录。不得只写中文副本或只改一侧；改一侧时按 [docs/AGENTS.md](../../../docs/AGENTS.md) 的轻量路径补齐对侧并重记记录。完整规则见 [docs/i18n/README.md](../../../docs/i18n/README.md)。
- **常规双语工作**走 `docs/AGENTS.md` 轻量路径；扩展的 `dsh-translate-docs` 工作流仅在用户显式调用时运行。

## 边界外的事实

本约定针对**新生成**的内容。仓库内既有的英文文档、英文注释不因本约定回译——
那属于配对流程范围内的独立工作，且成本高、风险高（会触发配对门禁）。
